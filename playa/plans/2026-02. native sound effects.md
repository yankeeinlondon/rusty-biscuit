# Sound Effects Channel: Analysis & Implementation Plan

## Context

Playa embeds 88 sound effects (~31MB across 6 categories) and plays them by delegating to host CLI players (mpv, ffplay, afplay, etc.) via `std::process::Command`. This means playa has **zero control** over which OS audio channel/category the sound goes through - it always lands on the default media output.

macOS, Windows, and (partially) Linux all have native concepts of a "sound effects" or "alerts" audio channel that is separate from normal media audio. The user wants to evaluate whether playa should route its embedded SFX through these channels.

## Current Architecture

- **Playback**: Subprocess delegation to host CLI players (13 supported)
- **Sound effects**: `SoundEffect::bytes()` returns `&[u8]` → written to temp file → played via host player
- **Audio ducking**: Already uses `coreaudio-sys` on macOS, but only queries `kAudioHardwarePropertyDefaultOutputDevice` (media device), never `kAudioHardwarePropertyDefaultSystemOutputDevice` (sound effects device)
- **No native audio library** in runtime deps - `symphonia` is build-dep only (for duration computation)

## Cross-Platform Sound Effects Channels

| Aspect | macOS | Windows | Linux |
|--------|-------|---------|-------|
| **Native SFX channel?** | Yes | Yes | No (convention only) |
| **Mechanism** | `kAudioHardwarePropertyDefaultSystemOutputDevice` | WASAPI `AudioCategory_SoundEffects` | PulseAudio `media.role=event` |
| **User controls** | Separate "Alert volume" slider + device picker in System Settings | Per-category volume in mixer | No dedicated slider |
| **OS auto-ducking** | Yes - ducks media when alert plays | No | Optional (module-role-ducking, off by default) |
| **Rust crate** | `coreaudio-sys` (already a dep) | `windows` crate | `libpulse-binding` |

**Key insight**: On macOS, the user can route sound effects to a different device entirely (e.g., MacBook speakers while music goes to headphones). This is a real user-facing feature, not just a volume knob.

## The Fundamental Problem

Host CLI players (mpv, afplay, etc.) don't expose audio category/channel selection. `afplay` always routes to the default output device. There's no `--system-sound` flag. **The only way to use OS sound effects channels is to bypass host players and use native audio APIs directly.**

## Recommended Approach: Dual Playback Path

Add native audio playback **for sound effects only**. Keep host player delegation for general audio files (music, podcasts, URLs, etc.).

```
Sound Effects:  SoundEffect::bytes() → rodio/cpal → OS sound effects channel
General Audio:  file/URL → host player subprocess → default media output
```

### Why `rodio`?

- Already pure-Rust, cross-platform (cpal backend)
- Built-in WAV/MP3/OGG/FLAC decoders (via symphonia) - covers all embedded SFX formats
- Allows device selection: `rodio::OutputStream::try_from_device(&device)`
- Lightweight for short clips (no streaming infrastructure needed)
- Well-maintained, widely used in Rust gamedev

### Implementation

#### Phase 1: Core native SFX playback (macOS-first) ✅

**Files modified:**
- `playa/lib/Cargo.toml` - added `rodio` dep, `sfx-native` and `sfx-native-macos` feature flags
- `playa/lib/src/effects.rs` - `SoundEffect::play_with_options()` tries native playback first when `sfx-native` enabled
- `playa/lib/src/sfx_player.rs` (new) - native playback engine with `macos` module for system sound device routing

**Implementation:**
- `play_sfx()` opens a rodio stream, applies volume/speed via `Player` API, decodes with `Decoder`
- macOS `macos::find_system_sound_device()` queries `kAudioHardwarePropertyDefaultSystemOutputDevice` via CoreAudio FFI, matches by name against cpal device enumeration
- Falls back to default rodio output when system sound device matches default or can't be found

#### Phase 2: Windows support ✅

**Implementation:**
- `windows_sfx::play_sfx_with_category()` uses WASAPI directly via the `windows` crate
- Tags stream with `AudioCategory_SoundEffects` via `IAudioClient2::SetClientProperties()`
- Decodes audio, collects samples, writes to WASAPI shared-mode stream with `AUDCLNT_STREAMFLAGS_AUTOCONVERTPCM`
- Speed via adjusted declared sample rate, manual render loop with drain

#### Phase 3: Linux support ✅

**Implementation:**
- `linux::play_sfx_as_event()` uses `libpulse-binding` to create a PulseAudio stream with `media.role=event` proplist
- Uses standard (non-threaded) mainloop with manual `iterate(true)` for synchronous playback
- Decodes audio with rodio, writes f32 PCM samples to PulseAudio, drains via `Operation` polling
- Works with both PulseAudio and PipeWire (via PipeWire's PulseAudio compatibility layer)
- `media.role=event` enables optional ducking via PipeWire's `module-role-ducking` / PulseAudio's equivalent
- Falls back to default rodio output on ALSA-only systems or if PulseAudio connection fails

### What stays the same

- General audio playback (files, URLs) continues to use host player delegation
- CLI `playa effect <name>` commands still work - they just use native playback internally when available
- Audio ducking continues to work independently
- Feature-gated SFX categories unchanged

### Binary size impact

- `rodio` + `cpal`: ~200-400KB additional binary size
- Only pulled in when `sfx-native` feature is enabled
- Sound effects features already add ~4-31MB, so this is negligible

## Verification

1. **macOS**: Set "Play sound effects through" to a different device in System Settings → Sound. Run `playa effect doorbell`. Confirm audio comes from the SFX device, not the default output.
2. **Volume independence**: Lower Alert volume in macOS Settings. Confirm SFX volume follows alert slider, not main volume.
3. **Windows**: Run `playa effect doorbell`. Check Volume Mixer shows "playa" under Sound Effects category.
4. **Linux (PulseAudio/PipeWire)**: Run `playa effect doorbell`. Check `pactl list sink-inputs` shows stream with `media.role = "event"`.
5. **Fallback**: Disable `sfx-native` feature. Confirm SFX still play via host player.
6. **General audio**: `playa play music.mp3` should still use host player, unaffected.
7. **Tests**: Unit tests for device lookup and sample spec validation, integration tests with `#[ignore]` for real hardware.
