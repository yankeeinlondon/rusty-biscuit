# Implementation plan for wrapper and agent PIDs in `current`

## Summary and Definition of Done

Claudine exposes the wrapper's actual process ID as `current.claudine_pid` and the current attempt's immediate child ID as `current.agent_pid`. Composition, dry run, and provider-free scopes return an observed null for the child. A successful spawn makes the ID available through terminal cleanup and the owning prompt's loop gate. New attempts and nested documents begin empty. Existing environment injection, child termination, logging, and report projections retain their contracts.

One Claudine registration declares both fields. The verified bundle, compiled catalog, lifecycle artifact, Darkmatter evaluator and checker, and DMLS use that declaration. Default Darkmatter, other hosts, `ctx`, and `claudine context` exclude the fields. Completion, hover, definition locations, bare-root enumeration, and shell approval regressions have coverage. Finish with regenerated artifacts, a verified publication through the installed-registration flow, updated canonical docs and published caller skills, and scoped test evidence.

Every session is non-interactive and uses the starting worktree. Numbered waves group independent tasks that may run concurrently. Finish a wave before its dependents. Review follows Phase 4.

## Phase 1 — Prepare the host extension

### Necessary Rules

1. **Use an explicit boolean extension marker.** Author `kind: namespace-schema`, `namespace: current`, and `extend: true`, with the added fields under `$schema`. Omission and literal `false` mean an ordinary declaration. Accept written YAML booleans only. In `simplified-schema/lib/src/simplified/standalone.rs`, expose the mode as `NamespaceSchemaDocument::extend: bool` and check the authored YAML kind and value span, as the parser already does for `namespace` after soft admission. Add the field to the closed `simplified-schema/schemas/namespace-schema.yaml` envelope and to `StandaloneSchemaEnvelope::admits_top_level_key` for this kind alone.
2. **Admit a single additive declaration for `current`.** In `darkmatter/lib/src/config/registration/namespaces.rs::prepare_catalog`, accept extension mode only for exact `current`. Refuse plain `current`, extension mode on every other root (including ordinary host roots), and each declaration in a duplicate extension. Preserve the existing sorted refusal behavior for duplicate ordinary namespaces. Check the resolved extension's fixed top-level members against `GlobalCatalog::darkmatter().global("current")`. Top-level entries must be explicitly named properties, with imports allowed in their types. Reject root spreads, root inheritance, and pattern or catch-all keys at their declarations. This keeps extension membership enumerable and puts every collision on an authored key instead of an expanded import. An empty mapping is a valid empty extension. Use the existing `NamespaceRefusal` with a one-based file position for mode, duplicate, and member failures. The existing `prepare_one` already resolves payloads under `BundleSources` and reports locations from authored YAML.
3. **Keep the extension out of ordinary globals.** Add `GlobalCatalog::current_extension() -> Option<&GlobalDeclaration>` and a dedicated optional `current_extension` record entry alongside `globals` in `markdown/schemas/catalog.rs`. Serialize the resolved extension definition and its own definition table; require the entry to be present in the generated artifact, with null for catalogs without one. Keep `globals()`, ordinary requirements, `BindingView`, and lifecycle `host_globals` for ordinary globals. Keep `GlobalCatalog::from_record` for built-in catalogs and reject an extension there before asking for any base shape. Add `GlobalCatalog::from_host_record` for Claudine's generator and acceptance path. Validate extension root identity, object shape, fixed member names, and base collision in that path. This avoids reentering Darkmatter's shipped catalog initialization. Claudine's `composition/schema/shipped.rs::accept_globals` also requires its extension with the two declared members. The catalog record currently validates global names and shapes on load, and `EventRegistry::declare_host_global` rejects reserved roots.
4. **Share the base by reference and preserve provenance.** The Darkmatter declarations for `ctx` and `current` in `darkmatter/schemas/darkmatter.yaml` both resolve `context@./partials/context-variables.yaml`. Use a base-first current-member accessor and iterator in `markdown/schemas/catalog.rs`, carrying the owning declaration's definition table with each member. Keep the two definition tables independent so imported type names in one cannot shadow names in the other. Keep built-in definition locations in `darkmatter/schemas/partials/context-variables.yaml` and record the extension's top-level key spans alongside its `NamespaceMember` in `prepare_one`, using the namespace document's `SchemaSourceMap`. DMLS resolves installed extension members from `RegisteredHostProfile::namespace` and its key spans. Preserve the compiled base's path and key positions as declaration metadata. Navigate to a base file in a checkout that contains the shipped schema and show its shipped source path in hover in other workspaces. Keep editor queries passive and avoid materializing schema files for navigation. Embedded and installed catalogs compare by semantic definitions, independent of install paths.
5. **Use real authored schema inputs and existing digest plumbing.** Add `claudine/registration/current.yaml` with `claudine_pid: "number(integer; min(1); required) -> The Claudine process running the workflow."` and `agent_pid: "number(integer; min(1)) | null -> The immediate provider child for this attempt, after a successful spawn."` Darkmatter supplies the base automatically. The new file needs no imports. The existing namespace bundle walk must still account for dependencies of other extensions. `prepare_catalog` already hashes each namespace file and each member served by the bundle resolver, and `HostLifecycleProfile::from_artifact_at` checks the resulting hash. Keep that digest format and use the existing inventory discovery, generator, and publisher.
6. **Keep host selection and runtime evidence independent.** Carry the selected host's catalog handle on Darkmatter's `CurrentAuthority`. Use `ComposeOptions::with_selected_host` for registered documents and an explicit `ComposeOptions::with_global_catalog(CatalogHandle)` for Claudine's embedded host. Expose `ComposeOptions::global_catalog() -> Option<&GlobalCatalog>` to the checker. Preserve selected-host precedence in both methods and derive runtime admission and the checker from that selection. `ComposeOptions::current_authority` must preserve the catalog through ambient refresh, discovery, cloning, and memoization. In `lifecycle/executor.rs::StackExecutor::build_state`, use the catalog already on the authority for foreign `md` execution and otherwise take the catalog from the stack's registry. Preserve this authority through inline, transclusion, and lifecycle state rebuilds. `CurrentScope::resolve_current` keeps the built-in `ContextGroup` path and request-owned behavior. Extension members use only the supplied provider. No provider or an unsupported answer yields the existing partial-runtime warning on reads. Bare `current` lists all admitted keys with null placeholders and performs no refresh. These paths converge in `ComposeOptions::current_authority` and `EffectiveState`'s lookup of the reserved root.
7. **Type extension members while keeping the reserved-root rules.** In `expression/scope/projection.rs`, project declared extension paths as `BindingId::Namespace` using the owning declaration and definitions. Use authored nullability and the existing expression fallback semantics. Keep `current` out of flow refinements by filtering its subjects in `scope/facts.rs` before adding guard facts. Keep built-in `current` member typing behavior and use the catalog for membership so an unknown path is distinct from an admitted member. Type literal-key accesses through the same member projection used for dotted paths where the expression evaluator supports reserved-root lookup. Keep whole-root values as key lists and preserve the existing behavior of computed selectors. `markdown/compose/call_precheck.rs::check_document` must pass the options catalog to `DeclaredTypes::for_site`, which today only sees the ordinary binding view. Claudine's lifecycle validation takes its catalog through `lifecycle_declared_types`; sequence preflight already attaches `claudine_globals`. DMLS's `diagnostics/call_check.rs::declared_types`, body and frontmatter providers, and lifecycle scopes must take the selected `HostView` catalog. Extend DMLS's reserved member completion and hover through `overlay/expressions.rs`, and use the same path projection for definition navigation through `providers/{dsl,frontmatter}.rs`. The reserved path takes precedence over a same-named document property. Existing DMLS completion for `ctx` uses its own descriptors.
8. **Own the live child observation per attempt.** Define `AttemptPid` in `claudine/lib/src/invocation_context.rs` as a cloneable `Arc<AtomicU32>` with zero as empty, and expose a typed read as `Option<u32>`. Install it through an explicit optional field on `PrepareOptions` and the harness materialization and feedback types, separate from `DocumentEpoch`, `RunEvidence`, and `RuntimeState`. Extend `LaunchRefresh` and the no-invocation Claudine refresh path to serve the actual wrapper PID and the supplied attempt observation or observed null, then delegate existing keys as before. The wrapper source is `std::process::id()` and never the launch environment. `prepare.rs` currently selects epoch, invocation, or `UnsuppliedRefresh`, and the outer loop engine retains one document epoch across passes. Allocate the first empty cell in the active-document preparation before building prompt or initialize options in `compose/prep.rs`. Carry it through `PreparedComposition` or `BootstrapPreparation` into the first harness entry. The document loop engine allocates an empty cell for each subsequent pass and passes it in `LoopIterationContext` to the iteration callback. Allocate another cell on harness retry/resume entry and on in-harness adoption before the target's bootstrap. Reuse the same cell during stabilized rereads within one attempt. Provider-free scopes and dry-run options without an attempt cell still return observed null. Keep outgoing cleanup bound to its own materialization.
9. **Record attempts independently of launch classification.** Replace the mutable bool argument across provider spawn functions with a launch-local `SpawnObservation` in `wrap/exec/mod.rs` holding the attempt cell and a sticky `any_child_spawned` bit. Initialize it per `execute_attempt_phase` or per wrapper-only launch in `wrapper_exec.rs`. At each successful provider `Command::spawn`, use a single `record_spawn(&Child) -> u32` before setup, and reuse that returned ID for existing result and dispatch fields. A retained ready child must carry its recorded PID through `Preflight::Ready`. Clear only the visible PID immediately before invoking the admitted fallback in `exec/spawn/semantic.rs`. The sticky bit remains true through a failed fallback and continues to drive the existing guard routing. The no-fallback branch returns before the clear. Preserve all process group, Windows Job Object, interrupt, and JSONL behavior.
10. **Hand the final attempt to the prompt loop only.** Carry the cell in `LoopPassPreparation` alongside its existing prepared context, epoch, and frontmatter. `publish_pass_preparation` runs before `start`, and `runner.rs` returns the final published preparation to `compose/prep.rs`. Recovery preflight and adopted bootstrap failures must build their event view with the new empty cell even when borrowing a previous epoch for context. Pass the final cell via `LoopIterationOutput::attempt_pid` to the document gate and condition in `looping/engine.rs`. Construct one `EffectiveState` for the gate condition with the pass's prepared context and attempt authority, then borrow it in `LoopExpressionLookup` to route reserved `current` reads through Darkmatter's evaluator. Propagate lookup errors from `resolve`. For cancellation observed by the outer loop after a pass returns, bind cleanup to the returned pass authority and context instead of `init_ctx`. A terminal event already handled by the attempt retains its existing event ordering. Default that runtime lookup to Claudine's provider-free authority for container and provider-free conditions. Explicitly wire `wrap/sequence/mod.rs::root_loop_frame`, `looping/container.rs`, `composition/sequence/task/mod.rs`, and the pre-launch max lookup in `compose/prep.rs`. Sequence source interpolation keeps its existing non-event lookup. Container events use the empty invocation provider, and nested `prep` creates a new target preparation. Parent actions continue reading their own retained event authority.
11. **Keep shell preflight independent of values and types.** Preserve refusal of late `current` reads for exact pre-launch command bytes, preserve typed-template validation and the existing rules on eligible surfaces, and refuse both PID reads as a new source of approved sequence shell bytes. Audit `darkmatter/lib/src/lifecycle/preflight/shell_walk.rs`, `lifecycle/shell_template.rs`, `claudine/lib/src/composition/sequence/preflight/mod.rs`, and `claudine/cli/src/commands/wrap/sequence/jit.rs::sequence_shell_roots` with positive control and refusal fixtures. Authority and catalog installation must leave discovery and approval eligibility unchanged.
12. **Use portable process fixtures and omit the spike.** The spec explicitly rules out separate performance measurement. `child.id()` and `std::process::id()` supply all evidence, and enumeration reads declarations only. Cover spawn modes with Rust fixtures, captured pipes, event or readiness synchronization, and deterministic injected setup failures in test code. Keep real-terminal assertions in the existing focus-safe harness. Use the local Linux host, with macOS, native Windows, and WSL2 covered by portable L1 fixtures and the existing CI environments. The planning environment declares `BUILD_MACOS`, `BUILD_WIN`, and `BUILD_WSL` for scoped rig verification. Use the canonical CI/archive flow for exact-tree receipts that already exist. For uncommitted local work, send a source-only tar snapshot to a temporary rig directory over batch-mode SSH or SCP and use the root test recipe there. This avoids the throwaway commit created by `just cross-check`. Keep worktree files and existing host-registration-v2 edits in place.

### Input Robustness Matrix

Every invalid authored shape returns a located error through the public parser or installed registration loader. It runs no document or provider and publishes no bundle. Treat the existing envelope and manifest fields as regression controls. This change adds a mode validator and the per-extension member admission rules.

| Public boundary | Controls and exceptions | Invalid mutations of the control |
| --- | --- | --- |
| `parse_namespace_schema_document` | Copy an existing namespace fixture, use explicit `extend: true`, and assert that omission and `false` both parse as ordinary. | Test explicit null in both YAML spellings, quoted boolean, number, empty string, empty collection, and collection with a value. Assert the `extend` span. |
| `parse_namespace_schema_document` payload | Explicit `$schema: {}` yields an empty mapping. Existing named property and bundled import fixtures stay valid. | Cover absent, explicit null, wrong whole type, and one invalid authored property definition. Reuse the existing ordinary namespace cases for shared checks. |
| `load_registrations` | Install an admitted `current` extension and a separate host with an ordinary namespace, then verify selection and catalog contents. | Edit one field or member per case to show plain `current`, another root in extension mode, a colliding built-in, a disjoint second extension, and a second extension with a repeated member. Cover root composition and pattern/catch-all refusal at the authored declaration. |
| Standalone YAML recognition and installed-member YAML loading | Accept a commented, flow-style YAML control. | Exercise duplicate mode key, invalid trailing content, and a second YAML document once at each distinct ingress. Preserve the loader's error mark in the public result, including the second document boundary. |
