# Centralized Providers Execution Plan

Source documents:

- `claudine/features/_unscheduled/centralized-providers/spec.md`
- `claudine/features/_unscheduled/centralized-providers/design.md`

Goal: make `claudine::provider::Provider` the single provider identifier, move every static per-provider fact into `ProviderInfo`, route dynamic operations through focused behavior traits, preserve current CLI output through the migration, and leave the lib crate with no `match Provider` dispatch outside the central provider registry.

## Phase Index

| Phase | Outcome | Depends on |
| --- | --- | --- |
| 0 | `AgentId` is collapsed into `Provider` with a deprecated compatibility alias | none |
| 1 | `provider/` skeleton, canonical `Provider`, registry, facades, and exhaustiveness tests exist with no behavior change | 0 |
| 2 | Agent and linking capability data are served from `ProviderInfo` | 1 |
| 3 | Event support and native event names are served from provider event mapping tables | 2 |
| 4 | Stream, MCP, adapter, and configurator dispatch route through provider behavior traits | 3 |
| 5 | Descriptive capability strings are replaced with typed catalog data | 4 |
| 6 | CLI wrapper profiles consume catalog defaults and composition flag drift is eliminated | 5 |
| 7 | ACP metadata is first-class and surfaced in hook capture output | 5 |
| 8 | Deprecated compatibility surfaces and dead provider dispatch code are removed | 6, 7, release-cycle deprecation window |

## Global Rules

- Keep each phase compiling and shippable.
- Preserve bit-for-bit output for `claudine providers`, `claudine providers --describe --format json`, `claudine hooks --support`, `claudine hooks --mapping`, `claudine hooks --describe`, and `claudine init --quick` through phases 1-6.
- Allow intentional snapshot changes only in phase 7 for ACP capture metadata and phase 8 for deprecated-field cleanup.
- Do not move `WrapperProfile` into the lib crate. The CLI keeps a separate `wrapper_for(Provider)` registry.
- After phase 1, all new lib call sites should prefer `provider_info(provider)` over adding new `match Provider` dispatch.
- Drift-maintenance updates are required when public behavior or workflow docs change: READMEs, `docs/dependencies.md`, per-area dependency docs, `.claude/skills/`, and this feature plan as applicable.

## Phase 0: Identifier Unification

Outcome: the codebase has a single provider identifier before central registry scaffolding begins.

Files likely affected:

- `claudine/lib/src/events/provider.rs`
- `claudine/lib/src/agents/registry.rs`
- `claudine/lib/src/agents/**/*.rs`
- Any call site using `AgentId`

Steps:

- [ ] Inventory all `AgentId` definitions, constructors, conversions, and call sites with `rg 'AgentId|agent_id' claudine`.
- [ ] Replace `AgentId` usage in `claudine/lib/src/agents/` with `Provider`.
- [ ] Update `agents::registry::agent_for` to accept `Provider`.
- [ ] Remove redundant `AgentId::from(provider)` and `provider.agent_id()` translation paths.
- [ ] Add `#[deprecated] pub type AgentId = Provider` or an equivalent deprecated re-export for one release cycle.
- [ ] Update tests and docs that refer to `AgentId` as the canonical identifier.

Parallelizable:

- Call-site migration can be split by module after the canonical alias shape is chosen.
- Test/doc wording updates can run in parallel with code call-site migration.

Validation checkpoint:

- `cargo check -p claudine`
- `cargo test -p claudine agents`
- `just test claudine`
- No non-deprecated canonical `AgentId` definition remains.

## Phase 1: Provider Skeleton And Facade

Outcome: `claudine::provider` exists as the canonical home for identity, provider data, behavior traits, registries, and exhaustiveness tests, while old behavior remains intact.

Files likely affected:

- `claudine/lib/src/provider/mod.rs`
- `claudine/lib/src/provider/{identity,docs,capabilities,runtime,event_mapping,registry,tests}.rs`
- `claudine/lib/src/provider/{claude,codex,gemini,goose,kimi,opencode,qwen,roo}.rs`
- `claudine/lib/src/events/provider.rs`
- `claudine/cli/src/commands/wrap/profile.rs`
- Provider CLI output tests and snapshots

Steps:

- [ ] Create `claudine/lib/src/provider/` and expose it from the lib crate root.
- [ ] Move the canonical `Provider` enum to `provider/mod.rs`.
- [ ] Re-export `Provider` from `events/provider.rs` with `#[deprecated]`.
- [ ] Define `ProviderInfo` with serializable static fields and skipped behavior trait-object fields.
- [ ] Define focused behavior traits: `ProviderBehavior`, `McpBehavior`, `AdapterBehavior`, and `ConfiguratorBehavior`.
- [ ] Add typed domain error stubs such as `McpError::NotSupported` and `ConfigError::NotSupported`.
- [ ] Add one stub provider file and one `ProviderInfo` constant per current provider.
- [ ] Implement `provider_info(Provider) -> &'static ProviderInfo` and `all_providers()` using the agreed registry shape.
- [ ] Add lib exhaustiveness tests for registry self-consistency, field touch coverage, and sniff binding round-trip.
- [ ] Add CLI-side wrapper registry exhaustiveness test for `wrapper_for(provider).provider() == provider`.
- [ ] Add or update `claudine providers --describe --format json` serialization to derive from `ProviderInfo` without changing user-visible output.
- [ ] Capture or refresh baseline snapshots for provider and hooks commands.

Parallelizable:

- Provider stub files can be filled independently once `ProviderInfo` and behavior trait signatures compile.
- Lib exhaustiveness tests and CLI wrapper exhaustiveness tests can be developed independently.
- Snapshot baseline work can proceed in parallel with registry scaffolding after serialization compiles.

Validation checkpoint:

- `cargo check -p claudine`
- `cargo check -p claudine-cli`
- `cargo test -p claudine provider`
- `cargo test -p claudine-cli wrapper`
- Snapshot outputs are unchanged from the phase-0 baseline.

## Phase 2: Agent And Linking Capability Migration

Outcome: provider capability and resource portability data live in provider files and legacy query functions forward to `ProviderInfo`.

Files likely affected:

- `claudine/lib/src/provider/*`
- `claudine/lib/src/agents/*`
- `claudine/lib/src/agents/registry.rs`
- `claudine/lib/src/linking/capabilities.rs`
- Matrix and linking tests

Steps:

- [ ] Move `AgentCapabilities` data from `agents/<provider>.rs` into each `provider/<provider>.rs`.
- [ ] Move `ProviderCapabilities` and `ResourcePortability` data from `linking::capabilities` into each provider info constant.
- [ ] Update `agents::registry::agent_for(provider)` to read from `provider_info(provider).capabilities` or equivalent catalog fields.
- [ ] Update `linking::capabilities::capabilities_for(provider)` to forward to `provider_info(provider).resource_support`.
- [ ] Keep legacy modules as thin re-exports or forwarding facades where external compatibility requires it.
- [ ] Delete provider-specific capability constructor functions only after all in-repo call sites use the facade or catalog.
- [ ] Update matrix tests so they prove the legacy facade and the provider catalog return the same data during the transition.

Parallelizable:

- Capability data migration can be split per provider.
- Linking-resource data migration can run in parallel with agent-capability data migration after shared types are stable.

Validation checkpoint:

- `cargo test -p claudine agents`
- `cargo test -p claudine linking`
- `just test claudine`
- `claudine providers --describe --format json` snapshot is unchanged.

## Phase 3: Event Mapping Migration

Outcome: event support level, native names, parse aliases, and capture mechanism are unified in `ProviderInfo.event_mapping`.

Files likely affected:

- `claudine/lib/src/provider/event_mapping.rs`
- `claudine/lib/src/provider/<provider>.rs`
- `claudine/lib/src/events/provider.rs`
- `claudine/lib/src/events/matrix.rs`
- Hooks command tests and snapshots

Steps:

- [ ] Define `EventMappingTable`, `EventMapping`, and the merged `EventSupportLevel` variants.
- [ ] Move `event_support_level` rows into provider-local event mapping tables.
- [ ] Move `native_event_name` and parse alias data into the same mapping rows.
- [ ] Fold shared native mapping constants into provider-local tables.
- [ ] Thin or delete `Provider::event_support_level`, `Provider::native_event_name`, and `Provider::registration_native_event_name` after call sites use table lookups.
- [ ] Update event matrix generation to derive only from `provider_info(provider).event_mapping`.
- [ ] Defer ACP-specific output changes to phase 7 unless a placeholder variant is needed for type completeness.

Parallelizable:

- Event table transcription can be split per provider once the table type exists.
- Matrix rendering changes can be implemented in parallel with provider table transcription using temporary compatibility tests.

Validation checkpoint:

- `cargo test -p claudine events`
- `cargo test -p claudine hooks`
- Hooks snapshots for `--support`, `--mapping`, and `--describe` are unchanged.
