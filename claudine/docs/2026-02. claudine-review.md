# Claudine Review (2026-02)

Skills used: `rust`, `claudine`, `biscuit-terminal`, `clap`.

## Findings

### 1. High: OpenCode bridge invokes `claudine handle` with incompatible arguments
- File refs: `claudine/lib/src/config/opencode.rs:52`, `claudine/cli/src/commands/handle.rs:12`, `claudine/cli/src/commands/handle.rs:22`, `claudine/cli/src/commands/handle.rs:38`
- The generated OpenCode bridge runs:
  - ``claudine handle <event> <payload-json>``
- But `handle` accepts exactly one positional `<EVENT>` and reads JSON from **stdin**, not argv.
- Repro:
  - `target/debug/claudine handle turn_complete '{}'`
  - Result: `error: unexpected argument '{}' found`
- Impact:
  - OpenCode bridge calls fail and are swallowed by the plugin `catch`, so hook actions silently never run.
- Recommended fix:
  - Pipe payload JSON to stdin and optionally pass `--provider open_code` explicitly.

### 2. High: Runtime dispatch ignores repo-scoped `.claudine/config.json`
- File refs: `claudine/lib/src/dispatch/mod.rs:47`, `claudine/lib/src/dispatch/loader.rs:82`, `claudine/lib/src/dispatch/loader.rs:90`, `claudine/cli/src/commands/handle.rs:24`
- `dispatch()` calls `load_runtime_config(None, None)`, so repo config is never considered.
- Loader supports repo merge only when `repo_root` is provided.
- Impact:
  - Config written by `claudine init --repo` does not affect runtime hook execution in `claudine handle`.
- Recommended fix:
  - Thread repo root into dispatch config loading (e.g., from cwd and/or detected git root in env context).

### 3. Medium: `--verbose` flag is documented but not wired to tracing levels
- File refs: `claudine/cli/src/main.rs:11`, `claudine/cli/src/main.rs:50`, `claudine/cli/src/main.rs:66`
- CLI docs say `-v`/`-vv` increase verbosity, but tracing filter is sourced only from `DEBUG` env var.
- `verbose` is only used for `hooks` display behavior.
- Impact:
  - Users cannot rely on CLI verbosity flags for runtime diagnostics.
- Recommended fix:
  - Map `verbose` count to tracing levels (`warn`/`info`/`debug`) and merge with env overrides.

### 4. Medium: Global TTS settings are defined but never applied to `Speak` actions
- File refs: `claudine/lib/src/events/config.rs:47`, `claudine/lib/src/dispatch/runner.rs:30`, `claudine/lib/src/dispatch/runner.rs:119`
- `GlobalSettings.tts` is documented as being passed to TTS behavior, but `execute_speak` ignores settings and always calls `biscuit_speaks::Speak::new(text).play()`.
- Impact:
  - User-configured provider/voice/rate in config has no runtime effect.
- Recommended fix:
  - Thread `settings.tts` into `execute_speak` and apply provider/voice/rate to the TTS builder.

### 5. Medium: `dry-run` provider parsing accepts providers that mock payload generation does not support
- File refs: `claudine/cli/src/commands/dry_run.rs:40`, `claudine/cli/src/commands/dry_run.rs:167`, `claudine/cli/src/commands/dry_run.rs:172`, `claudine/cli/src/commands/dry_run.rs:283`
- Help text says supported providers are `claude`, `codex`, `gemini`, `opencode`, but parser accepts all providers.
- For Goose/Kimi/Qwen/Roo, dry-run uses Claude mock payload fallback, which fails provider parsing.
- Repro:
  - `target/debug/claudine dry-run turn_complete --provider goose`
  - Result: `Adapter parse failed: missing required field: type`
- Impact:
  - `dry-run` appears broken for accepted provider values.
- Recommended fix:
  - Either restrict accepted providers to implemented mocks, or add provider-specific mock payload builders.

## Testing gaps observed
- No integration test validates that generated OpenCode bridge invocation matches `claudine handle` input contract (stdin JSON + CLI args).
- No test covers repo-scoped dispatch loading path end-to-end for `claudine handle`.
