# Frontmatter Properties Reference

Claudine reads and acts on a number of YAML frontmatter properties across its composition, lifecycle notification, linking, and prompt-reporting subsystems. This document catalogs every property that has special meaning, with links to deeper topic docs and the source-level symbols that implement each behavior.

## Lifecycle Notifications

Each lifecycle property is a top-level frontmatter key whose value is a sub-object with notification fields.

> **Event-time interpolation.** The seven lifecycle event keys (`initialize`, `start`, `success`, `blocked`, `failure`, `finalize`, `loop`) are deferred from compose-time resolution: their `{{ … }}` spans survive raw in `effective_frontmatter` and interpolate **when the event fires**, against the live document state plus the runtime globals (`err`, `timing`, `current`). This is what lets `failure.message: "{{err.code}}"` report the real error. Resolution fails closed before any side effect dispatches. The single exception is shell commands (the positional `shell: "…"` action and the key/value `command:` parameter), resolved against early-binding surfaces (`doc.*`/`ctx.*`/`env.*`/read-side functions) at pre-flight so the approved command is byte-identical to the executed one — a late-binding reference there is rejected at prepare time. See [lifecycle.md — When Lifecycle Properties Interpolate](lifecycle.md#when-lifecycle-properties-interpolate).

| Property | Description | Details | Symbols |
|----------|-------------|---------|---------|
| `start` | Emitted when a composition run begins. Fires once (idempotent) before the provider child process is spawned. | [lifecycle.md](lifecycle.md) · [composition.md](composition.md) | [`LifecycleConfig.start`](../../lib/src/composition/lifecycle.rs) [`LifecycleSignal::Start`](../../lib/src/composition/lifecycle.rs) [`LifecycleRunGuard::emit_start_once`](../../lib/src/composition/lifecycle.rs) |
| `success` | Emitted when a composition completes successfully. Once emitted, suppresses the drop safety-net so no duplicate terminal signal fires. | [lifecycle.md](lifecycle.md) · [composition.md](composition.md) | [`LifecycleConfig.success`](../../lib/src/composition/lifecycle.rs) · [`LifecycleSignal::Success`](../../lib/src/composition/lifecycle.rs) |
| `blocked` | Emitted when a composition exits before the provider child is spawned (pre-flight denial, user cancellation, schema validation failure). If the guard drops after `start` but before `mark_provider_launched()`, the drop safety-net automatically emits `Blocked`. | [lifecycle.md](lifecycle.md) · [composition.md](composition.md) | [`LifecycleConfig.blocked`](../../lib/src/composition/lifecycle.rs)  [`LifecycleSignal::Blocked`](../../lib/src/composition/lifecycle.rs)  [`LifecycleRunGuard::emit_blocked_or_failure`](../../lib/src/composition/lifecycle.rs) |
| `failure` | Emitted when a composition exits after the provider child has been spawned (provider error, crash, timeout). If the guard drops after both `start` and `mark_provider_launched()` without an explicit terminal, the drop safety-net emits `Failure`. | [lifecycle.md](lifecycle.md) · [composition.md](composition.md) | [`LifecycleConfig.failure`](../../lib/src/composition/lifecycle.rs) · [`LifecycleSignal::Failure`](../../lib/src/composition/lifecycle.rs) · [`LifecycleRunGuard::mark_provider_launched`](../../lib/src/composition/lifecycle.rs) |
