# Plan: Repo-Scoped Mode for Claudine Wrapper Commands

## Problem

The current implementation of `--repo` flag sets `HOME=/dev/null` when executing agent CLIs, but this causes:
1. Agent CLIs to choke on the non-existent "directory"
2. Users must re-authenticate each time

## Solution

Instead of using `/dev/null`, create a shadow HOME directory at `~/.claudine/{agent-offset}/` that:
1. Preserves user authentication (API keys, session tokens, etc.)
2. Symlinks all user directory contents EXCEPT:
   - `skills/` - skill definitions
   - `commands/` - custom slash commands
   - `agents/` or `.agents/` - subagent definitions
   - reusable script/hook directories
3. This allows the agent to use repo-scoped resources while preserving user authentication

### Implementation Steps

#### Phase 1: Add Agent Offset Helper

Add a method to `Provider` enum (or create a helper) that returns the agent offset string:
- `claudine/lib/src/events/provider.rs`: Add `fn agent_offset(&self) -> &'static str`

#### Phase 2: Create RepoHomeManager Module

Create new module `claudine/cli/src/commands/wrap/repo_home.rs`:

```rust
pub struct RepoHomeManager {
    agent_offset: String,
    shadow_home: PathBuf,
}

impl RepoHomeManager {
    /// Get or create the shadow HOME directory for repo-scoped mode
    pub fn ensure_shadow_home(&self, original_home: &Path) -> Result<PathBuf>;
    
    /// Symlink all contents except excluded directories
    pub fn sync_shadow_home(&self, original_home: &Path) -> Result<()>;
    
    /// Get the list of directories to exclude from symlinking
    fn excluded_dirs(&self) -> Vec<&'static str>;
}
```

#### Phase 3: Update env.rs

Modify `build_child_env` to:
1. Accept the provider as a parameter
2. Call `RepoHomeManager::ensure_shadow_home()` to create/get the shadow directory
3. Set `HOME` to the shadow directory path instead of `/dev/null`
4. Call `RepoHomeManager::sync_shadow_home()` to sync symlinks

#### Phase 4: Caching Strategy

- Check if shadow home exists and is "fresh" (recently synced)
- Only resync if original HOME has newer modification times
- Add a `--refresh-shadow` flag to force resync

## User Experience

### First Run in --repo Mode

```
$ claudine claude --repo -- "fix the bug"

Claudine > Claude > --repo ...

- Info: the --repo was used; this constrains skills, commands, and subagent definitions to those in the repo.
- Info: Created shadow HOME at ~/.claude/.claude for repo-scoped session

[Claude Code session starts with repo-scoped resources only]
```

### Subsequent Runs

```
$ claudine claude --repo -- "fix the bug"

Claudine > Claude > --repo ...

[Session starts immediately, no re-authentication required]
```

## Edge Cases

1. **Original HOME doesn't exist**: Error out with clear message
2. **Shadow HOME already exists but original HOME was deleted**: Recreate symlinks
3. **Permission issues on creating shadow directory**: Error with helpful message
4. **Agent not supported for repo-scoping**: Return error (RooCode - VS Code extension)
