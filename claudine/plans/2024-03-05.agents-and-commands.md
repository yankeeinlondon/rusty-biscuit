# Plan: Implement `claudine agents` and `claudine commands` Subcommands

## Context

The `claudine skills` subcommand is fully implemented — it discovers skills across providers, classifies scope (User/RepoMasked/Repo), validates frontmatter, reports exceptions, and can auto-fix missing symlinks. The `claudine agents` and `claudine commands` subcommands need the same treatment, following the patterns established by skills but adapted for the structural differences documented in `claudine/docs/cli/agents.md` and `claudine/docs/cli/commands.md`.

Additionally, Phase 1 of model-property-design (flag and report) applies: any agent or command with a `model` property is flagged as a `ModelPropertyNotShareable` exception. No model translation occurs.

## Decisions

- **Filter type**: Extract `SkillFilter` → shared `ResourceFilter` in a new `linking/filter.rs`. Reuse for skills, agents, and commands.
- **Agent paths**: Extend `ProviderPaths` with `user_agents`, `repo_agents`, `agent_also_reads_from` fields. Add `agents_for_scope()` and extend `target_dir()` / `also_reads_from()`.
- **CLI naming**: `commands/slash_commands.rs` for the commands subcommand, registered as `SlashCommands` in the `Commands` enum.

**File**: `claudine/lib/src/linking/paths.rs`

Add to `ProviderPaths`:

In `build_provider_paths()`, add:


Add `agents_for_scope()` method (parallel to `commands_for_scope()`).

```rust

```

Extend `also_reads_from()` to handle `LinkableResource::Agent`.

Both agents and commands use the same 3-variant scope pattern. Rather than defining `AgentScope` and `CommandScope` separately, consider whether a shared `ResourceItemScope` makes sense. ### 2.2 Discovery: `list_agents()`

```rust
pub fn list_agents(paths: &ProviderSkillPaths, filters: &[String]) -> Result<AgentsReport>
```

Flow (parallel to `list_skills` but for single files):

1. Get canonical provider's agent dirs (user + repo) via `paths.target_dir(canonical, Agent, scope)`.
2. `scan_agent_dir(dir)` → scans for `*.md` files, returns `Vec<(String, PathBuf)>` where name = stem.
3. Classify scope: User / RepoMasked / Repo (same logic as skills).
4. For each agent file: `parse_markdown_document()` to extract frontmatter. Read `description`, check for `model` property → `has_model_property`, check for `temperature`/`top_p` → `has_numeric_tuning`.
5. Apply `ResourceFilter::retain()`.
6. Sort by scope then name.
7. `gather_agent_exceptions()`:
   - For canonical agents: `check_invalid()` (required props from schema), `check_model_property()` (Phase 1 flag).
   - For each non-canonical Markdown provider: check missing agents → `Missing` exception.
   - For each non-canonical YAML provider (Goose, KimiCode, Roo Code): `FormatIncompatible` exception for every canonical agent.
   - Alias drift detection: check `name` vs `title`, `name` vs `slug`, `description` vs `whenToUse` in canonical file.

### 2.3 Fix: `fix_missing_agents()`

```rust
pub fn fix_missing_agents(paths: &ProviderSkillPaths) -> Result<AgentFixSummary>
```

Flow:
1. Scan canonical agent dirs.
2. For each canonical agent:
   - **Alias insertion**: Check frontmatter for missing aliases (`title`, `slug`, `whenToUse`). Insert if absent. Track `aliases_inserted`.
   - **Alias resync**: If aliases exist but values diverged, update to match canonical. Track `aliases_resynced`.
3. For each Markdown-compatible target provider:
   - Create dir if missing (`directories_created`).
   - Create symlinks for missing agents (`links_created` / `already_linked` / `skipped`).
4. For YAML providers: increment `format_incompatible` count per agent.

### 2.4 Known alias table

Implemented as a const array in `agents.rs`:

| Canonical Property | Alias Property | Target Provider | Derivation |
|---|---|---|---|
| `name` | `title` | Goose | Copied as-is |
| `name` | `slug` | Roo Code | Kebab-case derivation |
| `description` | `whenToUse` | Roo Code | Copied as-is |

## Phase 4: CLI Subcommands

### 4.1 `claudine agents` CLI

**New file**: `claudine/cli/src/commands/agents.rs`

Args:
```rust
pub struct AgentsArgs {
    #[arg(value_name = "FILTER")]
    pub filter: Vec<String>,
    #[arg(long, visible_alias = "fix")]
    pub apply: bool,
}
```

`run()` follows the same flow as `skills.rs`:
1. Build `ProviderSkillPaths::new()`.
2. Git detection.
3. Auto-init if `--apply` in git repo without canonical config.
4. Apply fixes if `--apply`.
5. `list_agents()`.
6. Filter exceptions.
7. Render header ("Agents" / "==================" / canonical providers with `LinkableResource::Agent`).
8. Three-mode rendering:
   - **Detail** (1 agent): name + badge + description + content preview (up to 20 lines via `CodeBlock` or `Prose` with dim formatting) + model property warning if present.
   - **Verbose** (2-5 or `--verbose`): `UnorderedList` with name + badge + format badge (`[md]`/`[yaml]`) + description.
   - **Normal** (6+): grouped by scope, names as space-separated links.
9. Fix summary.
10. Exceptions (grouped by provider, then by `AgentExceptionType`).
11. Footer messages (fix hint, user-only hint, verbose hint, filter hint, format warning, property passthrough notes in verbose mode).

### 4.2 `claudine slash-commands` CLI

**New file**: `claudine/cli/src/commands/slash_commands.rs`

Same pattern as agents but adapted per `commands.md`:
- Detail view shows frontmatter properties as key-value list + file size/format instead of content preview.
- `model` property flagged with `(not shareable)` in detail view.
- Format warning references Gemini (TOML) and Goose (MCP).
- Property passthrough notes reference `argument-hint`, `template`, `mode`, `subtask`.

## Phase 6: Model Property Flagging (Phase 1 of model-property-design)

This is integrated into the agent and command exception types above:

- **`AgentExceptionType::ModelPropertyNotShareable`**: Flagged when an agent file contains a `model` key in frontmatter.
- **`CommandExceptionType::ModelPropertyNotShareable`**: Same for commands.
- **Detail view**: When a single agent/command is shown and has `model`, append: `<dim><i><orange>note:</orange> this agent specifies a <b>model</b> property which limits cross-provider shareability</i></dim>`.
- **Exceptions section**: Each flagged resource shown as: `<b>{name}</b> (<i>specifies <orange>model</orange> property - not shareable across providers</i>)`.
- No translation, no transformation. Just flag and report.
