## Objective

Implement the Samsung Smart TV design from `schematic/docs/samsung-design.md` so Schematic supports:

1. A generated REST client named `SamsungSmartTv`.
2. A generated companion WebSocket runtime/definition module for Samsung remote control.
3. Type-safe Samsung REST/WS models that remain resilient to firmware variance.

## Scope

In scope:

- New Samsung REST API definition and model types in `schematic-definitions`.
- New Samsung remote WebSocket API definition and model types in `schematic-definitions`.
- Generator CLI registration for `samsung-smart-tv`.
- WebSocket output assembly wiring so Samsung WS module is generated.
- WS lowering/codegen tests updated to include Samsung WS.
- End-to-end generation and compile verification.

Out of scope:

- Discovery protocols (SSDP/mDNS), UPnP SOAP discovery flow, or SDB protocol.
- Runtime device probing in `homelab`.
- Additional Samsung channels not specified by `samsung-design.md`.

## Risk Register and Mitigations

1. Firmware variance may break strict typing.
   - Mitigation: optional fields + flattened extras in REST and WS envelope payloads.
2. WS auth/approval flows differ by firmware.
   - Mitigation: model `name`/`token` params only; keep auth strategy `None`; rely on runtime approval semantics.
3. Path mismatch for app launch endpoints.
   - Mitigation: keep both launch endpoints and document runtime fallback order.
4. Generator drift for WS module registration.
   - Mitigation: include Samsung in `ws_codegen` integration test matrix.
