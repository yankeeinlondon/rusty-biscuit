# OAuth2 Implementation Plan

## Overview

Implement first-class OAuth2 support across the Schematic ecosystem as specified in `oauth-schematic-design.md`. The work spans four packages (`schematic-define`, `schematic/oauth`, `schematic-gen`, `schematic-definitions`) plus documentation updates.

## Phase 1: `schematic-define` — OAuth2 Primitives

**Goal:** Add OAuth2 types to the definition layer so APIs can declaratively describe OAuth2 requirements.

### 1.1 New OAuth2 types module

**File:** `schematic/define/src/oauth.rs` (new)

Create the following types:

```rust
use serde::{Deserialize, Serialize};

/// OAuth2 provider configuration for an API.
///
/// Describes the OAuth2 endpoints, grant type, and security requirements
/// for a provider. This is declarative metadata — actual token lifecycle
/// management is handled by the `schematic-oauth` runtime crate.
///
/// ## Examples
///
/// ```
/// use schematic_define::{OAuth2Config, OAuth2GrantType, PkceRequirement, OAuth2ClientAuthMethod};
///
/// let config = OAuth2Config {
///     grant_type: OAuth2GrantType::AuthorizationCodePkce,
///     authorization_url: Some("https://github.com/login/oauth/authorize".into()),
///     token_url: "https://github.com/login/oauth/access_token".into(),
///     revocation_url: None,
///     device_authorization_url: None,
///     default_scopes: vec!["repo".into(), "read:user".into()],
///     pkce: PkceRequirement::Required,
///     client_auth: OAuth2ClientAuthMethod::ClientSecretPost,
/// };
/// ```
#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
pub struct OAuth2Config {
    pub grant_type: OAuth2GrantType,
    pub authorization_url: Option<String>,
    pub token_url: String,
    pub revocation_url: Option<String>,
    pub device_authorization_url: Option<String>,
    pub default_scopes: Vec<String>,
    pub pkce: PkceRequirement,
    pub client_auth: OAuth2ClientAuthMethod,
}

#[derive(Debug, Clone, PartialEq, Eq, Serialize, Deserialize)]
#[non_exhaustive]
pub enum OAuth2GrantType {
    AuthorizationCodePkce,
    ClientCredentials,
    DeviceCode,
}

#[derive(Debug, Clone, Default, PartialEq, Eq, Serialize, Deserialize)]
#[non_exhaustive]
pub enum PkceRequirement {
    #[default]
    Required,
    Supported,
    NotUsed,
}

#[derive(Debug, Clone, Default, PartialEq, Eq, Serialize, Deserialize)]
#[non_exhaustive]
pub enum OAuth2ClientAuthMethod {
    #[default]
    ClientSecretBasic,
    ClientSecretPost,
    None,
}
```

### 3.2 Update `generate_auth_setup()`

**File:** `schematic/gen/src/codegen/client.rs` (line ~478)

Replace the `_ => {}` fallback with an explicit `OAuth2` match arm:

```rust
schematic_define::AuthStrategy::OAuth2(_) => {
    // OAuth2 token injection is handled by the oauth runtime field
    if let Some(ref oauth_manager) = self.oauth {
        let token = oauth_manager.get_valid_token().await
            .map_err(|e| SchematicError::OAuthError(e.to_string()))?;
        req_builder = req_builder.header("Authorization", format!("Bearer {}", token));
    } else {
        return Err(SchematicError::OAuthConfiguration(
            "OAuth2 auth strategy requires an OAuth2Manager. Use the variant builder to configure one.".to_string()
        ));
    }
}
```

**Important:** Keep a `_ => {}` fallback after OAuth2 for future non_exhaustive variants, but this should now be truly unreachable for all current variants.

### 3.3 Update generated API struct

**File:** `schematic/gen/src/codegen/api_struct.rs`

Conditionally add an `oauth` field to the generated struct when the API uses OAuth2:

```rust
pub struct GitHub {
    client: reqwest::Client,
    base_url: String,
    env_auth: Vec<String>,
    auth_strategy: schematic_define::AuthStrategy,
    env_username: Option<String>,
    headers: schematic_define::Headers,
    variant_hooks: crate::shared::VariantHooks,
    oauth: Option<schematic_oauth::OAuth2Manager>,  // NEW (only when auth is OAuth2)
}
```

**Decision:** Always include the field as `Option<schematic_oauth::OAuth2Manager>` for all APIs (simpler generation), or only when `auth == OAuth2`. Recommendation: always include it. This keeps generation uniform and the `Option` makes non-OAuth APIs pay only 8 bytes.

**BUT:** This creates a dependency from generated code on `schematic-oauth`. Currently `schematic-schema` depends on `schematic-define`, `reqwest`, `serde`, `serde_json`, `thiserror`, `bytes`. Adding `schematic-oauth` means adding `oauth2`, `chrono`, `url` transitively.

**Alternative:** Don't add the field to the struct. Instead, generate OAuth helper methods that accept an `&OAuth2Manager` parameter. This keeps the dependency optional.

**Recommended approach:** Add `schematic-oauth` as an optional dependency of `schematic-schema` behind an `oauth` feature flag. The generator emits the field conditionally. For Phase 1, keep it simple: always emit the field but gate the import behind `#[cfg(feature = "oauth")]`.

**Simpler approach for v1:** The generated struct does NOT hold an `OAuth2Manager`. Instead:
- The generated struct has the `auth_strategy` field as today
- When `auth_strategy` is `OAuth2`, the `generate_auth_setup()` code checks `self.headers.has_authorization()` first (as today)
- If no auth header is set, it returns `SchematicError::OAuthAuthenticationRequired` with a message explaining the user needs to obtain a token via the `schematic-oauth` runtime and pass it via `.variant_with_headers(Headers::default().use_bearer_token(token))`

This means:
- No structural change to generated clients
- No new dependencies for `schematic-schema`
- OAuth2 token lifecycle is the caller's responsibility using `schematic-oauth`
- The `AuthStrategy::OAuth2` variant is still valuable because it carries provider metadata (URLs, scopes, PKCE requirements) that the `OAuth2Manager` consumes

**This is the recommended v1 approach.** It matches the design doc's principle: "Make interactive auth explicit; do not hide browser or callback behavior behind an ordinary request method."

```rust
SecurityScheme::OAuth2 { flows, .. } => {
    // Map the first supported flow
    if let Some(auth_code) = &flows.authorization_code {
        Ok(AuthStrategy::OAuth2(OAuth2Config {
            grant_type: OAuth2GrantType::AuthorizationCodePkce,
            authorization_url: Some(auth_code.authorization_url.clone()),
            token_url: auth_code.token_url.clone(),
            revocation_url: None,
            device_authorization_url: None,
            default_scopes: auth_code.scopes.keys().cloned().collect(),
            pkce: PkceRequirement::Required, // Default to requiring PKCE
            client_auth: OAuth2ClientAuthMethod::ClientSecretBasic,
        }))
    } else if let Some(client_creds) = &flows.client_credentials {
        Ok(AuthStrategy::OAuth2(OAuth2Config {
            grant_type: OAuth2GrantType::ClientCredentials,
            authorization_url: None,
            token_url: client_creds.token_url.clone(),
            revocation_url: None,
            device_authorization_url: None,
            default_scopes: client_creds.scopes.keys().cloned().collect(),
            pkce: PkceRequirement::NotUsed,
            client_auth: OAuth2ClientAuthMethod::ClientSecretBasic,
        }))
    } else if flows.implicit.is_some() {
        Err("Implicit OAuth2 flow is not supported (insecure). Use authorization_code with PKCE instead.".to_string())
    } else if flows.password.is_some() {
        Err("Resource Owner Password Credentials flow is not supported (insecure).".to_string())
    } else {
        Err("No supported OAuth2 flow found in security scheme.".to_string())
    }
}
```

## Execution Order

1. **Phase 1** (schematic-define) — Foundation. Must be first.
2. **Phase 2** (schematic/oauth) — Can be done in parallel with Phase 3 since the runtime crate doesn't depend on gen changes.
3. **Phase 3** (schematic-gen) — Depends on Phase 1 types.
4. **Phase 4** (OpenAPI) — Depends on Phase 1 types.
5. **Phase 5** (docs) — After all code changes are complete.
6. **Phase 6** (validation) — Final step.

## Key Design Decisions

1. **v1 does NOT embed OAuth2Manager in generated structs.** Generated clients return `OAuthAuthenticationRequired` if no bearer token is set via `Headers`. Users obtain tokens via `schematic-oauth` and inject them programmatically. This keeps generated code simple and avoids adding `oauth2` as a transitive dependency of all generated clients.

2. **PKCE is required by default** for authorization code flows. `PkceRequirement::Required` is the default.

3. **`oauth_scopes` on `Endpoint` is `Option<Vec<String>>`** — `None` means "use API-level default scopes."

4. **New `EnvMapping` fields are backward-compatible** — they're `Option` types that default to `None`.

5. **OpenAPI import maps `authorizationCode` → `AuthorizationCodePkce`** with a default of `PkceRequirement::Required`.
