## Objective

Implement first-class generated WebSocket runtime support in Schematic so generated clients/hosts are typed, resilient, and aligned with existing Schematic ergonomics (`new()`, `with_base_url()`, variant pattern, shared error model).

## Scope

In scope:

- Runtime-capable WS code generation for existing WS APIs.
- Shared WS runtime module generation (`ws_shared.rs`).
- Typed client generation for endpoint connect/send/request/events/close/state.
- Initial host generation for server-role APIs (starting with `unfolded_circle_integration_ws`).
- AsyncAPI import upgrades needed for runtime-level type quality.
- Test coverage across generator phases and runtime behavior.

Out of scope (v1, per design doc):

- Multi-endpoint multiplexing over one physical socket unless provider-native.
- Durable replay/exactly-once semantics across reconnects.

## Implementation Strategy

Deliver in 8 phases to keep risk bounded and keep generated output compiling at every checkpoint.

---

## Phase 1: Definition-Layer Runtime Hints (`schematic-define`)

### Changes

1. Extend `schematic/define/src/websocket.rs` with optional runtime metadata:
   - `WebSocketRuntimeHints`
   - `WebSocketEndpointHints`
   - `CorrelationHints`
   - `AuthFlowHints`
   - `HeartbeatHints`
   - `FrameFormat`
   - `RequestIdType`
2. Add optional fields:
   - `WebSocketApi.runtime: Option<WebSocketRuntimeHints>`
   - `WebSocketEndpoint.runtime: Option<WebSocketEndpointHints>`
3. Derive/serde defaults so this is non-breaking for existing definitions.
4. Export new types from `schematic/define/src/lib.rs` and `schematic/define/src/prelude.rs`.
5. Add unit tests for serialization defaults and backward compatibility.

### Exit Criteria

- Existing WS definitions compile without changes.
- New hints serialize/deserialize with sensible defaults.

## Phase 2: Generator WS Planning Layer (`schematic-gen`)

### Changes

1. Add new module tree:
   - `schematic/gen/src/ws_codegen/mod.rs`
   - `schematic/gen/src/ws_codegen/plan.rs`
   - `schematic/gen/src/ws_codegen/shared.rs`
   - `schematic/gen/src/ws_codegen/client.rs`
   - `schematic/gen/src/ws_codegen/host.rs`
   - `schematic/gen/src/ws_codegen/codec.rs`
   - `schematic/gen/src/ws_codegen/routing.rs`
   - `schematic/gen/src/ws_codegen/docs.rs`
2. Define a lowering model (`WsRuntimePlan`) that converts `WebSocketApi` + model metadata into explicit generation decisions:
   - framing mode
   - correlation capability
   - auth behavior
   - endpoint role (client/host/both)
3. Add validation pass before lowering:
   - malformed correlation hint detection
   - message schema existence checks
   - ambiguous auth-flow diagnostics
4. Wire modules in `schematic/gen/src/lib.rs`.

### Exit Criteria

- `WsRuntimePlan` can be created for all currently defined WS APIs.
- Lowering emits diagnostics instead of panicking on ambiguous input.

## Phase 3: Shared Runtime Generation (`ws_shared.rs`)

### Changes

1. Generate `ws_shared.rs` with:
   - `WsError`
   - `WsClientOptions`
   - `ReconnectPolicy`
   - `WsConnectionState`
   - `WsTransportHandle`
   - `WsEncode` / `WsDecode` traits
   - connection task scaffolding (reader/writer + bounded queues)
2. Use `tokio-tungstenite` transport and normalize tungstenite errors into `WsError`.
3. Implement deterministic pending-request cleanup on disconnect.
4. Keep control-frame handling (`Ping`, `Pong`, `Close`) internal and predictable.

### Exit Criteria

- Generated `ws_shared.rs` compiles independently.
- Unit tests cover option defaults, state transitions, and error conversion.

## Risks and Mitigations

1. Risk: generated WS modules become too large for large schemas.
   - Mitigation: plan module splitting hooks in `ws_codegen` early.
2. Risk: ambiguous AsyncAPI `oneOf` reduces type quality.
   - Mitigation: diagnostics + explicit fallback wrappers.
3. Risk: reconnect logic introduces race conditions.
   - Mitigation: bounded channels + single owner for transport lifecycle + integration tests.
4. Risk: memory growth from pending requests/event queues.
   - Mitigation: strict caps in `WsClientOptions` and overflow errors.

- [x] **Deferred JSON Parsing:** Envelope payloads use `Option<Box<serde_json::value::RawValue>>` instead of `Option<serde_json::Value>` to avoid costly AST allocations during routing.

- [x] **Pre-allocated Vectors:** Endpoint vectors with a known static size are initialized with `Vec::with_capacity(n)`.

- [x] **Minimized Helper Allocations:** Repetitive string allocations in helper functions are avoided (using lazy statics, array slices, or `Cow`).
  - Covered by runtime/shared helper implementation tasks in Phases 3 and 4.
- [x] **Memory Churn Warning:** Endpoints expected to be polled at high frequencies document the potential memory overhead of generating owned `String` fields repeatedly.
