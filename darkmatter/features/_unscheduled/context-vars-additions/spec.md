In this feature we are adding some more context variables and expression functions to Darkmatter

## Context Variables

- agent
    - the agent executing the operation
    - read from the existing `AGENT` environment value set by Claudine
- model
    - the model the executing agent is using
    - read from the existing `MODEL` environment value set by Claudine
    - defaults to `"default"` when `MODEL` is absent or unknown

## Expression Functions

- Filesystem
    - all filesystem helpers resolve their `file` input through `FileReference` first, then parse the resolved path
    - filesystem helpers are path-shape utilities, not existence checks
    - if `FileReference` parses successfully but the target path does not exist, helpers still operate on the resolved or normalized path string
    - malformed file references raise an error
    - non-string `file` arguments raise an error
    - indexed filename grammar:
        - a file is "indexed" only when its filename stem has a hyphen-delimited numeric suffix
        - regex-like rule: `{base}-{digits}` immediately before the final extension, if an extension is present
        - `review-1.md` and `review-100.md` are indexed
        - `review1.md` and `review_1.md` are not indexed
    - is_indexed_file(file) -> boolean
        - a file is "indexed" when its filename stem matches the indexed filename grammar
        - `example-1.md`, `example-100.md` would both be considered indexed files
        - this function does NOT check for the existence of the file; it only checks the resolved file reference string/path shape
    - file_index(file) -> number
        - returns the index number of an indexed file reference
        - if the file reference is NOT an indexed file then it returns -1
    - increment_file_index(file) -> string
        - increments a file reference to the next highest index
        - "review-1.md" -> "review-2.md"
        - existing zero-padded indexes preserve width:
            - "review-001.md" -> "review-002.md"
        - in cases where the file reference is NOT an index file then we will start with an index of 2:
            - "review.md" -> "review-2.md"
        - new indexes added to non-indexed files use no padding
    - decrement_file_index(file) -> string
        - just like increment_file_index except that the index counter is decremented instead of incremented
        - if we're at a 0 index, further decrements will remain at 0
    - basename(file) -> string
        - returns the basename of a file reference (e.g., filename and extension)
    - basename_without_index(file)
        - if the file was an indexed file, the index is removed
        - if it wasn't an indexed file then the basename is returned as is
        - "foo/review-1.md" -> "review.md"
    - dir(file) -> string
        - returns the directory portion of a file reference
    - ext(file) -> string
        - returns the file extension
        - return an empty string if there was no file extension
    - file_trailing(file) -> string
        - returns the last directory and the basename of the file reference
        - "foo/bar/baz/test.md" -> "baz/test.md"
    - dir_leading(file) -> string
        - returns any directory path other than the last directory segment
        - this is the inverse of file_trailing(file)
        - "foo/bar/baz/test.md" -> "foo/bar"
- Type Predicates
    - is_positive(val) -> boolean | Error
        - returns true/false based on whether the value passed in is positive
        - uses the existing numeric coercion rules
        - if the value passed in can't be coerced to a number then this raises an error
        - `0` is neither positive nor negative
    - is_negative(val) -> boolean | Error
        - same as is_positive(val) but in reverse
        - uses the existing numeric coercion rules
        - if the value passed in can't be coerced to a number then this raises an error
        - `0` is neither positive nor negative
    - is_integer(val) -> boolean | Error
        - tests whether value passed in is an integer value
        - strict: only JSON numbers can return true
        - no coercion of numberlike strings
        - "1" results in false, 1 results in true
- String Mutations
    - "numberlike" means the same numeric string syntax accepted by the existing `number()` helper
    - without_date(string) -> string
        - requires `string` to be a JSON string
        - non-string inputs raise an error
        - removes only strict calendar-date substrings in `YYYY-MM-DD` form
        - returns the string with all matched calendar-date substrings removed
        - if there are no matched calendar-date substrings then it returns an unchanged string
        - full datetimes such as `2026-06-10T12:30:00Z` are not removed as a single datetime token; only the `YYYY-MM-DD` calendar-date substring is in scope if matched
        - compact dates, ordinal dates, and parser-discovered variants are not removed
    - ensure_leading(var, prefix)
        - `var` may be a JSON string or JSON number
        - `prefix` may be a JSON string or JSON number
        - arrays, objects, booleans, and null raise an error
        - ensures that the "prefix" passed in is how the string starts
        - ensure_leading("foobar", "foo") -> "foobar"
        - ensure_leading("bar", "foo") -> "foobar"
        - returns a number only when `var` is a JSON number and `prefix` is numeric or a numberlike string; otherwise returns a string
        - if the "var" is a JSON number and "prefix" is numeric or a numberlike string, ensure_leading will preserve the numeric type:
            - ensure_leading(123, 4) -> 4123
            - ensure_leading(123, "4") -> 4123
        - however, if "var" is just numberlike then we just do simple string based logic:
        - ensure_leading("123", 4) -> "4123"
        - ensure_leading("123", "4") -> "4123"
        - ensure_leading("123", "abc") -> "abc123"
    - ensure_trailing(var, postfix)
        - `var` may be a JSON string or JSON number
        - `postfix` may be a JSON string or JSON number
        - arrays, objects, booleans, and null raise an error
        - just like `ensure_leading` except that it ensures that the string ends a certain way
        - returns a number only when `var` is a JSON number and `postfix` is numeric or a numberlike string; otherwise returns a string
    - link(file) -> string | Error
        - one-argument `link(x)` is file-only
        - HTTP(S) URL strings raise an error because URL links require `desc`
        - all other string inputs are resolved through `FileReference`
        - malformed file references raise an error
        - the description is the relative path to the file
    - link(target, desc) -> string | Error
        - two-argument `link(x, desc)` accepts either a valid file reference or an HTTP(S) URL string
        - HTTP(S) strings are classified as URLs
        - all non-HTTP(S) target strings are resolved through `FileReference`
        - it will render as markdown:
            - `[desc](destination)`
        - where file link destinations are always absolute paths after `FileReference` resolution
        - where URL link destinations are the supplied HTTP(S) URL
        - where `{desc}` is the explicit description argument
        - descriptions must be escaped for Markdown link text, including `[` and `]`
        - destinations must be emitted in a safe Markdown form when needed for spaces, `)`, or other characters that would otherwise break valid Markdown output
        - valid destination escaping strategies include angle-bracket destinations or percent encoding; the required behavior is valid Markdown output, not a specific implementation mechanism
    - terminal(string)
        - requires `string` to be a JSON string
        - non-string inputs raise an error
        - will convert the passed in string into a terminal escaped string using the `Prose` struct

- Context
    - has_skill(name) -> boolean
        - tests whether the passed in name is an available skill for the executing agent
        - Darkmatter derives skill roots from the executing agent and that agent's known skill storage locations
        - no explicit skill-root option is needed for this feature
        - checks any known skill root for the executing agent, including user-scoped and local-scoped roots
        - a skill is identified by a direct child directory whose basename exactly matches the skill name
    - has_local_skill(name) -> boolean
        - tests whether the passed in name is an available local-scoped skill for the executing agent
        - checks only local-scoped skill roots for the executing agent
        - a skill is identified by a direct child directory whose basename exactly matches the skill name
