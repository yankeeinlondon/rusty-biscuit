## Unblocked Findings

### R10-F2 (high) Reference validation drops malformed transclusions

**Authority (defect).** A user can type `::file` and leave off its path, or leave a blank `prologue:` while editing frontmatter. Darkmatter's `md compose` rejects these inputs. On the same files, `md validate refs` and `md graph --validate` exit 0. The graph construction code discards the parser error and returns a graph without the malformed directive, leaving both validators with nothing to check. Thus a reference check can report success on a document it was unable to inspect. [Graph body parser](../../lib/src/markdown/reference/graph.rs#L632), [Graph frontmatter parser](../../lib/src/markdown/reference/graph.rs#L960), [Local query contract](../../lib/src/markdown/reference/mod.rs#L155)

The defect class is treating a parser error as absence in a reference reader. A valid directive and an equivalent spelling should both be visible. An authored directive with an invalid path argument, heading level, depth, or field shape should surface its parser error in APIs that report errors. A truly absent or explicitly empty inclusion list yields no entry. The probes reused the component note and its existing `./side.md`, then changed one field or argument. No HTTP fetch was needed.

### R10-F1 (medium) Library consumers can ignore the admitted document source

**Authority (defect).** A Darkmatter library caller can supply an open file's current buffer to `Markdown::from(text)` and pass `vendor/review.md` to `ComposeOptions::with_source_file`. This is the request-only source form described in the composition guide. In a component checkout, a matching trigger can silently disappear and a valid bare schema can be reported missing. Adding the same file path to the Markdown object repairs those results without changing the document. In the request checkout itself, the local query also rejects a valid relative `prologue` or `epilogue` after admitting the source. [Request guide](../../docs/topics/compose-requests.md#preparing-a-request), [Schema eligibility](../../lib/src/markdown/compose/schema_validation.rs#L462), [Local query](../../lib/src/markdown/reference/mod.rs#L171)

The defect class is using a raw or absent Markdown path to make a decision after the request has already admitted the document's file. With identical contents and one unambiguous file path, attaching that path to the request, the Markdown, or both must produce the same file identity, whether the path is absolute or relative to the request directory. Changing the schema or target to a missing file must still fail or report a typed no-match, as each API promises. Changing a matching document to satisfy the component trigger must clear its validation error.

I reused the component setup from the preceding reviews, with a separate Git checkout under `app/vendor`, a distinct parent and component `&marker.md`, a component-only schema and type library, and separate parent and component triggers. The public-library probes changed how the path was supplied while leaving the buffer unchanged. A second note under `app/docs` exercised the same-checkout case.
