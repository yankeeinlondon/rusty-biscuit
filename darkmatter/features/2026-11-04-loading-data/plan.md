# Loading Data Implementation Plan

## Summary and Definition of Done

Implement `load_data(file, as)` as a fallible, typed-container reader for YAML, JSON, JSONL/NDJSON, CSV, TSV, TOML, and JSON5. Reuse the request's file-resolution and remote-fetch authorities, the SimplifiedSchema coercion engine, and the shared expression scanner. Add precise data-source diagnostics, request-wide single-flight memoization, and expression read tracking. Extend passive checks and DMLS authoring support without evaluating expressions in the editor.

Success means every R1–R12 acceptance criterion has executable coverage; all supported formats return fully converted values or a located failure; failure envelopes retain dependencies; repeated reads obey the selected cache mode; all expression surfaces share the same runtime; and the scanner preserves previously parsing expressions. Current documentation, generated catalog documentation, skills, dependency references, and four active follow-up specs must be delivered. Run `just test` and `just lint` in darkmatter, biscuit-file, simplified-schema, and claudine. Leave the feature active and ready for review, without committing or moving lifecycle directories.

Execution follows completion of the implementation of 2026-11-04-composition-errors. This is an implementation dependency, not a human review gate. At planning time its envelope and output collector exist in the working tree, while its plan still has unchecked tasks and `docs/cli/report-json.md` has not yet been renamed. The execution scheduler completes that prerequisite's existing plan before starting this plan. No repeat approval or review is required between the two implementations.

Waves are globally numbered. Finish a wave before starting the next. Tasks within a wave may use separate agents with the stated file ownership; they must receive the non-interactive-session rules. An agent runs its focused checks; the final phase runs the complete area suites once after integration. No new runtime spike is scheduled: SP1, SP2, and SP3 already supply the required evidence.

## Phase 1: Establish Implementation Contracts

### Necessary Rules

1. **Use the new output contract.** Extend `DocumentEnvelope` in `darkmatter/lib/src/markdown/output/command/document.rs`, `ReportSink` in `darkmatter/cli/src/output/report.rs`, `Diagnostic` in `compose/expression/diagnostics.rs`, and `cli/schemas/output/compose.yaml`. Use `docs/cli/data-contract.md` as the renamed prerequisite page. Do not restore `report-json`. Evidence: the prerequisite's in-progress types and collector are present, and the dependency and R12 explicitly require the new names.

2. **Keep all six proposed codes and cap failures at 20.** Use `dm.data.not_a_container`, `dm.data.row_shape_conflict`, `dm.data.this_import_rejected`, `dm.data.unsupported_format`, `dm.data.malformed`, and `dm.data.contract_mismatch`, all errors. Emit the first 20 contract violations and one overflow record with the omitted count. Keep them out of the warning-only `COMPOSE_DIAGNOSTIC_CODES`. Evidence: R5 proposes exactly these codes and cap; `compose/policy.rs` governs recoverable warnings.

3. **Keep a typed error until projection.** Add `ExpressionError::Data(Arc<DataError>)`, with `DataError` and its typed variants in a new `compose/expression/data/error.rs`. Retain the resolved identity, format, source text/location metadata, written contract, and structured conversion failure; never recover these from display text. Make data errors authoring-fatal and propagate them through callbacks, iteration wrappers, interpolation, conditions, discovery's existing lenient boundary, and nested composition. Construct final `Diagnostic` records only in `compose/report_diagnostics.rs`; passive findings are carried by the existing expression finding machinery and projected there for composition. Evidence: `ExpressionError` is cloneable and distinguishes fatal failures; `report_diagnostics.rs` already unwraps these layers.

4. **Keep file failures in the existing family.** Missing/unreadable files, policy refusals, and fetch failures use `FileReferenceDiagnostic`, including `reference` and `failure`. Call `FileReference::new` and the existing document resolver against the captured `FileResolutionContext`; use `canonicalize_simplified`, portable path helpers, and `PathIdentity` for external identities and comparisons. Do not add path-prefix parsing or capture process state. Evidence: `functions/fs.rs::{resolve_arg,load_markdown}`, `resolve_ctx.rs::file_context`, and R1/R5/R6.

5. **Use an explicit data-location type.** Add public `DataLocation { file: String, pointer: String, line: Option<usize>, column: Option<usize> }` beside `Diagnostic`; omit absent coordinates and omit `Diagnostic.data_location` entirely when unavailable. Malformed document errors use pointer `""`; invalid UTF-8 reports its zero-based original-body byte offset in the message, with pointer `""` and no coordinates. Contract errors use their RFC 6901 pointer. Missing values point at the nearest existing parent container; unexpected keys point at the key token and unexpected tuple elements at the element. Overflow records retain the file and root pointer without invented coordinates. Evidence: R3 requires a byte offset for undecodable input; R5 prescribes the four location fields and omission rather than null-filled placeholders.

6. **Locate against BOM-stripped text.** Strip one UTF-8 BOM, then use a shared biscuit-file `source_position(text: &str, byte_offset: usize) -> Option<(usize, usize)>` for 1-based line/character columns. LF and CRLF break lines; lone CR does not. Normalize each parser's location to a byte offset before calling it. Do not change the existing frontmatter byte-column convention or `positions.rs::LineIndex`, which currently also handles lone CR. Contract locations in YAML files containing aliases or multiline flow collections remain pointer-only; parser errors retain their authoritative parse-error positions. Evidence: SP2 and `positions.rs::{LineIndex,PositionMap}` expose distinct conventions; the feature requires character columns only for `data_location`.

7. **Keep location ownership with the parser.** Add public biscuit-file modules `source_position`, `json_lines`, `delimited`, and `data_locations`. Export `locate_json`, `locate_jsonl`, `locate_toml`, and `locate_json5` as `(text: &str, pointer: &str) -> Option<usize>`, gated with their existing format features where applicable. The delimited result exposes field offsets directly. JSON uses `RawValue`, last duplicate occurrence wins; JSONL adds physical-line offsets; TOML walks `DeTable` spans; JSON5 walks `json_five` token spans and selects the last duplicate key. Add `json5_parse_error_offset(&str) -> Option<usize>` beside that locator, using `json_five::parser::from_str` and `ParsingError.index` after the wrapper reports a syntax failure; its Serde adapter otherwise erases the typed position into `Custom(String)`. YAML uses `PositionMap::project` and `byte_range`, never its top-level fallback. Evidence: SP2 demonstrated these exact mechanisms and R5 assigns these owners.

8. **Extend both format enums without expanding the bf conversion product.** Add `Jsonl`, `Csv`, and `Tsv` to `DataFormat` and `FileType`; make `detect_from_extension(&Path) -> FileType` public and re-export it. Add `.ndjson` as a JSONL alias and preserve the existing extensions. Update enum methods and conversions, including structured/UTF-8 classification for the new formats. Use `application/x-ndjson`, `text/csv`, and `text/tab-separated-values`. In `biscuit-file/cli/src/main.rs`, explicitly reject these newly detected inputs with a supported-conversion error; do not add CLI input/output variants or conversion commands. Evidence: detection currently returns `FileType`, `From<DataFormat>` is exhaustive, and bf's conversion dispatch has no readers for these formats; R3 authorizes library support, not new bf conversions.

9. **Make delimited support opt-in.** Add `delimited = ["dep:csv", "dep:csv-core"]`, excluded from `default` and included in `full`. Declare `csv = "1.3"` and `csv-core = "0.1.13"` as optional dependencies; enable `delimited` on darkmatter's biscuit-file dependency. Use `csv` for decoded records and a synchronized `csv-core` pass for source-field offsets. Add strict quote-state validation to reject unterminated quotes, quotes in unquoted fields, and non-delimiter text after closing quotes, since permissive CSV parsing must not silently accept malformed RFC-style records. Skip physically blank records, retain delimiter-only rows, preserve cell text, and enforce header width for all data rows. Evidence: R3 requires both dependencies and raw offsets; SP2 proves decoded buffer ranges are unsuitable, and R4 demands strict rows and CSV-style TSV quoting.

10. **Use rejecting TOML conversion only in load_data.** Read `Toml::from_str(text)?.value()` and walk that tree in darkmatter's data parser: admit integers with `numeric::admit_integer`, floats with `admit_f64`, recurse through tables/arrays, and preserve the wrapper's datetime-to-string behavior. Leave `Toml::as_json_value` and private `toml_to_json` unchanged. JSON/JSONL use `admit_json_text_numbers`; JSON5 uses `reject_non_finite_json5` and shared admission of parsed numbers. YAML uses `schemas/yaml_documents/load.rs::load_yaml_document` without changing merge-key/non-string-key behavior; reject custom tagged values before JSON conversion. Evidence: `Toml::value` exposes the native tree, and R3 expressly permits a separate rejecting conversion to avoid changing other callers.

11. **Retain raw remote bodies once.** Convert the private transport-cache outcome, cached body, and fetch slot from `String` to raw bytes (`Arc<[u8]>` at the runtime boundary). Add `RemoteFetchRuntime::get_bytes` and `ResolutionContext::fetch_remote_bytes`; keep `get_content`/`fetch_remote_text` as strict UTF-8 adapters for existing callers. Preserve the cache manifest/layout and body-byte checksum, early host-policy check, redirects policy, cache-control precedence, and single-flight registration. Expose a typed fetch failure internally so load_data distinguishes transport failures from UTF-8 decoding failures without parsing messages. Evidence: `cache/remote_cache.rs::fetch_with_cache` currently decodes UTF-8 in three branches and `remote_fetch.rs::FetchSlot::Ready` stores `String`; otherwise a remote encoding error cannot become R3's located malformed-data error. Transport storage already represents raw response artifacts.

12. **Use one container predicate and one union flattening rule.** Add `narrowing::denotes_container(&PropertyDef) -> bool` for fully known types and a parse-only admission helper that provisionally accepts unresolved named references. Drop null alternatives but require at least one non-null container; arrays, tuples, objects, and dictionaries pass, scalars/unknown/null alone fail. Expand embedded imports passively and external imports only at execution. Add `Constraint::Container` throughout grammar, lowering, format payload (`container: true`), and authoring metadata. Evidence: R2's tables and `format.rs::TypeDefinitionOptions` currently know only `forms` and `declaredRequired`; changing only that struct would leave the grammar and keyword payload incomplete.

13. **Resolve a contract once per document context and written declaration.** Parse `as` with `parse_property_definition`; reject authored `@this` references at every depth, but allow internal recursion in imported types. Wrap the definition in a synthetic one-property `SchemaRoot`, call `schemas::resolve::expand_named_types` with `SchemaRoots::for_document` and the existing shipped sources, and translate the expanded property with `shape_from_property_def_with_definitions`. Bind the bare shape, without an implicit optional-null wrapper. Store the resolved property, definitions, imports, and compiled shape together. A missing/unreadable import keeps the file-reference error family, naming the import reference; a malformed schema or unknown exported type is a typed `DataError::ContractSchema` carrying `Arc<SchemaError>`, projected as `dm.expression.evaluation_failure` at `as` with the schema cause in the message and no data_location. A contract that resolves to a scalar receives `dm.data.not_a_container`. Evidence: `expand_named_types` returns `NamedTypeExpansion { schema, imports, definitions }`, the translator supports definition tables, and R1/R7 require document-relative imports and resolved type identity.

14. **Choose CSV shape before reading data.** Add `RowMode::{Object,List}` and one pure contract classifier under `expression/data/contract.rs`. Walk every non-null top-level arm and every array/tuple element, including nested union elements: all object/dictionary row elements select Object; all list/tuple row elements select List; anything else fails with `row_shape_conflict`. A tuple with no elements cannot determine a row mode and fails. Bare `object` is an object row when nested in an outer collection, but not a top-level tabular contract. Literal file plus literal contract is checked passively using URL path extension or local path extension; external named contracts remain provisional until execution. Evidence: R4 requires agreement across all elements and forbids scalar/unknown rows.

15. **Memoize success or typed failure without call-site state.** Add `DataRuntime` under `compose/expression/data/runtime.rs`, with shared contract preparation and data-entry maps. Data entries use `Arc<OnceLock<Result<LoadedData, Arc<DataError>>>>`; never hold the map mutex while loading. Key by canonical path/normalized URL plus the serialized synthetic schema from `to_json_schema_with_definitions` and the sorted resolved import identities. This existing lowering includes reachable definitions and preserves union/property order; serialize its value without key sorting. Include the bare contract declaration in the key so root presence/constraint distinctions are retained. Use exact serialized keys rather than a new hash. Memoized errors acquire the current call site's source only at diagnostic projection. `ReadWrite` and `ReadOnly` populate/reuse this request-private memo; `Refresh` and `Off` bypass both prepared-contract and loaded-data reuse. Remote bytes still use existing single-flight in every mode. Evidence: R7 explicitly proposes this mode table, and `cache/types.rs` separates semantic reuse from remote freshness.

16. **Name and expose the dependency field read_set.** Use `Vec<String>` on `ComposeReport`, `ComposeFailure`, and `DocumentEnvelope`, always serialized as an array including `[]`. Internally deduplicate through a shared sink and return lexically sorted portable canonical paths/normalized `Url::to_string()` values. Preserve URL query and fragment consistently with existing fetch keys. Record at successful resolution, before read/fetch/validation and before memo lookup, including failed reads and denied resolved URLs. `file_exists` records the first normalized candidate for a valid missing local reference, obtained from `FileReference` candidate planning; malformed references and null arguments record nothing. Include resolved contract-import files too, using expansion imports; the read set describes actual dependencies, not only data files. Evidence: R8 requires failure coverage and every read-side expression; `resolve_ctx.rs::resolve_document_file_ref_shape` already exposes the first missing candidate without inventing resolution rules.

17. **Share runtime through options, with a fresh root-run boundary.** Add an options-level `Arc<DataRuntime>` and share it through both `expression_resolution_context_in` and `local_expression_resolution_context_in`; frontmatter inherits the latter. At `run_root_pipeline_collecting`, reset the shared memo and read sink before executing the root; recursive transclusion and nested compose use `run_compose_pipeline_node` and retain that state. Serialize root executions sharing one runtime with a root-run guard; internal nested calls do not acquire that guard. Separate request runtimes may execute concurrently. Lifecycle expressions use the request's sink: the CLI snapshots and unions their pre-compose reads into ReportSink before root reset, then unions post-compose reads at lifecycle completion. Preflight/discovery get forked data-runtime handles so their resets cannot clear the real run's sink or memo. Add a public `ComposeRequest::read_set()` snapshot for hosts and failure collection; ordinary standalone `ResolutionContext::new` owns an isolated runtime. Evidence: options.rs has these two production constructors, lifecycle `md_host.rs` uses the local adapter, `nested.rs` enters `run_compose_pipeline_node`, and provider-query caches otherwise default per context. Extend the collecting return to `(MarkdownResult<ComposeReport>, Vec<ComposeWarning>, Vec<String>)`; update `compose/mod.rs::compose_with_warnings`, `pipeline/mod.rs::run_root_pipeline_hooked`, `preflight/collect.rs`'s two destructures, and `reference/graph.rs`'s match so failed reads reach ComposeFailure without a global sink.

## Phase 5: Prove Input and Execution Contracts

### Input Robustness Matrix

The matrix applies to the new structured-data loaders and container-option payload reader, not the Markdown/expression grammar. Default: invalid input produces a typed located failure, returns no loaded value, executes no subsequent expression/shell/lifecycle action dependent on that value, and publishes no document. Necessary reads and in-memory transport work are not rolled back. Static call failures occur before any execution. All data fields are load-bearing only through their supplied contract; the shared coercion validator defines their shapes once.

Exceptions are explicit: absent optional object properties remain absent and optional properties admit null under existing schema rules; absent required non-null properties fail; explicit nullable arms preserve null; compatible scalar text converts through the shared engine. Empty strings/arrays/objects remain explicit values, subject to their declared constraints. An empty cell remains `""`, never absent or null. Empty files follow R3: YAML null, JSON/JSON5 error, JSONL/CSV/TSV empty list, TOML empty object. A null file argument bypasses loading. JSON duplicate keys are last-wins; JSON5 duplicate keys are last-wins too. Evidence: biscuit-file `Json5::from_str` deserializes into `serde_json::Value`; json-five 0.3.1 `JSONMapAccess` visits entries in order and serde_json's `ValueVisitor::visit_map` inserts each entry with `Map::insert`. Its locator selects the last occurrence. YAML/TOML duplicate keys fail. Blank JSONL lines are skipped. List-mode duplicate/empty headers are allowed.

Test the field validators once through public `compose_with_warnings` results: required/optional object slot presence, scalar conversion, array element, tuple slot, and dictionary value. For each validator cover absent and explicit null distinctly, whole-field wrong type, empty value, and collection mixed/all-invalid elements. Include a valid text-to-number conversion to distinguish conversion from silent type filtering. Use one control fixture and one invalid wiring case per format for each different parser-to-value path, not the entire shape matrix per extension. Cover `type-definition(container)`'s emitted keyword payload through public SimplifiedSchema validation: absent flag and false leave the general format behavior, true enforces containers, null/non-boolean fail admission.

Document-loader cases are separate: JSON accepts last-wins duplicates but rejects trailing garbage; YAML rejects duplicate keys, multiple documents, custom tags, and invalid syntax while accepting aliases; TOML rejects duplicate keys, trailing garbage, and non-finite/inexact numbers; JSON5 accepts comments/trailing commas and rejects invalid/trailing text and non-finite numbers; JSONL accepts blank lines and rejects a malformed line or multiple values on one physical line; the shared CSV/TSV loader rejects strict quoting/ragged rows and accepts quoted delimiters/newlines. CSV and TSV share the matrix, plus one tab-specific quoting case. YAML/YML and JSONL/NDJSON share loaders, so aliases receive extension wiring controls only. All format families receive BOM, CRLF, invalid-UTF-8, and empty-input controls because darkmatter owns that common byte boundary.
