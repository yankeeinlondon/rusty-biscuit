Declared threshold (before capture)
-----------------------------------
Target operation: one `md hash --diff` / `--save` invocation.
Minimum repeatable win: >= 5% on the large-document `detailed` target.
Maximum permitted control regression: 0% on the `simple` and small-document

What was duplicated
-------------------
`run_hash_diff` calls `compare_hash` and then `explain_hash_diff`; the latter
called `compare_hash` AGAIN, and for the `detailed` kind `detailed_body`
recomputed the artifact a THIRD time. `run_hash_save` adds `plan_hash_save`,
which computed the stored-policy comparison artifact and, separately, the
current-policy baseline.

Fix (no public API change): `compare_options` names the like-for-like identity;
`compare_with_computed` accepts an already-computed artifact. `explain_hash_diff`
now computes ONE artifact and shares it with both the comparison and
`detailed_body` — provably the same artifact, since `detailed_body` is only
reachable via `ComparisonDetail::Detailed`, which only arises when
`stored.kind == Detailed`. `plan_hash_save` computes the comparison artifact once
and reuses it for the baseline ONLY when `(selected kind, normalized ignore-set)`
matches the stored identity; a kind change or ignore-policy change still computes
the current-policy baseline separately, preserving `--save`'s legitimate
distinction between its two artifacts.

Honest residual (NOT fixed, and why)
-------------------------------------
`--diff` still computes the artifact TWICE: once in the CLI's `compare_hash`
(needed for the exit-2 decision) and once in `explain_hash_diff`. Removing that
last duplicate requires the CLI to derive changed-ness from the explanation, but
`ExplanationBody`, `FmConcern`, `StructuredBody` and `DetailedBody` are all
PRIVATE and `HashExplanation` exposes only `render()`. Closing it would therefore
need either:
  (a) a new public accessor on `HashExplanation`, or
  (b) an interior-mutability memo on `Markdown` itself.
(a) is barred by the standing "no new public Rust API shape change" contract.
(b) would put a cache inside a value type that is `Clone`/`PartialEq` and shared
across rayon threads in `run_hash_directory`, introducing a Sync obligation and a
staleness hazard on a mutable document — disproportionate to the remaining ~2.3 ms.
This residual is recorded here rather than silently absorbed; it is a candidate
for a future owner-approved API addition, not an oversight. The `simple` and
`structured` rows above are unchanged for exactly this reason.

Disposition: ACCEPTED (implementation win) with a recorded residual.

Cross-platform classification: OS-IDENTICAL, confirmed from the actual diff.
The change is pure call-graph restructuring in `compare.rs` / `explain.rs` /
`save.rs`: no `cfg`, no filesystem access (the CLI still owns `fs::write`), no
path handling, no clock. Stored hash semantics are unchanged — proven by the
round-trip test `saved_baseline_reads_back_as_unchanged` across 5 kinds x 2
ignore policies. Windows compile + macOS behavioral run + ordinary Linux CI are
sufficient per the Verification Matrix.
