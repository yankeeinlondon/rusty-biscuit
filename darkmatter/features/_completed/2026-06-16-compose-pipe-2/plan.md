# Compose Pipeline v2 — Implementation Plan

This plan is the **join** of the two design documents:

- [`tech-design.md`](./tech-design.md) — the *functional* source of truth (behavior, invariants, error model, acceptance tests).
- [`module-structure.md`](./module-structure.md) — the *structural* source of truth (target module layout, migration order).

Each phase below carries a **structural move** (from module-structure) and its **functional payload** (from tech-design): the requirements it delivers, the acceptance tests that gate it, and a **behavior flag** (preserving vs changing). The § *Module Structure Alignment* constraints in `tech-design.md` are binding throughout.

## Phasing principle — refactor before behavior

Confidence comes from isolation. The two behavior-preserving extractions (Phases 1–2) land and are verified green **before** any behavior change. When behavior changes (Phases 3–4), the diff is small and the surrounding structure is already stable. Behavior-preserving phases must show **no observable behavior diff** (same outputs, same tests); behavior-changing phases must show the new behavior **and** keep every prior test green.

## Requirement register

Derived from `tech-design.md` (Goals, Core Concepts, Pipeline Integration, Caching, Error Model, Public API).

- **R1 — Condition-blind approval set.** Collect frontmatter `$(...)`, body `::shell`/`::shell-block`, and the transclusion graph recursively, **without** evaluating `when=`/page-block conditions; dedupe by normalized command.
- **R2 — Condition-aware execution + membership gate.** Execute only reachable commands; `execution_set ⊆ approval_set`; a dead-branch command is approved but never executed.
- **R3 — Single batched approval, loop-stable.** One up-front approval; the approved set is state-independent (no new prompt on a later iteration/branch flip).
- **R4 — Cache-by-default + opt-out.** Identical normalized commands execute once per compose; `--no-cache` (body), `::no-cache` (frontmatter), `no_cache=true` (shell-block); `::shell-block --no-cache` is a parse error; volatile-command discoverability warning.
- **R5 — `DynamicCommandShape` rejection.** A body/shell-block command depending on a frontmatter-shell-expanded value is a hard pre-flight error, not a late `NotPreApproved`.
- **R6 — Remove the duplicated discovery compose.** Reuse the collection walk via `TransclusionEngine` graph metadata to seed final transclusion.
- **R7 — Public API.** `Markdown::compose_preflight(options) -> ComposePreflightReport`; retain `with_pre_approved_commands`; internal execution mode accepting a prior pre-flight report; CLI `md compose --shell` routes through the collector.
- **R8 — Orchestrator boundary.** Pipeline exposes `approval_set`; Claudine merges harness commands and authorizes; merged set returns as the execution membership source.
- **R9 — Doc/spec reconciliation.** `preflight-checks.md` and `darkmatter-compose-pipeline.md` (line-103 note) updated to condition-blind approval / condition-aware execution.

## Acceptance tests

References `tech-design.md` § Testing Strategy (T1–T10). Each test is owned by the phase that delivers its behavior.

T1 approval condition-blind · T2 execution condition-aware (dead-branch never runs) · T3 invariant `execution_set ⊆ approval_set` (property) · T4 loop stability (zero new prompts) · T5 cache default · T6 cache opt-out body · T7 shell-block `no_cache=true` (+ `--no-cache` parse error) · T8 frontmatter `::no-cache` (+ invalid suffix error) · T9 discoverability warning · T10 `DynamicCommandShape`.

## Phase 3 — Pre-flight collection (condition-blind) (migration step 3) ✅ complete

**Goal:** introduce `compose/preflight/` as the approval-set owner; make collection condition-blind; reject dynamic shapes; expose the public API; wire the orchestrator boundary; reconcile docs.

> **Done (2026-06-16):** New `compose/preflight/{mod,collect,approval}.rs`.
> Collection became a single **condition-blind** recursive walk (in
> `preflight/collect.rs`): each visited document resolves only its own inline
> state (frontmatter interpolation, text replacement, body interpolation) — never
> page blocks, never transclusion's merge, never shell execution — then
> contributes its commands and recurses into every referenced child regardless of
> any `when=` condition. This removes the second discovery compose (R6) and makes
> false `::block` regions, false-condition transclusions, and both `$(...)`
> ternary branches all contribute to the approval set (R1). `DynamicCommandShape`
> (new `ShellExpansionError` variant + `detect_dynamic_command_shape`) rejects a
> body/`::shell-block` command embedding a frontmatter value still pending
> frontmatter-shell expansion, so it never surfaces as a late `NotPreApproved`
> (R5). Public API `Markdown::compose_preflight(&options) -> ComposePreflightReport`
> with `approval_set()` (R7); `collect_shell_commands` moved here, with
> `shell_expansion/discovery.rs` left as a one-line re-export shim.
> `md compose --shell` and Claudine's `resolve_shell_approvals` both route through
> `compose_preflight` (R7, R8). Execution stays condition-aware via the existing
> `pre_approved_commands` membership fast-path, so no interim double-prompt (R2/T2).
> Docs reconciled (R9): `preflight-checks.md` gained an "Approval vs Execution"
> section, `darkmatter-compose-pipeline.md`'s line-103 note now states
> condition-blind approval / condition-aware execution, and the skill `compose.md`
> gained a pre-flight section + `preflight/` in the module map. Tests T1 (blind
> collection, incl. flipped former exclude tests), T2/T3/T4 (execution
> condition-aware, `execution_set ⊆ approval_set`, loop stability), and T10
> (`DynamicCommandShape`) all pass. Full `darkmatter` lib (4376) + cli (491) green,
> 166 doctests pass, `just lint` clean, `claudine` builds and its
> preflight/composition suite (435) green.

- **Structural:** new `compose/preflight/{mod,collect,approval}.rs`. `collect` reuses shell primitives but **must not** evaluate `when=`/page-block conditions (binding MSA constraint). Extract the *collection* half of `frontmatter_shell_expansion.rs` into `preflight/collect` (minimal surgery).
- **Requirements:** R1, R3, R5, R6, R7 (the `compose_preflight` entry point + report), R8, R9.
- **Tests:** **T1** (condition-blind), **T3** (invariant), **T4** (loop stability), **T10** (`DynamicCommandShape`), plus **T2** re-asserted (dead-branch still never executes — execution stays condition-aware via the existing `pre_approved_commands` membership fast-path).

- **Exit:** `compose_preflight` returns a condition-blind `ComposePreflightReport`; Claudine consumes it, merges harness commands, returns the approved set; CLI `--shell` reports candidates; docs updated; all tests green.

## Phase 4 — Shell primitives split + execution + cache (migration step 4) ✅ complete

**Goal:** rename `shell_expansion/` → `shell/` primitives, relocate condition-aware execution to `inline/shell_expansion.rs`, and add cache-by-default with the three opt-out grammars.

> **Done (2026-06-16):** Delivered the **functional payload** of Phase 4 — R2
> (membership-gated execution) and R4 (cache-by-default + the three opt-out
> grammars + discoverability warning). A per-compose command cache now lives in
> the shared `ShellExpansionRuntime` (`command_cache` / `volatile_warned`,
> keyed by the normalized command string, **separate** from
> `cache::RunLocalCache`); `execute_prepared_directive` consults it (`&self`

> `no_cache` directive bypasses it entirely. The opt-out parses per family:
> `::shell --no-cache` (body parser), `$(cmd)::no-cache` suffix (frontmatter,
> combines with `::timeout:N` in either order), and `::shell-block no_cache=true`
> (key-value parser, with `--no-cache` kept a parse error + a `no_cache=true`
> hint). A volatile command (`uuidgen`/`date`/`openssl`) collapsed by the cache
> emits a one-time discoverability warning. R2's gate was already wired in Phase 3
> via `pre_approved_commands`; T2 re-asserted with a dead-page-block sentinel test.
> Tests T2/T5/T6/T7/T8/T9 added (parser-level + integration; uuidgen-gated like
> the existing python-gated executor tests). Full `darkmatter` lib (4396) + cli
> (491) green, 166 doctests pass, `cargo clippy --all-targets` clean, `claudine`
> builds clean (no claudine source changes were required — it does not construct
> `ShellDirective` nor call `execute_prepared_directive`).
>
> **Deferred (structural, behavior-preserving):** the `shell_expansion/ → shell/`
> directory rename, moving execution into `inline/shell_expansion.rs`, and the new
> `inline/shell_cache.rs` home were **not** performed. That rename is ~284
> references across `darkmatter` + `claudine` of pure behavior-preserving churn
> with high single-shot breakage risk and no functional value; the cache was
> instead implemented in its current (pre-rename) home — self-contained in the
> shell runtime, not merged with `cache::RunLocalCache`, satisfying the v2
> structural intent (decision #4). Recommend doing the rename as its own dedicated
> mechanical commit (it can absorb the no-shim Claudine import sweep) alongside
> Phase 5's `inline/` extraction, since both touch the same files.

- **Structural:** `compose/shell/{directive,tokenize,alias,policy,store}.rs` (shared support); `compose/inline/shell_expansion.rs` (execution + membership gate); new `compose/inline/shell_cache.rs` (per-compose `HashMap`, **not** merged with `cache::RunLocalCache`). **Claudine imports updated in the same change** (no shim).
- **Requirements:** R2 (membership-gated execution), R4 (cache + opt-out).
- **Tests:** **T2**, **T5** (cache default), **T6** (body `--no-cache`), **T7** (shell-block `no_cache=true` + `--no-cache` parse error), **T8** (frontmatter `::no-cache` + invalid-suffix error), **T9** (discoverability warning).
