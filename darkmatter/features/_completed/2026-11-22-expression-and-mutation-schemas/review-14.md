## Unblocked Findings

### R14-F1 (high) Command preflight rejects recoverable missing frontmatter inclusions

**Authority (defect).** With `prologue: "./gone.md"`, `md compose --allow missing-transclusions` still exits 1 without a document. The same happens with `epilogue`, including a list that also contains a usable file. The public composition API skips that missing file under the same option. The public preflight API refuses it. The fault prevents a command with an explicit recovery option from producing output and prevents its `composed` event from running. [Frontmatter preflight loop](../../lib/src/markdown/compose/preflight/collect.rs#L1171) · [Runtime frontmatter handling](../../lib/src/markdown/compose/transclusion/engine.rs#L1021) · [CLI reference decision](../../cli/src/commands/compose.rs#L826)

The defect class is losing an allowed-missing decision when a second walker resolves the same inclusion. A quoted path and the same path in a singleton list should make the same decision. With recovery enabled, replacing a valid file path with a well-formed missing path should omit that inclusion. Replacing it with `@` or an existing unsupported file should still fail. I used the same guide with an existing `side.md`, a plain-text file, and an optional child whose `composed` event reports `done`. I exercised the public composition and preflight entry points and the built CLI.

### R14-F2 (medium) Skipped inclusion warnings lose their authored locations

**Authority (defect).** An embedder using the Darkmatter public composition API with missing-transclusion recovery receives a warning for a missing include, but the warning’s structured source has no line or column. This also surfaces in direct and lifecycle CLI JSON, where the preliminary check hands the author a located issue and the composition stage emits another record for the same miss without a position. Under the public ignore-invalid option, a skipped unsupported file or URL also becomes the generic `dm.compose.warning`, even though the typed failure and authored site are available at the skip. [Body skip](../../lib/src/markdown/compose/transclusion/engine.rs#L833) · [Frontmatter skip](../../lib/src/markdown/compose/transclusion/engine.rs#L1031) · [Warning construction](../../lib/src/markdown/compose/transclusion/engine.rs#L2126)

The defect class is replacing a located inclusion failure with a warning built from its message or a count in the rewritten body. The warning should retain the typed code and the authored opener, key, or list entry. Quoting an unchanged target or removing a preceding false block during composition should leave the warning attached to its authored site. Replacing a missing path with an existing admissible path should leave no warning. I exercised the public composition result with missing-target recovery alone and with ignore-invalid enabled, and the built CLI for the body recovery and neighbor controls.
