# DMLS cheaper live graph rebuilds

## Summary and Definition of Done

Reduce the path-derived work performed on each open-buffer edit without changing resolution, lazy parsing, notification batching, or immutable snapshot publication. Cache the live wiki universe by its complete inputs, then share an immutable document table across rebuilds with identical path-derived inputs. Reassemble every parsed document's content nodes, edges, resolutions, awaited paths, and reverse index on every publication.

Successful completion means:

- Content-only edits perform zero wiki-path canonicalizations, zero portability-key computations, and zero document-table constructions for unchanged paths. A listed join/leave, dependency transition, or changed wiki roots constructs one universe and one table per final batched rebuild.
- Cached and fresh builds produce equivalent document facts, nodes, spans, edge targets, wiki outcomes, derived lookups, awaited paths, diagnostics, and provider results across all transitions specified below. Old readers retain their original answers.
- Document IDs remain dense and path-ordered. Document roots precede content nodes, with root `NodeId(d)` for `DocumentId(d)`; node IDs remain snapshot-local.
- The normal notification/request path proves editing, diagnostic refresh, ambiguity changes, and batching still work. The persistent facts format and store-backed request behavior stay unchanged.
- One release editing sample records the completed optimization's costs alongside the existing measured baseline. Its results do not add another implementation phase or a performance gate.
- Darkmatter's `just test` and `just lint` pass; current topic documentation and DMLS skill guidance describe the implemented design. The implementation log records validation, measurements, and the lookup terminology correction below.

All paths below are repository-relative unless explicitly described otherwise. Waves are globally numbered. Tasks in the same wave may run concurrently with the stated file ownership; waves execute in order. Every session is non-interactive. No phase includes a human gate. This plan authorizes implementation and local validation, not a commit, push, installation, or lifecycle move.

## Phase 1: Cache the wiki universe

### Necessary Rules

1. **Implement both specified optimization steps; do not repeat the initial spike.** The spec's completed measurement reports 13.6% of one core in rebuilds, 97% attributable to open-buffer edits, and a step-1 prototype still using 4.4%. This settles both the cause and the need for step 2. Membership optimization, stable identities, keystroke coalescing, a new graph representation, synthetic large-workspace studies, and public benchmark-format changes are outside this change. The final sample is a delivery measurement, not a decision spike.

2. **Cache by value equality of complete universe inputs.** In `graph/invalidate.rs`, introduce private `WikiUniverseInputs { candidates: Vec<PathBuf>, dependencies: Vec<PathBuf>, wiki_roots: Vec<PathBuf> }` and `CachedWikiUniverse { inputs: WikiUniverseInputs, universe: Arc<WikiUniverse> }`; add `wiki_cache: Option<CachedWikiUniverse>` to `WorkspaceIndex`. Candidates are sorted/deduplicated `listed` plus parsed non-dependencies; dependencies are the sorted result of `dependencies()`; roots preserve their configured order. Equal inputs reuse the exact `Arc`; different inputs construct one replacement. Evidence: `WorkspaceIndex::rebuild`, `dependencies`, `open_buffer`, and `install_listing` distinguish listed, open-unlisted, and referenced-only documents; `WikiDoc::for_path` gives the first containing root precedence. Dirty flags and filesystem identity normalization are unnecessary and must not replace these comparisons.

3. **Prepopulate dependency slots in the cached universe.** Build candidates with `WikiUniverse::new`, then append sorted dependency paths with `WikiDoc::unmatchable()` before wrapping the result in `Arc`. Candidate and dependency sets are disjoint. Keep request-build fallback appending for missing paths through `Arc::make_mut`; a live rebuild over its own complete universe never takes that fallback. Evidence: `arena::assemble_listed` currently appends dependency slots, and `wiki/universe.rs::push` mutates the universe. Without prepopulation, a retained snapshot forces a copy on each live rebuild with dependencies. Dependency slots follow sorted candidate slots; the slot-to-document mapping, never numeric equality with `DocumentId`, remains authoritative.

4. **Cache portability keys per slot.** Add `portability_keys: Vec<String>` and `pub(crate) fn portability_key(&self, slot: usize) -> Option<&str>` to `WikiUniverse`; compute and append the key in `push`, including the empty canonical path of an unmatchable slot. `new`, `Default`, cloning, and equality keep all slot arrays aligned. Group collisions only over the graph's non-dependency documents, using their mapped slots. Evidence: `arena::portability_collisions` currently recomputes `wiki::portability_key` for every non-dependency document; a request graph may contain fewer documents than its universe, as `wiki_universe_equivalence.rs` proves. Never group every universe slot into graph collisions.

5. **Read canonical candidate facts from slots; preserve real dependency facts.** An existing non-dependency slot supplies `canonical` and `workspace_id`; a dependency record uses `WikiDoc::for_path` for its actual path, since its slot is intentionally unmatchable. A missing non-dependency slot is computed and appended through the existing fallback. Evidence: `arena::assemble_listed` currently computes real canonical facts before selecting or appending the slot. Step 2 moves dependency canonicalization into table construction, eliminating it on content-only reuse too. Retain supplied-universe precedence for request graphs, including a dependency already present as a candidate there; live dependency exclusion remains governed by rule 3.

6. **Share path lookups, not frontmatter content.** The shared table contains the existing **wiki basename** `KeyIndex`, not a frontmatter-key lookup. `graph/key_index.rs::KeyIndex::build` indexes path basenames, and `arena::finalize` builds it from non-dependency paths. In contrast, `assemble_listed` creates `FrontmatterKey` nodes and `key_by_name` from parsed content and resolves `UsesVariable` against them. Those nodes and that map must be rebuilt on every edit. Record this spec terminology departure in `implementation-log.md`; leave the specification's design text intact. Add a key-renaming edit test so stale variable targets cannot be hidden by the cache.

7. **Use one private immutable document table and borrowed public record views.** In `graph/arena.rs`, define private `DocumentPathRecord { path: PathBuf, canonical: Vec<String>, workspace_id: usize, dependency: bool, wiki_slot: usize }`, `DocumentState { content_hash: u64, parsed: bool }`, and `DocumentTable { records: Vec<DocumentPathRecord>, by_path: HashMap<PathBuf, DocumentId>, slot_documents: HashMap<usize, DocumentId>, keys: KeyIndex, portability: HashMap<DocumentId, Vec<DocumentId>>, universe: Arc<WikiUniverse>, listing: Listing }`. `WorkspaceGraph` and `GraphAssembly` hold `Arc<DocumentTable>` plus a dense `Vec<DocumentState>`; table records imply root `NodeId(position)`. Keep the exported name `DocumentRecord`, now `DocumentRecord<'a>`, a returned view with `path: &'a PathBuf`, `canonical: &'a Vec<String>`, and the existing scalar fields `content_hash`, `root`, `workspace_id`, `parsed`, `dependency`. Use `#[derive(Debug, Clone, Copy, PartialEq, Eq)]`. This preserves field-based reading without cloning path strings or assembling an owned record vector per snapshot. Evidence: `document` currently returns `&DocumentRecord`, and `documents` returns a slice mixing path facts with content state, so their exact return types cannot survive the required split without redundant work.

8. **Make the record API migration explicit.** Keep accessor names: `document(&self, id: DocumentId) -> Option<DocumentRecord<'_>>`; `documents(&self) -> impl ExactSizeIterator<Item = DocumentRecord<'_>> + DoubleEndedIterator + '_`. Remove `.iter()` at callers in `providers/{completion,frontmatter,symbols,wiki}.rs` and `tests/l1/entry_point_parity.rs`; direct iteration in `tests/l1/index_store_keys.rs` remains valid. `graph/mod.rs` keeps re-exporting `DocumentRecord`. Convert owned-path extraction to `.to_path_buf()` and canonical-segment ownership to `.to_vec()` at consumers of the borrowed fields, including `providers/{mod,definition,dsl,hover,location,rename,wiki}.rs` and `graph/invalidate.rs`. Internal `ReferenceResolver` takes table path records and the state slice instead of `&[DocumentRecord]`; `resolve_file_edge`, link resolution, transclusion resolution, and wiki resolution derive roots from document IDs. Evidence: repository-wide Rust searches found this graph record only in DMLS, with all explicit type references inside `graph/`; there is no other package API migration. Update lifetime-bound local bindings in tests retaining record views from temporary snapshots by first binding the snapshot `Arc`.

9. **Reuse tables only with exact structural inputs.** Add private `DocumentTable::matches` comparing the sorted union of parsed and listed paths to record paths, effective dependency flags to records, `Listing` by equality, and the universe by `Arc::ptr_eq`. The comparison ignores parsed status and hashes, which are per-snapshot state. `Listing::Pending`, `Ready { complete: false }`, and `Ready { complete: true }` are distinct inputs. A relink or awaited creation with equal structural inputs may reuse the table but still performs complete content assembly and resolution. Evidence: path records are derived solely from paths, dependencies, and universe roots; the actual `ReferenceResolver` consults `DocumentContexts` anew. No context-derived resolution or probe result belongs in the table, so context identity need not enter its key.

10. **Retain a fresh full-builder entry point.** Preserve signatures of `WorkspaceGraph::{build,build_with_roots,build_listed}`. They always construct a new table and run the same assembly/resolution path. Add crate-private `build_listed_reusing` with the same arguments plus final `previous: &WorkspaceGraph`; only `WorkspaceIndex::rebuild` calls it. Internally both routes call one builder accepting `Option<&WorkspaceGraph>`. Public builders pass `None`; the live route passes `Some`. Unsupported table inputs construct a full new table without another invalidation mechanism. Evidence: `index_store/workspace.rs` request graphs and existing oracle tests call the public builders; preserving those paths supplies an uncached reference and avoids store-format changes.

11. **Number roots first, then assemble parsed content in path order.** Allocate all root nodes in table order; iterate parsed `indices` in their `BTreeMap` order and look up their dense document IDs to append content. Preserve the existing per-document node sequence and deferred-edge passes. Keep heading maps only for parsed documents; missing heading entries read as empty, while unparsed targets remain unchecked through the explicit parsed flag. Evidence: the current assembly loop interleaves roots and content, and inserts empty heading vectors for unparsed files. The spec explicitly permits roots-first numbering; `resolve_in_document` already represents absent heading facts as `HeadingMissing`, with unparsed handling performed by `resolve_wiki_link`. No node or edge identity crosses a snapshot boundary.

12. **Preserve publication and resolution authority.** Leave `begin_batch`/`end_batch`, generation increments, unchanged-content short-circuiting, stale-parse handling, open-buffer precedence, `context::plan_reference`/`resolve_reference`, and `router::ServerState::apply_disk_changes` semantics intact. Only the graph construction work changes. Evidence: the router wraps all disk mutations in one index batch and publishes its final snapshot; `invalidate.rs` tests already prove awaited-only unlisted creation and no-op behavior. Re-resolve all references even with reused tables; an event does not prove existence or override probe failures.

13. **Extend existing deterministic work counters.** Add `wiki_universes`, `wiki_path_facts`, `wiki_portability_keys`, and `document_tables` to `work_counters::WorkCounts`, its `since`/snapshot functions, and its unit-test literal. Add crate-private recording helpers at `WikiUniverse::new`, `WikiDoc::for_path`, `WikiUniverse::push`'s key computation, and actual table construction, respectively. Match the existing atomic-counter model; do not add permanent duration logs, cause telemetry, a benchmark API, dependencies, or feature flags. Evidence: existing process-wide counters support integration assertions because nextest runs each test in its own process. Take work deltas before constructing the fresh oracle, which would itself increment counters.

14. **Keep this a graph change, not a loader change.** No parser, configuration field, persistent facts row, or serialization behavior changes. The Input Robustness Matrix therefore does not apply. Markdown/frontmatter content is test stimulus for graph invalidation, not a new file-format validator. No dependency documentation change or facts-version bump is required. Evidence: the touched construction paths consume typed `DocumentIndex`, `Listing`, paths, and already-captured contexts.

15. **Use portable comparisons and tests.** Retain ordinary Rust `Path`/`PathBuf` ordering and equality used by the existing `BTreeMap` and universe. Do not introduce raw filesystem canonicalization, slash-string cache keys, or OS-specific production code. Use `context::test_support::{abs,workspace_contexts}` in unit fixtures, and `LspWorkspace`/`RequestSnapshot` with runtime fixture roots in sessions. Exercise NFC/case collision facts using logical paths, without requiring two case-distinct files on a case-insensitive disk. Evidence: the DMLS skill documents rootless-path failures on Windows, and the OS skill distinguishes native Windows from WSL2. Cross-platform correctness remains required; the performance sample remains one macOS host.
