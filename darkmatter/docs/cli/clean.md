## Overview

The `clean` command tidies how a Markdown document is spelled without changing
what it means. It repairs deterministic YAML problems in the frontmatter and
formats the body under the document's
[`style.markdown`](../topics/markdown-formatting.md) rules: padded tables,
labeled code fences, renumbered ordered lists, consistent nested-list
indentation, and blank lines around lists. Command-line flags override the
document's rules for one run.

Cleanup is all or nothing. It checks its result against the input, and if the
structure or meaning differs anywhere it prints the original document
unchanged and reports `clean.fidelity-fallback` instead (see [When cleanup
declines](#when-cleanup-declines)). With the default rules, cleanup never:

- changes or moves a directive line (`::block`, `::end-block`, `::file`,
  `::shell`, …) or adds a blank line next to one
- joins or re-wraps lines you wrote (unless you ask for `unwrap` or
  `fixed-width`)
- changes link targets, emphasis, hard breaks, HTML, task-list state, or code
- adds trailing whitespace, changes line endings, or adds a final newline

Frontmatter repair is enabled by default; `style.markdown.frontmatter: false`
turns it off for a document. Only the YAML between the opening and closing
frontmatter delimiters is analyzed. The delimiter lines, including their
surrounding whitespace and line terminators, are preserved byte-for-byte. YAML
fenced code blocks in the Markdown body are never inspected or changed by the
YAML analyzer.

Without `--save`, the result is written to stdout and the input file is not
modified. With `--save`, the result is written back to the input file.

It is useful when you want to:

- Normalize spacing and structure before committing documentation
- Standardize markdown generated by multiple tools
- Fix common formatting noise without changing meaning
- Keep backslash escapes you wrote (`\*`, `\.`, `\-`, Windows paths such as `C:\repo\.claudine`)

## Reporting

### Usage

```bash
# Clean and print cleaned markdown to stdout
md clean README.md
md clean -
cat README.md | md clean

# Emit the v1 diagnostic envelope instead of cleaned Markdown
md clean README.md --json

# Replace the document's $schema layer for this run
md clean README.md --schema docs.schema.yaml

# Replace or disable the default Darkmatter baseline schema
md clean README.md --baseline-schema project-baseline.yaml
md clean README.md --no-baseline-schema

# Disable repository trigger schemas
md clean README.md --no-trigger-schemas

# Join wrapped prose, then re-wrap it to 80 columns
md clean README.md --fixed-width 80

# Keep source line breaks even if the document asks for unwrap or fixed-width
md clean README.md --ignore-incidental-newlines

# Clean and enforce 2-space nested list indentation
md clean README.md --indent 2

# Remove (or add) blank lines between sibling list items
md clean README.md --compact
md clean README.md --loose

# Clean in place and print a delta-style report
md clean README.md --save

# Clean in place with delta report + visual diff
md clean README.md --save -v

# Shorthand for clean-and-save
md README.md --save
```

### Arguments

- `[INPUT]`: Markdown file path (supports `@` file references). Use `-` for stdin. If omitted, reads from stdin.
- `--save`: Clean in place and print a delta-style change report (same report format used by `md delta`).
- `--indent <#>`: Sets `indentation` to `2`, `4`, or `8` spaces per nested-list level. For an eight-space step, cleanup uses CommonMark-valid marker padding on parent items when needed to preserve the same list tree.
- `--compact`: Sets `list-item-padding: none` (no blank lines between sibling list items). Conflicts with `--loose`.
- `--loose`: Sets `list-item-padding: one` (one blank line between sibling list items). Conflicts with `--compact`.
- `--fixed-width <#>`: Sets `fixed-width`: join single newlines in prose, then re-wrap prose, including list-item paragraphs, to the target display width.
- `--ignore-incidental-newlines`: Sets `unwrap: false` and `fixed-width: false`, keeping source single newlines even when the document asks for unwrapping or a width.
- `--json`: Emit the version-1 diagnostic envelope as the sole stdout payload. The cleaned document, human suggestion report, and save-mode delta report are suppressed.
- `--schema <PATH>`: Replace the document's inline or referenced `$schema` layer with an explicit SimplifiedSchema file. Baseline and matching trigger layers still apply beneath it.
- `--baseline-schema <PATH>`: Replace the default Darkmatter baseline with an explicit SimplifiedSchema file.
- `--no-baseline-schema`: Disable the default Darkmatter baseline. Conflicts with `--baseline-schema`.
- `--no-trigger-schemas`: Disable repository trigger discovery and bare-name schema-root lookup.

`--fixed-width` and `--ignore-incidental-newlines` cannot be used together.
Fixed-width reflow starts by removing the source wrapping that
`--ignore-incidental-newlines` preserves.

Each formatting flag overrides only its own rule, for this run. A rule with no
flag comes from the document's `style.markdown`, then the built-in default.
The full rule list, precedence, and examples are in [Markdown Formatting
Rules](../topics/markdown-formatting.md).

Shell completion notes:

- `[INPUT]` completes markdown files (`.md`, `.dm`) and traversable directories.
- `--indent` completes to `2`, `4`, or `8`.
- `--fixed-width` completes common prose widths (`40`, `60`, `80`, `100`, `120`) and accepts any value from `1` through `1000`.

### Output Modes

**Default mode (no `--save`)**

- Prints cleaned markdown to stdout (the original document when cleanup declines)
- Does not modify files
- Prints report-only findings to stderr, in two sections: "frontmatter
  suggestions (not applied)" and "markdown cleanup" (`clean.invalid-rules`,
  `clean.fidelity-fallback`). Findings do not change the exit code

**Save mode (`--save`)**

- Requires a file path input (stdin is not supported)
- Writes cleaned markdown back to the same file
- Prints a delta-style report instead of cleaned markdown
- Skips writing when the file is already clean (no changes detected) or when
  cleanup declines
- With `-v`/`--verbose`, also prints frontmatter/content visual diffs

**JSON mode (`--json`)**

- Prints one version-1 JSON envelope to stdout instead of Markdown or a delta report
- Suppresses human diagnostics on stderr; findings are in `diagnostics`
- With `--save`, writes the cleaned file and still prints the envelope
- Reports whole-document `changed`, not merely whether frontmatter was repaired
- When cleanup declines, reports `changed: false`, `applied: []`, and the
  `clean.fidelity-fallback` finding; stderr stays empty

### Frontmatter Repair and Schema Precedence

`md clean` auto-applies only deterministic repairs whose safety proof passes.
These include source normalization, parse-equivalent whitespace cleanup,
tab-indentation repair (each indentation tab becomes two spaces, matching how
Darkmatter reads tab-indented frontmatter), root-indentation repair (see
[Indented Root Mappings](#indented-root-mappings-yamlroot-indentation)),
reserved-indicator quoting, and schema-proven string quoting. Bytes outside
accepted edits are preserved. Non-deterministic findings, including duplicate
keys and suspicious values, are report-only and never mutate the document.

A report-only schema finding ends with its instance path, the validator's JSON
Pointer, in both the stderr suggestion and the JSON
`message`. The span cannot stand in for it: a node in a flow collection
(`content_policy: [TimeSensitive, Duration(3mo)]`) has no located span and
reports the document start.

```text
- schema.shape-repair. "Duration(3mo)" is not valid under any of the schemas
  listed in the 'anyOf' keyword (at `/content_policy/1`)
```

A missing or unknown key's path is its parent object's, and the message names
the key; a missing or unknown top-level key has an empty pointer and so no
suffix.

For a non-empty frontmatter block, the effective schema is assembled in this
order, with later layers taking precedence:

1. The default Darkmatter baseline, an explicit `--baseline-schema`, or no
   baseline when `--no-baseline-schema` is set.
2. Matching repository trigger schemas, unless `--no-trigger-schemas` is set.
3. The document's inline or referenced `$schema`, replaced by `--schema` when
   that flag is present.

Trigger discovery requires a file-backed document path. It is inert for stdin,
even when the current directory is inside a repository; `--schema` and
`--baseline-schema` still apply to stdin. Schema resolution is skipped for
documents with no frontmatter or an empty frontmatter block.

There is no `md clean --strict` in v1. Report-only findings remain suggestions
and exit successfully.

### Indented Root Mappings (`yaml.root-indentation`)

Frontmatter whose top-level keys are all indented is valid YAML, and
Darkmatter reads it normally. The text-preserving editors, such as
[`md hash --save`](./hash.md#indented-frontmatter), need top-level keys at
column 0, so they refuse it. `md clean` repairs it by removing the leading
spaces every content line shares:

```markdown
---
    title: Weekly report
  # indented less than the keys
    prompt: |
      Summarize the week.
    tags: [ops]
---
```

After `md clean --save`:

```markdown
---
title: Weekly report
  # indented less than the keys
prompt: |
  Summarize the week.
tags: [ops]
---
```

Comments indented at least as far as the keys move with them; comments
indented less keep their position. The repair never touches line terminators
or the delimiter lines. DMLS formatting applies the same repair, and a second pass
finds nothing to do.

The repair is offered only for a nonempty block mapping whose first key is an
ordinary `key: value` entry. It is not offered for flow (`{...}`), sequence,
or scalar roots, for empty or comment-only frontmatter, for YAML with
directives or explicit `---` / `...` document markers, or when the first key
is complex (`?`), tagged, anchored, or an alias. Like every automatic repair,
it must also pass the parse-equality proof: the dedented YAML has to read as
the same value. When it does not, for example because blank lines inside a
block scalar would change the scalar's text, nothing is applied and the
editors keep refusing the file; move the keys to column 0 by hand. Tab-indented
frontmatter is first repaired by `yaml.tab-indentation`, and the same run then
removes the remaining indentation.

### When Cleanup Declines

When cleanup cannot format the body without changing its structure or
meaning, it leaves the whole document unchanged and reports one
`clean.fidelity-fallback` finding that names the first place the result
differed. It is a report, not an error:

- human mode prints the original document (or, with `--save`, writes
  nothing) and the finding on stderr;
- `--json` reports `changed: false`, `applied: []`, and the finding;
- frontmatter repairs from the same run are discarded, so the file is never
  half-cleaned;
- the exit code is `0`.

The common cause is a malformed directive region, for example a `::block`
with no `::end-block`:

```text
markdown cleanup
- clean.fidelity-fallback. cleanup left the document unchanged because of a
  malformed directive region at line 4, column 1: ::block when="x" is never
  closed by an ::end-block
```

Fix the directive and run `md clean` again. A refusal on a well-formed
document is a cleanup bug.

An unusable `style.markdown` value is also report-only: cleanup reports
`clean.invalid-rules`, ignores the document's `style.markdown`, and formats
with the flags and defaults.

### Version-1 JSON Envelope

The v1 envelope has six top-level fields. Diagnostic spans use byte offsets
into the whole authored document: offsets are zero-based and end-exclusive;
lines and byte columns are one-based. `applied` contains only repairs actually
accepted and applied. Existing v1 fields and enum/code spellings are stable;
later versions may add fields.

Classification spellings are `deterministic`,
`deterministic_find_non_deterministic_solution`, and
`non_deterministic_find`. Diagnostic codes are stable dotted lowercase names;
the `yaml.*` family comes from `biscuit-file` and the `schema.*` family comes
from Darkmatter's schema-aware layer. Diagnostics are emitted in stable source
order, and a diagnostic with no candidate repair contains `"repairs": []`.

```json
{
  "version": 1,
  "source": { "kind": "file", "path": "README.md" },
  "frontmatter": {
    "present": true,
    "span": { "start": 4, "end": 25 }
  },
  "diagnostics": [
    {
      "code": "yaml.reserved-indicator",
      "classification": "deterministic",
      "message": "plain scalar begins with the reserved YAML indicator `@` and does not parse",
      "span": {
        "start": 11,
        "end": 24,
        "start_line": 2,
        "start_column": 8,
        "end_line": 2,
        "end_column": 21
      },
      "repairs": [
        {
          "span": { "start": 11, "end": 24 },
          "replacement": "\"@daily-report\"",
          "explanation": "quote the scalar so the indicator is treated as string content"
        }
      ]
    }
  ],
  "applied": [
    {
      "span": { "start": 11, "end": 24 },
      "replacement": "\"@daily-report\"",
      "explanation": "quote the scalar so the indicator is treated as string content"
    }
  ],
  "changed": true
}
```

For stdin, `source` is `{ "kind": "stdin", "path": null }`. When no
frontmatter is present, `frontmatter` is `{ "present": false }`.

### Exit Status

- Exit `0`: cleanup succeeds, including when report-only suggestions exist
  and when cleanup declines (`clean.fidelity-fallback`).
- Exit `1`: cleanup cannot complete, including frontmatter that cannot be
  read even after repair (or with repair turned off), a missing or invalid
  referenced schema, or `--save` with stdin. Human mode writes the error to
  stderr and leaves a save target untouched; the body is not cleaned either.
- With `--json`, unreadable frontmatter still exits `1`, but stdout contains
  the v1 envelope (including `yaml.parse`, with `applied: []`), stderr is
  empty, and the file is untouched.

Frontmatter that strict YAML rejects but Darkmatter reads, such as a bare
`{{ … }}` value, is not an error: the block is kept as written, `yaml.parse`
is reported as a suggestion, and the body is cleaned. Tab indentation is
different because it has a repair: each indentation tab becomes two spaces,
which Darkmatter reads as the same value.

### Save Mode Constraints

- `--save` with stdin (`-`) returns an error:
    - `--save requires an input file path (stdin is not supported)`
- `--save` can be used either:
    - On the subcommand: `md clean FILE.md --save`
    - As top-level shorthand: `md FILE.md --save`

## Transformations Applied

Each body transformation belongs to one `style.markdown` rule. The default
column is what happens when neither the document nor a flag sets the rule.

| Rule | Default | Transformation |
| --- | --- | --- |
| `frontmatter` | on | Proven deterministic YAML repairs to the frontmatter only; every other finding is reported without mutation |
| `table-layout` | on | Pads table cells for aligned columns |
| `default-language` | `text` | Adds a language to fences that have none |
| `ordered-lists` | on | Renumbers ordered lists that are neither uniform (`1, 1, 1`) nor sequential (`3, 4, 5`) |
| `indentation` | `4` | Re-indents nested lists, keeping the same list tree |
| `list-padding` | on | One blank line before and after each list, where structure allows |
| `list-item-padding` | `preserve` | Blank lines between sibling items (`--compact`, `--loose`) |
| `list-interior-padding` | `preserve` | Blank lines before blocks nested in an item |
| `unwrap` | off | Joins single newlines inside paragraphs |
| `fixed-width` | off | Unwraps, then re-wraps prose to a display width (`--fixed-width`) |

Everything else is kept as written: list markers (`*`, `-`, `+`, `1.`,
`1)`), emphasis markers (`*` vs `_`), escapes, blank lines between other
blocks, block quotes, headings, HTML, line endings, a byte-order mark, and
whether the file ends with a newline. With every body rule off, the body is
byte-for-byte unchanged.

## Examples

### Default

Input:

````markdown
Intro:
- a
- b

```
code
```
````

Command:

```bash
md clean -
```

Output (a blank line before the list and a `text` label; the line breaks are
kept):

````markdown
Intro:

- a
- b

```text
code
```
````

### Fixed Width

Input:

```markdown
This paragraph was wrapped by an editor at a fixed column
and should be collapsed before being wrapped to the requested display width.
```

Command:

```bash
md clean --fixed-width 80 -
```

Output:

```markdown
This paragraph was wrapped by an editor at a fixed column and should be
collapsed before being wrapped to the requested display width.
```

For list-item paragraphs, the width includes the complete list and blockquote
container prefix. Newly wrapped continuation lines use a hanging prefix aligned
with the first body character:

Input:

```markdown
- Alpha beta gamma delta
    epsilon zeta eta theta.
```

Command:

```bash
md clean --fixed-width 24 -
```

Output:

```markdown
- Alpha beta gamma delta
  epsilon zeta eta
  theta.
```

### Rules From the Document

A document can carry its own rules; a flag still wins for its rule:

```markdown
---
style:
    markdown:
        unwrap: true
---
This paragraph was wrapped
by an editor.
```

`md clean -` joins the paragraph into one line;
`md clean --ignore-incidental-newlines -` keeps both lines.

### Color and Styling

- Default clean output is plain markdown text.
- Save-mode reporting uses the same symbol-based style as `md delta`.

## Lessons Learned

- Cleanup is formatting-oriented and never changes document meaning; when it cannot show that a result keeps the meaning, it declines and leaves the document unchanged.
- `clean --save` is built to support in-place workflows while still surfacing exactly what changed.
- Using `md FILE.md --save` provides a fast top-level shorthand for the same behavior.

## Issues

- No `--output` flag exists for `clean`; output behavior is mode-based (`stdout` vs `--save` report).
