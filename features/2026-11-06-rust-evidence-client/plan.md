# Rust evidence client implementation plan

## Summary and Definition of Done

Create the `evidence-client` library and `evidence-client-cli` package area, port the current qualification rules without changing their decisions, and replace evidence-note transport with the prerequisite Worker API. Move host, rig, seed, hosted, nightly, inspection, and recovery callers together. Preserve the Python planner, its `--apply-to` operation, scope-note transport, whole-run validation reuse, and nightly certification. Retain version-1 exact-tree reuse through a separate legacy store envelope; never manufacture modern observations from legacy receipts.

Done means frozen Python/Rust comparisons agree on accepted cells, selected identities, rejection codes, conflicts, and nightly blockers; authenticated store integration and failure recovery pass; checksummed version-specific binaries work on macOS, Linux, native Windows, and toolchain-free WSL2; final migration is reconciled; production readers and publishers use Rust and the store; replaced Python modules are removed; scope receipts and constraints retain their behavior; and current documentation describes the resulting system. No policy differences are accepted as part of this port. Fix every parity mismatch before cutover.

Execute all seven phases without a human gate. Waves have globally unique numbers. Tasks within a wave may run concurrently with the file ownership stated below; later waves depend on earlier checkpoints. Every subagent brief must repeat that the entire session tree is non-interactive. Do not commit, push source changes, create branches/worktrees, run `cargo fmt`, or move the feature into a lifecycle directory. Authorized release/deployment operations use the existing automation, not bypasses of its policy. An unavailable prerequisite or credential is an execution failure with a named diagnostic and retained progress, never permission to mark acceptance complete. Continue independent tasks before reporting an incomplete run.

10. **Outages fail visibly.** A transport failure returns nonzero plus a versioned failure document containing no reusable cells; adapters explicitly retain all affected required cells and attach the diagnostic. 11. **Snapshots and cache.** Read primary snapshot generation, retention epoch, repository revision, and both event watermarks once; bind every history/location page to them. Batch reachable heads to the API's 256-head limit while exhausting every page and retry predecessor. A missing page or pruned/expired snapshot invalidates the entire evaluation. Cache only within a captured request, bound to repository, canonical plan, base/head/tree, verifier policy, generation/epoch/revision, and earliest location expiry, capped at five minutes. Recheck snapshot validity and expiry immediately before applying a carried decision; changed revision triggers complete reevaluation, at most three evaluation rounds before a visible unavailable result. Do not publish shared evaluations or trust persisted cached passes. Evidence: prerequisite snapshot/cursor/retention rules and specification's stale-publication requirement.

Trusted recovery runs on protected code and imports the untrusted attempt only after normal validation. Requests time out at 60 seconds and retry network/429/503 failures at most five attempts, with capped jitter and Retry-After matching prerequisite rule 12. Use API limits (1 MiB JSON/pages/chunks, 256 observations/heads, 64 MiB object); oversized retry collections are rejected intact. ### Input Robustness Matrix

Default: invalid configuration/request shapes produce a located typed error with file/resource and JSON path or line, run no tests, publish nothing and apply no reusable cells. Validate a whole recording/import bundle before its first mutation. Reuse misses are valid decisions, not parse errors. Existing contract quirks are preserved explicitly in fixture manifests rather than accidentally tightened.

- **Loader families:** one strict lossless JSON loader handles plans, receipts, observations, service responses, proofs, event payloads, policy, pins and resume/import journals. Test duplicate keys at nested depth, malformed UTF-8, trailing data, nonfinite numbers, null/scalar roots, Unicode/surrogate and numeric syntax once through public load/evaluate/import APIs. Version dispatch precedes version-specific field errors. A strict JSONL loader applies that loader per record to producer manifests, backend and status records; blank lines are ignored, malformed nonblank lines reject recording with a line number. Inspection alone tolerates torn/invalid lines and labels their presence; it cannot certify anything. Test that separate diagnostic loader once, including blank lines and a final truncated line. JUnit XML loading is a separate loader: reject malformed/trailing XML and external entities; test valid tool-generated XML, counts and failing names through public recording results. Cargo metadata and deployment policy remain owned by existing tooling; do not add YAML/TOML parsing to this client.
- **Shared field validators:** walk absent, null, wrong whole type and empty through each required scalar/object validator; collection validators also cover mixed-invalid and all-invalid members. Share validators for identifiers/nonempty strings, exact integer schema versions, finite durations/nonnegative counts, booleans, digests/byte sizes, objects, arrays, enums, context/OIDs, cell keys, report references, retry links, snapshot bounds/cursors and expiry. Each wired load-bearing field gets its valid control and one invalid-shape case, proving the connection without multiplying whole matrices.
- **Load-bearing field inventory:** plans include event/environment/cell/build/input paths, reusable/gap/companion/filter/backend/features and coverage boundary; evidence includes source/version/context, producer identity, outcome/completion/counts/failures/durations, features/build, retries, reports, proof and original locators; proofs include version/package/gate/complete and expected tests; service includes repository/generation/epoch/revision/watermarks, IDs/pages/cursors/has_more, location state/digest/size/expiry and capabilities; local configuration includes endpoint/repository/token-file/evidence root, pins, bundle content/acknowledgments and import checkpoints; reuse includes event/ref/tree/base/head/run/conclusion/artifact identity, certifications/environment policy/audit results; JSONL includes gate/package/environment/exit status/report presence/backends/duration. Put the exact field-to-validator map in `evidence-client/docs/input-validation.md` alongside tests.
- **Exceptions:** optional evidence `retry_of`, `features`, `build`, filter and proof fields accept omission only where existing validators allow it; explicit null remains rejected. Missing package closure permits exact-tree reuse only. Empty v3 observations are a valid no-op; empty v2 cells remain invalid. Empty planned cells yields an empty successful evaluation. Empty reports on incomplete attempts remain valid but prove no coverage. Absent cursor is the initial page; null/missing continuation on `has_more:true` is invalid. Missing evidence-root directory is an empty inspection, not a passing evaluation. Preserve structural proof-digest nonempty-string acceptance; byte verification can still reject the claim. Missing legacy measurements are rendered unrecorded. Unknown field handling follows the frozen validator for each existing format; new request/pending/pin formats reject unknown fields, service extensions ignore only documented non-load-bearing metadata.
- **Public results:** derive every mutation from a frozen real-tool control with one edit. Assert positive load-bearing decisions first, then located errors, zero launches and zero publication. CLI wiring uses one control and one or two malformed examples per loader, not one spawned process per cell. Test no partial effects for a later invalid collection member or manifest line.
- **Completion audit:** search changed code for `#[serde(default)]`, `Option<T>` conflating null/absence, `filter_map` with `as_str`, `unwrap_or_default`, and swallowed `.ok()` parsing. Use explicit presence types for fields whose null/absence differ. Record justified defaults in the field map. A finding about one matrix cell must report all shapes in its validator and loader before closure.

Checkpoint: staged caller tests pass with fake service and both positive/negative CLI wiring; every input outcome is observable at the public crate API. Rust supplies all qualification and identity decisions, while Python still supplies the canonical plan.
