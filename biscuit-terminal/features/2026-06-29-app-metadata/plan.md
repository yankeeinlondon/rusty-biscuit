# Plan: Terminal App Configuration & Environment Metadata

Success means `biscuit-terminal` exposes static terminal app metadata, resolves the active config file with provenance, extracts supported values, preserves the legacy config path behavior, and ships `bt about [APP]` with JSON, terminal, and plain output. The library stays sniff-free; install detection is CLI-only.

## Phase 1: Baseline Inventory And Compatibility Contract

- [x] Capture the current workspace state with `git status --short` and note any pre-existing user changes before editing.
- [x] Run `cargo metadata --no-deps --format-version 1` from the repo root and identify the exact `biscuit-terminal` library and CLI package names used by `just`.
- [x] Read the existing config resolver in `biscuit-terminal/lib/src/discovery/config_paths.rs` and record every `TerminalApp` variant that currently returns `Some`.
- [x] Read `biscuit-terminal/lib/src/discovery/detection/app.rs` and record all `TerminalApp` variants, display strings, and environment detection paths.
- [x] Read `biscuit-terminal/cli/src/args.rs`, `main.rs`, `output.rs`, and the five `CliStyles` call sites named by the spec.
- [x] Check `biscuit-terminal/lib/Cargo.toml`, `biscuit-terminal/cli/Cargo.toml`, root `docs/dependencies.md`, and the per-area dependencies doc location before adding dependencies.
- [x] Validation checkpoint: write down the app-coverage floor as a concrete list of legacy `Some` apps, including `VsCode`, `Konsole`, `Foot`, `Contour`, and `Warp`.

### Phase 1 Inventory Findings

**Workspace state:** clean. Only pre-existing change is the untracked
`biscuit-terminal/features/2026-06-29-app-metadata/plan.md` (this plan). No
user working-tree edits to preserve.

**Package names (from `cargo metadata`):**

- Library: `biscuit-terminal` — manifest `biscuit-terminal/lib/Cargo.toml`,
  lib target name `biscuit_terminal`.
- CLI: `biscuit-terminal-cli` — manifest `biscuit-terminal/cli/Cargo.toml`,
  binary name `bt`.

**App-coverage floor (legacy `Some` apps in
`config_paths::get_terminal_config_path`).** These must never regress to
`None` after the Phase 3 rewrite (subject to their existing per-OS gating):

- `Wezterm` — Some on all OSes.
- `Kitty` — Some on macOS/Linux (None on Windows).
- `Ghostty` — Some on macOS/Linux.
- `Alacritty` — Some on all OSes (Windows via `%APPDATA%`).
- `ITerm2` — Some on macOS only.
- `AppleTerminal` — Some on macOS only.
- `Konsole` — Some on Linux/FreeBSD/NetBSD/OpenBSD (dir path).
- `Foot` — Some on Linux/FreeBSD.
- `Contour` — Some on Windows/macOS/Linux.
- `Warp` — Some on macOS/Linux (points at `~/.warp` directory).
- `VsCode` — Some on Windows/macOS/Linux.

Variants that already return `None` (not part of the floor): `GnomeTerminal`
(dconf), `Wast`, `Other(_)`.

**`TerminalApp` variants (`discovery/detection/app.rs`):** `AppleTerminal`,
`Contour`, `Foot`, `GnomeTerminal`, `Kitty`, `Alacritty`, `Wezterm`,
`Konsole`, `ITerm2`, `Warp`, `Ghostty`, `Wast`, `VsCode`, `Other(String)`.
There is **no** `WindowsTerminal` variant yet — Phase 3 adds it.

- Derives: `Debug, Clone, Serialize, Deserialize`. No `PartialEq`.
- Display: `Other(name)` → `name`; every other variant → its `Debug` string
  (`Kitty`, `Wezterm`, `ITerm2`, `AppleTerminal`, …).
- `get_terminal_app()` detection order: (1) `TERM_PROGRAM` match table
  (`Apple_Terminal`, `iterm2`/`iTerm.app`, `vscode`, `warp`/`WarpTerminal`,
  `ghostty`, `kitty`, `Alacritty`, `WezTerm`, `gnome-terminal`, `konsole`);
  (2) terminal-specific env vars — **`WT_SESSION` currently returns
  `Other("Windows Terminal")`** (Phase 3 changes this to `WindowsTerminal`),
  then `KITTY_WINDOW_ID`/`KITTY_PID`, `WEZTERM_PANE`/`WEZTERM_UNIX_SOCKET`,
  `ITERM_SESSION_ID`/`ITERM_PROFILE`, `GHOSTTY_RESOURCES_DIR`, `ALACRITTY_*`;
  (3) `TERM` table (`xterm-kitty`/`kitty`, `alacritty`, `wezterm`, `ghostty`,
  `foot`/`foot-extra`, `contour`); fallback `Other(term)`.

**CLI surface & the five `CliStyles` call sites named by the spec:**

- `cli/src/args.rs` — global flags on `Args`: `--json`, `-v/--verbose`
  (count), `-q/--quiet`, `--silent`, `--completions`. No `--plain` yet
  (Phase 5). `Command` subcommand enum has no `about` (Phase 6).
- `cli/src/main.rs` — builds `CliContext { json }`, dispatches subcommands
  via `Run`; default path prints metadata / content analysis.
- `cli/src/output.rs` — two `CliStyles::detect()` call sites:
  `print_content_analysis` (content-analysis path) and `print_pretty`
  (default metadata path). Both emit raw ANSI via `println!`.
- `cli/src/commands/graph.rs`, `cli/src/commands/mermaid.rs`,
  `cli/src/commands/shared.rs` — the other three `CliStyles` call sites.
- `CliStyles` itself lives in `cli/src/types.rs` (`detect`/`plain`/`ansi`;
  honors `NO_COLOR` only). To be deleted in Phase 5 once call sites migrate.

**Dependencies (pre-change baseline):**

- `biscuit-terminal/lib/Cargo.toml`: no `biscuit-file`, no `plist` (Phase 4
  adds both). Has `serde`, `serde_json`, `globset`, `regex`, etc.
- `biscuit-terminal/cli/Cargo.toml`: no `sniff` (Phase 6 adds `sniff/lib`
  CLI-only). Depends on `biscuit-terminal` with `clap` + `image` features.
- Dependency docs to update later: root `docs/dependencies.md` and per-area
  `biscuit-terminal/docs/dependencies.md`.

**Discovery module surface (`lib/src/discovery/mod.rs`):** public submodules
`clipboard`, `config_paths`, `cursor_position`, `detection`, `eval`, `fonts`,
`locale`, `mode_2027`, `os_detection`, `osc_queries`, `raw_mode`. Phase 2 adds
`app_metadata` here.
