# FileSystem

Renders directory trees in the terminal with tree-style output using Unicode box-drawing characters (`├──`, `└──`, `│`). Supports Nerd Font icons for files and directories with Unicode fallbacks, gitignore awareness, configurable depth/entry limits, symlink detection, per-file metrics (size, tokens, timestamps, permissions, ownership), OSC8 clickable hyperlinks, and color highlights.

## Programmatic Use

```rust
use biscuit_terminal::prelude::*;

// Basic usage
let mut fs = FileSystem::new(".")?;
fs.ensure_tree_built();
let term = Terminal::default();
print!("{}", fs.display(&term));

// With formatting presets + customization
let mut fs = FileSystem::new_with_formatting(".")?
    .depth(5)
    .max_entries(100)
    .highlight_green("src")
    .highlight_red("TODO")
    .with_file_links();
fs.ensure_tree_built();
println!("{}", fs.render(&Terminal::default()));
```

`FileSystem::default()` constructs an instance rooted at the current working
directory (falling back to `"."` if the CWD cannot be resolved) — useful for
quick demos but most callers should use `new()` or `new_with_formatting()` so
that path errors surface early.

### Constructors

| Constructor | Description |
|-------------|-------------|
| `FileSystem::new(path)` | Validates the path and returns `Result<Self, FileSystemError>` |
| `FileSystem::new_with_formatting(path)` | Same as `new()` plus italicize dotfiles/dotdirs, dim gitignored entries, and skip recursing into gitignored directories |
| `FileSystem::default()` | Uses `std::env::current_dir()` (or `"."` on failure); never errors |
| `TryFrom<&str> / TryFrom<String>` | Equivalent to `FileSystem::new(...)` |
| `TryFrom<&Path> / TryFrom<PathBuf>` | Equivalent to `FileSystem::new(...)` |

### Tree-shape Builders

| Method | Description |
|--------|-------------|
| `.depth(n)` | Maximum recursion depth (default `20`; `0` = root only) |
| `.max_entries(n)` | Hard cap on total entries rendered (default `1000`) |
| `.show_root(bool)` | Toggle the root header line (default `true`) |
| `.filter(pattern)` | Repeatable — restricts entries whose names contain `pattern` |
| `.do_not_recurse_gitignore(bool)` | Show gitignored dirs but don't descend into them |
| `.hide_dot_files(bool)` / `.hide_dot_dirs(bool)` | Omit dotfiles / dotdirs entirely |

### Styling Builders

| Method | Description |
|--------|-------------|
| `.italicize_dot_files(bool)` / `.italicize_dot_dirs(bool)` | Italic styling for entries starting with `.` |
| `.dim_gitignore(bool)` | Render `.gitignore`-matched entries dim |
| `.highlight_red(pattern)` / `.highlight_green(pattern)` | Repeatable — color matching entries |
| `.with_file_links()` | Wrap filenames in OSC8 hyperlinks (TTY only) |
| `.layout(Layout)` | Replace the entire layout config (margins/alignment) |
| `.left_margin(Margin)` / `.right_margin(Margin)` | Per-side margins (via the `Renderable` trait) |
| `.alignment(Alignment)` | Block alignment (via the `Renderable` trait) |
| `.show_on_directories()` | Also show applicable metrics (timestamps, permissions, owner/group) on directories — `FileSize` and `Tokens` remain file-only |

### Metric Builders

Each metric exposes a `MetricKind` and is enabled through a triple of builders
(generated by the internal `metric_builder!` macro):

- `show_{name}()` — enable globally for all files
- `show_{name}_with_filename(globs)` — enable only when filenames match the
  glob list; patterns prefixed with `!` are exclusions
- `show_{name}_highlight_greater_than(threshold)` — enable and render values
  above `threshold` in bold yellow

Available metric names: `file_size`, `tokens`, `created`, `created_since`,
`modified`, `modified_since`, `permissions`, `permissions_numeric`, `owner`,
`group`.

```rust
let mut fs = FileSystem::new_with_formatting(".")?
    .show_file_size_highlight_greater_than(1_000_000)
    .show_tokens_with_filename(vec!["*.rs", "*.md", "!*.lock"])
    .show_modified_since()
    .show_on_directories();
fs.ensure_tree_built();
println!("{}", fs.render(&Terminal::default()));
```

The `MetricKind` enum and `FileMetrics` struct are public so consumers can
inspect collected metadata directly (see [`TreeNode::metrics()`](#tree-inspection)).
`FileMetrics` includes `file_size`, `tokens`, `created`, `modified`, and on
Unix `permissions_mode`, `owner`, `group`.

### Rendering

| Method | Description |
|--------|-------------|
| `.ensure_tree_built()` | Walks the filesystem and populates the tree (must be called before rendering) |
| `.render(&Terminal)` | **Recommended.** Honors detected terminal width, color depth, Nerd Font availability, and TTY styling |
| `.render_optimistic(Option<u32>)` | No terminal context — hardcodes Unicode fallback icons, no ANSI styling; defaults to 80 columns |
| `.display(&Terminal)` | `render()` plus a guaranteed trailing newline |

### Tree Inspection

After `ensure_tree_built()`, the tree is available for inspection. There is
**no aggregate `metrics()` method on `FileSystem`** — instead, walk
`fs.tree()` and pull per-node metadata via `TreeNode::metrics()`.

| Method | Description |
|--------|-------------|
| `fs.root_path()` | Returns `&Path` to the root directory |
| `fs.is_tree_built()` | `true` once `ensure_tree_built()` has populated the tree |
| `fs.tree()` | Returns `Option<&Vec<TreeNode>>` for traversal |
| `fs.get_max_depth()` / `fs.get_max_entries()` | Read back the configured limits |
| `fs.get_icon(node, depth, is_nerd_font)` | Resolve the icon that would be rendered for a node |

```rust
fs.ensure_tree_built();
if let Some(nodes) = fs.tree() {
    let files = nodes.iter().filter(|n| n.is_file()).count();
    for node in nodes {
        if let Some(metrics) = node.metrics() {
            println!("{}: {:?} bytes", node.name(), metrics.file_size);
        }
    }
    println!("top-level files: {files}");
}
```

`TreeNode` is an enum (`Dir { .. }` / `File { .. }`) exposing `name()`,
`is_dir()`, `is_file()`, `is_ignored()`, `is_symlink()`, and `metrics()`.

### Icon Support

Icons use Nerd Fonts by default with Unicode emoji fallback. Selection
priority inside `get_icon()` is: error/depth-limit → file-name match
(README/CLAUDE/SKILL/AGENTS/justfile/.gitignore/.env/.editorconfig) →
extension match (`.rs`, `.ts`, `.js`, `.toml`, `.yaml`/`.yml`, `.json`) →
markdown → base file/dir icon. Special directory icons exist for `.git`,
`.github`, `utils`/`util`, and `docs`/`documentation`.

```rust
use biscuit_terminal::components::filesystem::icons;

// Nerd Font (patched fonts required)
let _ = icons::nerd::ext::RUST;        // 
let _ = icons::nerd::dir::BASE;        // 
let _ = icons::nerd::file::SKILL;      // 
let _ = icons::nerd::dir::DEPTH_LIMIT; // shown when a directory hits `.depth(n)`

// Unicode fallbacks (any terminal)
let _ = icons::unicode::file::BASE;    // 📄
let _ = icons::unicode::dir::BASE;     // 📂
let _ = icons::unicode::file::SYMLINK; // @
```

### Error Handling

`FileSystem::new()` returns `Result<Self, FileSystemError>`. The error enum:

- `PathNotFound { path }` — path does not exist
- `NotADirectory { path }` — path exists but isn't a directory
- `PermissionDenied { path }` — access denied
- `IoError(std::io::Error)` — wraps any I/O failure (`#[from]`)
- `Ignore(ignore::Error)` — wraps gitignore pattern errors (`#[from]`)

## CLI

Exposed via `bt dir`:

```bash
bt dir                          # Current directory (default path = ".")
bt dir src --depth 3            # Limit depth
bt dir . --filter .rs --filter .toml
bt dir . --skip-root            # Hide the root header line

# Metric columns (file-only unless noted)
bt dir . --size                 # show_file_size()
bt dir . --tokens               # show_tokens()
bt dir . --modified             # show_modified()       (absolute mtime)
bt dir . --updated              # show_modified_since() (relative mtime)

# Layout (shared with other bt subcommands)
bt dir . --ml 2 --mr 4 --mt 1 --mb 1 --align center
```

`bt dir` always uses `FileSystem::new_with_formatting()` as the base, so
dotfiles are italicised, gitignored entries are dimmed, and gitignored
directories are not recursed into. Use the programmatic API if you need to
opt out of any of those defaults, set `--max-entries`, enable additional
metrics (permissions, owner/group, created timestamps), highlight patterns,
or generate OSC8 file links.
