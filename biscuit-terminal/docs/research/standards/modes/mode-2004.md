# DEC private mode 2004: bracketed paste

DEC private mode 2004 is an xterm extension, not a mode defined by the original DEC terminal standards. An application enables it with `CSI ? 2004 h` (DECSET) and disables it with `CSI ? 2004 l` (DECRST). While enabled, a terminal's clipboard-paste operation sends `CSI 200 ~`, the pasted bytes, and `CSI 201 ~`. Ordinary typing is unchanged. The receiving program recognizes the delimiters and can insert the whole paste as data, temporarily suppress auto-indent or key bindings, and avoid treating embedded newlines as individually typed Enter keys.

The sequence originated in xterm's 2002 user-contributed readline-related work by Ilya Zakharevich; it was documented and named “bracketed paste” shortly afterward. It spread first through xterm derivatives and later through terminal emulators, shells, editors, and multiplexers. Current implementations span desktop, web, and cross-platform terminals. Adoption continues: newer terminal apps and terminal libraries implement mode 2004 because modern shells, editors, and TUIs commonly request it. It remains informal and behavior details—especially sanitization and status reporting—vary.

## Testing and capability queries

There is no universal, non-invasive capability probe. DECSET 2004 tells the terminal to enter the mode but does not itself return an acknowledgment. A practical behavioral test is to enable the mode, paste a known harmless string into a byte-inspection program such as `cat` piped to a hex dumper, and confirm that the start and end markers surround the paste. Reset the mode afterward. Such a test must be performed in the actual path under test: a multiplexer or remote hop may change behavior even when the outer emulator supports it. Avoid using a live shell prompt for adversarial payload tests.

DECRQM uses `CSI ? 2004 $ p` (often written `CSI ? 2004 $ p`) and, when implemented for this mode, can reply with `CSI ? 2004 ; Ps $ y`. The standard DECRPM status values are `0` not recognized, `1` set, `2` reset, `3` permanently set, and `4` permanently reset. Xterm's control-sequence documentation identifies 2004 as bracketed paste but does not promise DECRQM reporting for every emulator. Implementations differ: some answer `1` or `2`, some return “not recognized,” and others do not reply. A reset reply means only that the mode is currently off; it does not mean unsupported. A set reply is useful evidence that the mode state is tracked, but does not prove that the paste implementation correctly wraps every paste or sanitizes hostile clipboard contents. Treat DECRQM as advisory state inspection, never as a complete security/capability test.

Applications should generally enable mode 2004 for the duration in which they consume interactive input and restore/reset it on every normal exit path. A crash or dropped SSH connection can leave the outer emulator in bracketed-paste mode; later pastes may display `0~` and `1~` or confuse programs that did not request it. Reset the terminal/session, or send `CSI ? 2004 l` at a trusted prompt. Shell integration can detect some disconnects and clear stale state.

## Delimiters, security, and paste data

The end delimiter is ordinary input syntax to the receiving application. If a clipboard payload contains a literal `CSI 201 ~`, a parser may mistake it for the end of the paste; remaining bytes then look like typed input. A pasted payload can also contain C0 controls, newlines, or other escape sequences. Robust terminals filter unsafe controls and remove or transform embedded bracket delimiters before adding their own outer markers. The iTerm2 feature-reporting contract explicitly requires control filtering and neutralization of embedded end markers. VTE filters control characters; Konsole additionally removes ESC bytes. Historical defects in kitty and WezTerm illustrate that a one-pass substring replacement can be bypassed with overlapping/split marker patterns. Keep terminal versions current and test the exact paste path if untrusted clipboard data matters.

Bracketed paste addresses accidental or malicious execution of pasted newlines and avoids interpreting pasted characters as interactive editor/readline shortcuts. It does not make pasted content safe: the application must honor the markers, and users can still submit the resulting buffer. Nor does it prevent every injection path (for example, clipboard access, terminal escape processing outside the bracketed input path, or an app that ignores the delimiters). Terminals that fail to filter embedded terminators can reintroduce the very keystroke-injection risk the feature is meant to reduce. Programs should treat bracketed content as data and terminals should sanitize at the source.

## Multiplexers

Multiplexers sit between the emulator and application, so they must track mode 2004 per pane and relay paste correctly. tmux has supported bracketed-paste mode since 1.7. It tracks the pane's request and wraps a paste when appropriate; older releases and state-leak bugs have produced literal `200~`/`201~` text in panes where the application did not request it. Keep tmux current and ensure the outer terminal and tmux's advertised terminal description agree. Recent tmux also recognizes incoming bracket markers, so partial sequences split across input reads have been a reported edge case.

Zellij consumes host paste events and forwards bracket markers for panes that have enabled the mode, removing them for panes that have not. That path has had reported quirks: removing markers without translating clipboard LF to the CR expected by some legacy applications can alter multiline pastes (notably programs that bind Ctrl-J specially). A reported native-Windows defect reverses lines in multiline bracketed paste in affected releases. For affected apps, update Zellij; as a workaround, use a program that understands bracketed paste or paste through the terminal directly when safe.

GNU screen support is version/build dependent and historically less consistent. Upstream support has lagged or been carried as patches in some distributions; do not infer support from `TERM=screen` or from the outer emulator. Check the installed screen version and exercise paste inside it. If an application receives literal markers or no markers, use a current build with the relevant support, configure a compatible terminal description, or disable bracketed paste in that application while inside screen. Nested multiplexers add another state boundary and should be tested as a stack.

## Terminal application support and notes

The applications below are known to implement DECSET/DECRST 2004 and paste bracketing in at least current or documented releases. Support says nothing about every version, configuration, platform, or multiplexer path. `apps_supporting` lists applications with evidence of mode support, not a promise of identical sanitization or DECRQM replies.

| Terminal                      | Support notes and known quirks                                                                                                                                                                                                                                     |
|-------------------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| WezTerm                       | Supports bracketed paste. A 2024 issue reported that an embedded end marker could terminate a paste; it was marked fixed in nightly builds. Use a current release and avoid assuming old versions sanitize hostile payloads.                                       |
| Ghostty                       | Supports mode 2004. As with other emulators, the mode is controlled by the foreground application; stale state after abrupt disconnects can cause visible marker text.                                                                                             |
| iTerm2                        | Supports DECSET/DECRST and documents filtering C0 controls and embedded end markers. DECRQM may report current reset state. Shell Integration can clear stale bracket mode after detected SSH disconnects; Session > Reset is a manual recovery.                   |
| cmux                          | Supports mode 2004 in its terminal surface. Its automation `send` API can conditionally add markers when `paste:true` and mode 2004 is active; it does not sanitize caller-supplied markers, so API callers must avoid double wrapping and sanitize their payload. |
| kitty                         | Supports bracketed paste. A historical overlapping-marker injection defect was fixed; use a current version. Vim may need explicit `t_BE`, `t_BD`, `t_PS`, and `t_PE` settings because Vim's built-in terminal detection can miss modern terminals.                |
| Konsole                       | Supports mode 2004. It removes ESC bytes from pasted text in this mode, which protects the delimiter but changes pasted control-bearing data.                                                                                                                      |
| Apple Terminal (Terminal.app) | Supports bracketed paste. In ordinary paste mode it translates line endings for legacy applications; inside multiplexers that transformation may differ.                                                                                                           |
| Alacritty                     | Supports mode 2004. Its non-bracketed paste path converts LF to CR for conventional terminal input; a multiplexer that strips markers may not reproduce this behavior.                                                                                             |
| Contour                       | Supports DECSET/DECRST 2004. Check release notes for exact paste sanitization behavior; the mode's existence does not imply DECRQM support.                                                                                                                        |
| foot                          | Supports mode 2004. Paste behavior depends on whether the foreground application has enabled the mode; test through any multiplexer separately.                                                                                                                    |
| GNOME Terminal (VTE)          | VTE-based terminals support bracketed paste and filter control characters. This includes GNOME Terminal and other VTE frontends.                                                                                                                                   |
| xterm                         | Original implementation. Its control-sequence reference defines mode 2004 and the `CSI 200 ~` / `CSI 201 ~` wrappers.                                                                                                                                              |
| urxvt                         | Supports bracketed paste in commonly used builds; verify distribution/version because extensions and patch sets vary.                                                                                                                                              |
| mintty                        | Supports mode 2004; its source implements bracketed paste output.                                                                                                                                                                                                  |
| Windows Terminal              | Supports bracketed paste in current releases. Shell and application handling still determines whether pasted newlines are submitted or buffered.                                                                                                                   |
| VS Code integrated terminal   | Supports bracketed paste through its terminal backend; behavior can also depend on the host platform and shell integration.                                                                                                                                        |
| hterm                         | Supports DECSET/DECRST 2004 and has an automated test for the wrapper behavior.                                                                                                                                                                                    |
| st and derivatives            | Often supported through patches rather than the minimal upstream terminal; check the exact build and patch set.                                                                                                                                                    |

For a developer, the most portable strategy is to rely on the application's existing terminal library or terminfo capability when available, enable the mode only while reading input, and use behavioral fallback rather than treating a missing DECRQM reply as unsupported. Test paste in the real stack—including remote shell and multiplexer—and include multiline text, control characters, and embedded delimiter cases in security testing.
