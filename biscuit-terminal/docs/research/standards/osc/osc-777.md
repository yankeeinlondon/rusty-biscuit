## Overview

OSC 777 is an informal terminal-emulator extension for asking the emulator to show a desktop notification. It is not part of ECMA-48, a standards-track VT specification, or a centrally maintained terminal protocol. Its familiar notification form is:

```text
ESC ] 777 ; notify ; title ; body ST
```

`ESC ]` begins an Operating System Command (OSC), `777` selects the rxvt-unicode extension namespace, and `notify` selects the notification operation. The title and body are plain text fields separated by semicolons. `ST` is String Terminator (`ESC \`); BEL (`0x07`) is also accepted by many implementations. For example, a shell can emit one with `printf '\033]777;notify;Build complete;All tests passed\007'`.

The request travels in the terminal's output stream, so programs can use it without linking a desktop-notification library or knowing whether the local desktop uses D-Bus, macOS Notification Center, or another service. With SSH, the escape can reach the local terminal even though the command runs remotely. Multiplexers and other layers can intercept, filter, or drop it; tmux does not pass arbitrary OSC through by default. Configure and use its explicit passthrough mechanism when needed.

There is no standard query or reply that tells a program whether OSC 777 is supported. `$TERM` does not reliably advertise notification support. A program can send a test notification, but that is an active test: it may create a visible notification, be suppressed, or be ignored. Automated tests should distinguish parser acceptance from user-visible delivery; the latter also depends on OS notification permission, focus policy, desktop configuration, and whether the app was launched in a way that grants access to its notification service.

## What the user sees

OSC 777 does not prescribe a graphic or layout. It requests a notification; the terminal decides whether to pass title and body to native desktop notifications, show an in-app toast, add an unread marker, or suppress it. The OS or desktop environment controls icon, duration, grouping, placement, action buttons, and history. Focus suppression is common. Foot inhibits notifications while focused by default and lets users choose the notification command in `foot.ini`. WezTerm describes its result as a toast. cmux adds a notification panel and workspace unread state. There is no portable promise about click behavior or returning to the originating pane.

## Namespace and origins

OSC 777 came from rxvt-unicode's extension mechanism, rather than a notification-only protocol registry. rxvt-unicode dispatches the text after `777;` to an extension (the common Perl extension form is `extension;parameters`). `notify` is the widely reused command. WezTerm documents only `notify` as supported; other receivers may recognize additional commands, so senders should use only the documented notification form and receivers should not assume every OSC 777 payload is a notification.

The extension is rooted in rxvt-unicode/urxvt; its exact first release is not specified in a normative document. GNOME's VTE/Terminal work was proposed in 2013 and support was added to GNOME Terminal in 2015. Adoption has continued across independent emulators, including WezTerm, Foot, Ghostty, Contour, and cmux. The ecosystem remains fragmented: iTerm2 and Apple Terminal are generally targeted with OSC 9, kitty has the richer OSC 99 protocol (and accepts legacy OSC 777 in current releases), and there is no shared capability negotiation or cross-terminal conformance suite.

## Current application support

Support below means recognition of the `notify` form, not guaranteed alert delivery under every OS configuration.

| Application                | Support and practical notes                                                                                                                                                                                                                                                       |
|----------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| WezTerm                    | Yes. Only the `notify` extension is supported; it produces a toast. BEL and ST terminators are accepted.                                                                                                                                                                          |
| Ghostty                    | Yes. Notifications can be disabled; on Linux launch through the desktop entry/launcher so the desktop environment permits notification delivery. OS permissions and focus behavior apply.                                                                                         |
| cmux                       | Yes. Its guide documents the sequence. Desktop alerts are suppressed when the cmux window or sending workspace is active. An intermittent raw-sequence display bug has been reported; verify receipt on the target version.                                                       |
| kitty                      | Yes, as a compatibility form. Prefer OSC 99 or `kitten notify` for notification IDs, richer metadata, and activation behavior.                                                                                                                                                    |
| Konsole                    | Yes in current support references. KDE also has its own OSC 99 notification protocol; use that where its richer features are needed.                                                                                                                                              |
| Contour                    | Yes; recognizes the urxvt-style `notify;title;message` form.                                                                                                                                                                                                                      |
| Foot                       | Yes. Its manual documents OSC 777 and a configurable notification command. It inhibits alerts while focused by default.                                                                                                                                                           |
| GNOME Terminal (VTE-based) | Not guaranteed in current builds. VTE has a legacy OSC 777 compatibility property, `enable-legacy-osc777`, since VTE 0.78; its library default is false. Only treat a VTE app as supporting OSC 777 if it enables this property and handles the resulting notification termprops. |
| rxvt-unicode (urxvt)       | Yes; originating implementation. Extension availability depends on its notification extension being installed/enabled.                                                                                                                                                            |
| Terminology                | Yes; supports the urxvt-style `notify` command.                                                                                                                                                                                                                                   |
| Warp                       | Yes. Warp documents OSC 9/777 notification hooks; a specially named OSC 777 title may be interpreted as structured agent data.                                                                                                                                                    |

### Similar but different protocols

| Application                   | What to send instead                                                                                                                        |
|-------------------------------|---------------------------------------------------------------------------------------------------------------------------------------------|
| iTerm2                        | OSC 9 (`OSC 9;message`); its documented notification interface is not the rxvt title/body form.                                             |
| Apple Terminal / Terminal.app | Do not count on OSC 777; use an OS-native notification or helper. Some compatibility tables report OSC 9, but verify the installed version. |
| Alacritty                     | No native OSC 777 notification action is documented; use a platform notification API/helper.                                                |
| Windows Terminal              | References conflict on OSC 777 support. Do not assume compatibility without checking the installed release.                                 |

For portability, select a protocol from known terminal identity or user configuration: OSC 777 for documented receivers, OSC 9 for iTerm2-style receivers, and OSC 99 for kitty/Konsole-style rich notifications. Provide a bell or OS-native fallback if delivery matters. The simple OSC 777 format has no universal quoting convention, so semicolons and control characters in text are not safely portable.
