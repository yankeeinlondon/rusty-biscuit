# OSC 5 and OSC 105: special attribute colors

OSC 5 is an xterm-family extension for assigning/querying the color used to render selected text attributes. OSC 105 resets those attribute colors to the terminal's configured defaults. They are separate operations: OSC 5 changes color values; it does not turn an attribute on or off. A program must still emit SGR (for example, SGR 1 for bold) for the color to be visible.

The canonical forms use `ESC ]` as the OSC introducer and either BEL or ST (`ESC \\`) as the terminator:

```text
OSC 5 ; index ; color BEL|ST     set a special color
OSC 5 ; index ; ? BEL|ST         query a special color
OSC 105 ; index BEL|ST           reset one special color
OSC 105 BEL|ST                   reset all special colors
```

The xterm indices are 0 bold, 1 underline, 2 blink, 3 reverse video, and 4 italic. Color values use the terminal's OSC color syntax (commonly X11 names or `rgb:` values; accepted syntax varies by emulator). Multiple index/value pairs may be sent in one OSC 5 sequence. In xterm, special colors also have an OSC 4 alias at `color_count + index` (for example, 256 through 260 in 256-color mode); OSC 5 avoids coupling the request to the active palette size.

An assigned color may not be applied unless the emulator's corresponding special-color mode is enabled. xterm exposes those controls separately through OSC 6/106 and resource settings such as `colorBDMode`; emulator defaults differ. For attributes that are not normally foreground colors, notably reverse video, the visual result is implementation-specific. OSC 105 restores the special colors to terminal resource/theme values; it does not reset the SGR attributes on already printed cells.

## Origin, testing, and adoption

This is an informal xterm extension, not an ECMA-48 or ISO standard. xterm's control-sequence reference documents it alongside OSC 4 palette colors. Its reset form is present in xterm's changelog by patch 301 (January 2014), which fixed resetting individual special-color slots; this establishes adoption by that date, not the original date of invention. A VTE feature request from January 2014 independently identifies xterm as the reference behavior. The extension remains niche: many terminal emulators ignore it, and broad TUI software rarely depends on it. Adoption continues in newer emulators: Ghostty documents OSC 5/105, and Contour's release notes record implementation of both.

It can be probed, but there is no standardized capability bit or universal device-attributes response for it. Send `OSC 5;0;? ST` and look for a color reply, then set a conspicuous test color, print bold text, reset with OSC 105, and visually verify restoration. Queries may be ignored or their replies may use a different but equivalent OSC form: xterm has historically replied to an OSC 5 query using its OSC 4 extended-index form. A timeout with no reply does not prove lack of set/reset support. Use a disposable terminal or restore the value explicitly; do not leave a modified color behind. When testing through tmux, screen, SSH, or another multiplexer, the path may filter sequences or replies, so repeat directly in the emulator before attributing behavior to it.

## Terminal support

The table distinguishes documented/parser-confirmed support from absence in published sequence tables. “Not confirmed” means this research found no first-party evidence; it is not a claim that every version silently ignores the sequence. Terminal implementations change, so check the linked upstream reference when targeting a specific release.

| Terminal             | Status                             | Notes                                                                                                                                                                                                                 |
|----------------------|------------------------------------|-----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Ghostty              | Supported                          | Its VT reference documents querying/changing OSC 5 special colors and OSC 105 reset. Support landed after reports in 2025 noted the earlier missing parser support; older builds may not implement it.                |
| cmux                 | Supported through libghostty       | cmux uses libghostty as its terminal rendering engine, so its OSC behavior follows the bundled libghostty version. Verify the cmux/libghostty release; older engine versions can lack later OSC additions.            |
| Contour              | Supported                          | Release notes explicitly add OSC 5 and OSC 105, special-color queries, and X11 color parsing.                                                                                                                         |
| GNOME Terminal (VTE) | Supported                          | VTE's OSC 5 feature was resolved fixed; GNOME Terminal inherits the VTE parser. Frontends may expose configurable bold colors differently, and VTE historically rendered bold color while retaining bold font weight. |
| xterm                | Supported                          | Reference implementation; supports set/query and reset, with resource-dependent defaults and optional color modes.                                                                                                    |
| WezTerm              | Not confirmed / documented ignored | Its current escape-sequence table marks OSC 5 ignored and lists no OSC 105 entry. Use ordinary SGR/palette colors where portability matters.                                                                          |
| iTerm2               | Not confirmed                      | Its published escape-code reference does not document OSC 5/105. Do not infer support from its broad OSC 4 or true-color handling.                                                                                    |
| kitty                | Not confirmed                      | Its published protocol documentation does not list OSC 5/105. Use application-controlled SGR colors instead.                                                                                                          |
| Konsole              | Not confirmed                      | No first-party OSC 5/105 support statement was found. Its support for OSC 4/104 does not imply the special-color family.                                                                                              |
| Apple Terminal       | Not confirmed                      | No first-party OSC 5/105 support statement was found. Treat both sequences as unavailable for cross-terminal applications.                                                                                            |
| Alacritty            | Not confirmed                      | No first-party OSC 5/105 support statement was found in its published protocol references.                                                                                                                            |
| Foot                 | Not confirmed                      | No first-party OSC 5/105 support statement was found in its sequence documentation.                                                                                                                                   |
| Tera Term            | Supported                          | Its control-sequence manual documents OSC 5 special colors and OSC 105 reset; its documented slot set may differ from modern xterm's five-slot extension.                                                             |

For portable output, avoid relying on special attribute colors as a semantic requirement. Prefer explicit SGR foreground/background styling, and use OSC 5 only as an optional enhancement with a graceful fallback. Reset colors with OSC 105 when supported, and separately restore any changed SGR state.
