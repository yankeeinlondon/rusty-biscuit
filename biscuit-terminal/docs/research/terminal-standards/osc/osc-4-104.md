## Overview

OSC 4 and OSC 104 are xterm-family Operating System Command (OSC) extensions for the indexed color palette. OSC 4 changes or queries a palette slot; OSC 104 restores one or more slots to their terminal-defined defaults. They are informal conventions rather than controls specified by ECMA-48, and behavior varies by emulator and version.

An OSC begins with `ESC ]` and ends with BEL (`\x07`) or String Terminator (`ESC \`). OSC 4 uses index/specification pairs:

```text
ESC ] 4 ; index ; color ST       set a slot
ESC ] 4 ; index ; ? ST           query a slot; terminal replies with OSC 4
ESC ] 104 [ ; index ... ] ST     reset listed slots, or all slots if omitted
```

The index normally addresses the 256-color palette: 0–7 standard colors, 8–15 bright colors, 16–231 the 6×6×6 color cube, and 232–255 grayscale. Xterm-derived implementations generally accept color specifications such as `#RRGGBB` and `rgb:RR/GG/BB`; some accept other X color forms. Multiple index/color pairs can be carried in one OSC 4 request, and OSC 104 implementations commonly accept multiple indices. A query response is a color specification, often `rgb:rrrr/gggg/bbbb`; the returned encoding and precision may differ from the input because the emulator can quantize or normalize the color.

A minimal example sets palette slot 1, queries it, then restores it:

```sh
printf '\033]4;1;#ff0000\a'
printf '\033]4;1;?\a'
printf '\033]104;1\a'
```

Use OSC 104 with no index to restore the entire palette. Applications that temporarily change colors should restore them when finished, including on normal shutdown; they should not assume the terminal supports reset merely because it accepts a set operation.

## What users see

These sequences do not print a swatch or draw a palette. OSC 4 changes the color used whenever subsequent text uses that indexed SGR color, affecting existing cells only if an emulator dynamically recolors them; implementations commonly apply the changed palette to rendering. The result is visible in colored text, backgrounds, and applications that use indexed colors. OSC 104 makes affected indexed colors revert to the terminal's current configured palette. Neither sequence changes the terminal's default foreground/background (OSC 10/11) or arbitrary RGB colors emitted directly with true color.

The result depends on the terminal's configured theme and implementation. The same color index can have different defaults in different themes, and a terminal can normalize a requested color. Some environments expose the change only in the pane content; others may also use palette colors in terminal chrome or auxiliary UI. Applications should not rely on changes propagating to tab bars or other non-cell UI.

## Detection and testing

There is no portable capability bit or widely implemented query that safely answers whether both operations work. OSC 4 query is the practical probe: send `OSC 4;index;?`, wait with a bounded timeout for the matching OSC reply, and parse the returned index and color. A missing reply is inconclusive: a multiplexer may filter replies, a remote connection may delay them, or the terminal may support setting but not querying. Query responses can also be transformed. Do not probe by changing a user's palette unless the original color is captured and reliably restored.

For an end-to-end visual test, set a conspicuous unused palette index, print a cell using that index, inspect the rendered color, and reset it. Automated tests should distinguish parser acceptance from a real emulator rendering the updated palette: headless VT parsers may recognize the sequence without possessing a display palette. Test BEL and ST termination only when those variants matter to the application, and account for tmux/screen forwarding and SSH paths.

## History and adoption

These operations originated in xterm's terminal-control extensions; the xterm control-sequence reference documents changing/querying ANSI color numbers and resetting them. They are not a formal cross-vendor standard, and there is no central conformance or version-negotiation mechanism. Adoption has broadened across modern graphical emulators and terminal libraries because indexed-color themes and runtime theme switching are common. Recent work in terminal emulators continues to improve compatibility, including multi-pair parsing and reset behavior, but support is not universal and can differ between OSC 4 set/query and OSC 104 reset.

### Developer guidance

- Treat set, query, and reset as separate capabilities. A query timeout does not prove set is unsupported, and support claims for a parser crate do not prove the GUI terminal updates visible cells.
- Use a short query timeout and restore any changed indices. If reliable cleanup cannot be guaranteed, avoid changing the user's palette.
- Prefer one index/color pair per request when targeting a broad range of versions. Multi-pair handling has had compatibility bugs even where single-pair OSC 4 works.
- Use BEL or ST termination according to the tested target set; xterm-derived terminals commonly accept both, but forwarding layers can alter or reject sequences.
- Do not assume all 256 indices are mutable, that the emulator returns the exact requested value, or that a theme reload and OSC override have the same precedence across apps.
