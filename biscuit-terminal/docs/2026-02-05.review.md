# Biscuit Terminal Components Review (2026-02-05)

## Scope

- Reviewed components in `biscuit-terminal/lib/src/components/` with emphasis on ergonomics, Renderable consistency, performance, and comment accuracy.

## Strengths

- Solid test coverage in many components (lists, table formatting, mermaid cache).
- Clear separation between rendering primitives (layout, styling) and higher level components.
- Mermaid caching is thoughtfully keyed on render parameters and version.

## Findings

### Ergonomics

- Compose is not Renderable and has no render method, which makes it hard to use as a real composition container. Consider implementing Renderable and adding a `render` path that joins parts with layout support. Also `add_*` methods return `&Self` while taking `&mut self`, so chaining does not work. Suggest returning `&mut Self` or switching to `self -> Self`. File: `biscuit-terminal/lib/src/components/compose.rs`.
    - DECISION: Make `Compose` implement `Renderable` and add `add_*` methods to build up what Compose contains.
- TextBlock builder-style methods also return `&Self` while requiring `&mut self`, which prevents chaining in practice. Prefer returning `&mut Self` or consuming `self`. File: `biscuit-terminal/lib/src/components/text_block.rs`.
    - DECISION: implement suggestion
- BlockQuote exposes `text_color`, `bg_color`, and `left_block_color` setters, but the colors are never applied. This is a functional gap for callers who set these options. File: `biscuit-terminal/lib/src/components/block_quote.rs`.
    - DECISION: implement the color handling for this struct's rendering functions but with no-color fallback when the terminal does not support color
- Section and list types require callers to manually wrap with `RenderableContent` to mix strings and components. Consider `add_item<T: Into<RenderableContent>>` or `push` convenience methods to reduce boilerplate. Files: `biscuit-terminal/lib/src/components/section.rs`, `biscuit-terminal/lib/src/components/list.rs`.
    - DECISION: implement suggestion

### Renderable Consistency

- `Renderable::render` is documented as an opportunistic, terminal-agnostic render. Several components call `Terminal::new()` or `Terminal::new_tty()` inside `render`, which makes output depend on the environment and blurs the distinction between `render` and `fallback_render`. Files: `biscuit-terminal/lib/src/components/text_block.rs`, `biscuit-terminal/lib/src/components/todo.rs`, `biscuit-terminal/lib/src/components/block_quote.rs`.
    - DECISION:
        - we need to create a method off of `Terminal` called `new_optimistic(width: u32)` which sets the terminal to:
            - supports OSC8
            - supports TrueColor depth
            - supports italic and all forms of underline
            - no support for multiplexing
            - is a TTY terminal
            - calls to width() resolve statically to whatever `width` was when instantiated.
                - NOTE: we may need a function implementation `set_fixed_width(width: u32)` to address this need as well as some related ones.
        - all `Renderable::render` methods should use `new_optimistic(width)`

- TerminalImage does not return any string from `render` or `fallback_render`; it only prints via viuer and returns empty output. This breaks composition (lists/sections silently drop images) and contradicts Renderable expectations. Consider returning a proper escape sequence (Kitty/iTerm2) or at least an alt-text fallback from `render` and `fallback_render`, while keeping explicit side-effect printing in `render_with_options` or a dedicated method. File: `biscuit-terminal/lib/src/components/terminal_image.rs`.
    - DECISION:
          - TerminalImage's render() should always return a escape sequence for the image rather than rendering to the terminal directly
          - TerminalImage's fallback_render() should ideally do the same but i'm a bit uncertain of the tradeoffs so it may be safer to do this as a second pass.
          - There's a section at the end called `Example Image Rendering` which offers a starting point for how this may be handled


- Block-level child rendering in lists is width-constrained in `render` but not in `fallback_render` (uses full terminal width). This can cause overflow when nested in narrow layouts. Consider passing a cloned `Terminal` with `fixed_width` (as done in TwoColumn) or using `render(Some(child_width))` consistently. File: `biscuit-terminal/lib/src/components/list.rs`.
    - DECISION
        - For both render() and fallback_render() the constraints should only require that we:
            - set a fixed width for the terminal
            - the `Layout`'s left and right margins will then impose the constraints on the renderable page (not the Terminal's width)

### Performance (without changing ergonomics)

- Prose block tag parsing is O(n^2) due to repeated `ends_with(format!(...))` checks on the growing buffer. This can be optimized by using index-based scanning or a tag stack to avoid repeated string allocations and suffix scans. File: `biscuit-terminal/lib/src/components/prose.rs`.
      - DECISION: implement this change
- Atomic token matching allocates on every token via `to_lowercase()`. Consider `eq_ignore_ascii_case` or an ASCII-only normalization step to avoid per-token allocations. File: `biscuit-terminal/lib/src/components/prose.rs`.
      - DECISION: implement this change
- Mermaid cache key generation builds a large formatted string. Hashing incrementally (e.g., via a hasher that feeds each field) would avoid a large allocation and extra copies, even if diagram size is capped. File: `biscuit-terminal/lib/src/components/mermaid_cache.rs`.
      - DECISION: implement the suggested change
- TerminalImage width/margin calculations are duplicated in several methods (`render_inline`, `render_via_viuer`, `build_viuer_config`, `render_as_kitty`, `render_as_iterm2`). A shared helper would reduce repeated work and help keep behavior consistent. File: `biscuit-terminal/lib/src/components/terminal_image.rs`.
      - DECISION: implement this suggestion

### Comments and Doc Accuracy

- ColumnType docs say integer alignment defaults to Right, but implementation defaults to Center. Either change the comment or the behavior. File: `biscuit-terminal/lib/src/components/table/types.rs`.
    - DECISION: switch integer types back to using Right justification
- TerminalImage `render_to_terminal` doc claims it returns a plain-text fallback, but it currently returns an empty string on unsupported terminals. `render` is documented as optimistic but also returns empty output. These comments should be updated or behavior fixed. File: `biscuit-terminal/lib/src/components/terminal_image.rs`.
    - DECISION: Behavior will be updated (see above)
- `render_kitty_cells` docs mention width/height in pixels, but the parameters are cell counts. The comment is misleading. File: `biscuit-terminal/lib/src/components/terminal_image.rs`.
    - DECISION: Use more appropriate language to avoid this confustion
- TextBlock has multiple public methods and fields that are not documented, and the `to_terminal` comment is truncated. The crate guideline says public symbols should have `///` docs, so TextBlock and Todo should be brought into compliance. Files: `biscuit-terminal/lib/src/components/text_block.rs`, `biscuit-terminal/lib/src/components/todo.rs`.
    - DECISION: make sure all public methods are documented and `to_terminal` comment is completed
- BlockQuote color fields are documented but unused (comment implies effect that does not exist). Either implement styling or update comments. File: `biscuit-terminal/lib/src/components/block_quote.rs`.
    - DECISION: implement the color handling based on the existing color fields
- `biscuit-terminal/lib/src/components/metrics.rs` is empty and not referenced from `mod.rs`. If it is intended as a module, add a module doc and export it; otherwise remove the file to avoid confusion.
    - DECISION: remove for now

### Correctness and Consistency Issues

- Prose documents `<rgb 125,67,45>` block tags, but `parse_opening_tag` does not emit an attribute usable by the `rgb` handler (it looks for an empty key). This likely means the documented form does not work. Either update the parser or change the documentation to a supported syntax. File: `biscuit-terminal/lib/src/components/prose.rs`.
    - DECISION: we need to make sure the `<rgb x,y,z>...</rgb>` tag is parsable and emits the appropriate escape codes to the terminal
- BlockQuote calculates `_child_width` but never uses it, so child components do not get width reduction for the left border. This is likely a bug for nested components. File: `biscuit-terminal/lib/src/components/block_quote.rs`.
    - DECISION: BlockQuote should use left and right margin adjustments to adjust size not a "width"
- Todo fallbacks include colored glyphs even when `is_nerd_font` is false, but there is no color capability check. If `TermColor` already handles detection, consider documenting that; otherwise consider a no-color fallback for non-color terminals. File: `biscuit-terminal/lib/src/components/todo.rs`.
    - DECISION: add a no-color fallback for non-color terminals
- Mermaid rendering uses `to_str().unwrap()` on temp paths in non-test code, which can panic on non-UTF8 paths (and violates the repo guideline of avoiding unwrap in production). Consider graceful error handling. File: `biscuit-terminal/lib/src/components/mermaid.rs`.
    - DECISION: Add graceful error handling
