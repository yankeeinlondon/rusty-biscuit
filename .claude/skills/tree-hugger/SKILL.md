## Purpose

Tree Hugger provides Tree-sitter-based symbol extraction and diagnostics across 16 programming languages. Use this skill when:

- Working in `tree-hugger/lib/` or `tree-hugger/cli/`
- Extracting functions, types, imports, or exports from source files
- Implementing or debugging lint diagnostics
- Adding support for new languages or fixing query issues
- Understanding the query vendoring system

## Quick Reference

### Supported Languages

Rust, TypeScript, JavaScript, Go, Python, Java, C#, C, C++, Swift, Scala, PHP, Perl, Bash, Zsh, Lua

### Changed-file declaration selection

```bash
hug functions --changed
hug symbols --changed=main
hug symbols --changed --file 'src/**'
hug --json-full symbols --changed
```

Bare `--changed` uses HEAD for uncommitted-only selection; `=main` adds
local main-tip vs HEAD-tip differences, never merge-base or fetch. It
reports whole files' current on-disk content, even when staging and working
edits cancel. Git-reported regular-file/symlink replacements also select the
current file; default walks still exclude symlinks, while explicit selectors
retain their normal symlink resolution. Keep `ChangedRequest::Omitted` distinct from explicit HEAD:
only omission tolerates unborn HEAD without resolving a base.

`cli/src/changed.rs` discovers from the invocation directory through sniff,
uses the active worktree root, drops absent candidates, and matches native
`file_identity` values. `main.rs` validates Git before ordinary file
selection, intersects before analysis/cache lookup, and treats only
`NoSourceFiles` as empty under this flag. Never feed Git paths into explicit
selectors: package scope, ignores, fixtures, forced language and exclusions
must retain their ordinary behavior. Explicit files outside a package must
still belong to the active checkout; guard each changed candidate alias hop and
resolved ancestor against external roots and nested `.git` files/directories
before inserting its canonical identity. Inspect traversal components before
`..` cancels visited directories; resolve aliases before applying subsequent
parents. Ordinary same-checkout parents remain eligible, while an alias through
`inner/../clean.rs` cannot hide a nested marker. Do not discover a second repository
or scan submodules; ownership I/O failures are errors, not empty reports.

Empty selections succeed in every format (text `(no symbols)`, classes
terminal/plain outlines empty; no JSON Lines; count 0; empty files/indexes and errors in JSON). Invalid Git state and conflicts anywhere fail before any
report, with exit 1. Truncated indexes produce repository/index context and empty
stdout before source/cache analysis; absent and valid empty indexes remain allowed.
`changed::index_corruption` checks every prefix on main and linked administrative
indexes across commands, base variants, and report modes. Syntax errors and `--prelude` conflicts exit 2.
Changed flags/references never enter cache keys. The L1 tests in the
`changed` target (`tests/changed/main.rs` declares each module) cover CLI
selection, errors, empty output, public help and repeated warm cache hits;
use `just test --test changed`. User-facing details and the flow diagram
live in [Symbol Reports](../../../tree-hugger/docs/symbol-reports.md#changed-files).

### Package identity for reports

For package reporting, sniff exposes `detect_repo_structure_or_root_package`,
`PackageNameSource`, and `PackageOwnershipLookup`. Capture one structure catalog
and borrowing lookup; check the deepest owner's `name_source == Manifest`
before treating its display name as declared identity. Root `relative` is empty
(render it as `.`). Use `GitRepo::discover(...).repo_root()` for the active
worktree root, with the scan root outside Git.

`cli/src/grouping.rs::Catalog::capture` runs only for `ReportFormat::Stats`,
before prelude/source analysis and any output. Errors exit 1 with catalog/root
context and repair guidance; absence succeeds. `declarations::tally` creates a
group from each selected native analysis path before settling its result, then
adds selected records to both overall and group counters (classes: containers).
Synthetic export ownership uses the prelude analysis path, never the target
`source.file_path`. `Grouping::finish` sorts by portable relative path then name,
Unassigned last; groups use native directory keys and stay outside cache entries.
`stats::write_json` emits `package_root_dir` before overall `stats`, then
`groups` before final `errors` at report version 1. One `as_json` projection
keeps overall/group shapes identical; a null package is Unassigned. Terminal
`write_grouped_terminal` prints All selected declarations then sorted
`name (path)` sections and Unassigned, reusing the existing tables. Headings
use `render::literal` with Prose and no wrapping; plain strips escapes.
The discovery path frame is independent of scan `root_dir`, and empty reports
still include it. Output goldens intentionally include the new sections and
fields; their JSON normalizer redacts both absolute roots. Targeted L1 coverage: `just test grouping
--test-threads 4`, including bin unit tests and `symbols::grouping_core`.
`symbols::grouping_acceptance` exercises normal CLI membership (Cargo/npm),
shipped lib/CLI manifests, linked-worktree roots, external explicit files,
filters, partial failures, cross-package prelude exports, and warm manifest
renames with unchanged cache bytes and zero parse work. Its shared assertion
checks all grouped counters and ratios against overall stats. Alias cases use
forced-language positional explicit files; outside-root cases use `--file`.
Native Windows spelling coverage is cfg(windows); filesystem non-UTF-8
coverage is cfg(target_os = "linux") because APFS rejects those filenames.
These remain L1 in the declared symbols target, not terminal tests.

User-facing package stats guidance lives in the
[CLI README](../../../tree-hugger/cli/README.md#package-stats) and
[Symbol Reports](../../../tree-hugger/docs/symbol-reports.md#--stats).
The topic's flow distinguishes file-level group initialization (including
failed/zero-match files) from declaration-level counting. The
[release notes](../../../tree-hugger/docs/release-notes.md#automatic-package-sections-in-stats)
show the intentional before/after terminal change; additive envelope fields
retain report version 1 independently of symbol-record schema versions.

### Library API (`TreeFile`)

```rust
let file = TreeFile::new("src/lib.rs")?;
file.source();              // Source text of the parsed file
file.comment_ranges()?;     // Byte ranges of comment nodes
file.symbols()?;            // All symbols
file.symbol_records()?;     // v2 parse records
file.symbol_index_v2()?;    // complete index: every pass, diagnostics included
file.query(&SymbolQuery::new().kinds([..]).capabilities([..]))?; // selective
file.query(&SymbolQuery::new().scopes([..]).name(NamePattern::new("parse")).scan_root("."))?; // filtered, prefixed
// Capability::Flags -> is_test/is_deprecated; Capability::Metrics -> metrics facet
SourceFile::read(path)?.query(&query)?; // read+hash once, parse on demand
file.imported_symbols()?;   // Imports
file.exported_symbols()?;   // Exports
file.local_symbols()?;      // Local definitions
file.referenced_symbols()?; // Identifier usages
file.reference_evidence()?; // Occurrences (owner, Call/Usage, Scoped/NameOnly/Unresolved) + region coverage
file.lint_diagnostics();            // Pattern lint rules (with metadata)
file.syntax_diagnostics();          // Parse errors
file.dead_code();                   // Unreachable code blocks
file.experimental_semantics = true; // Enable experimental semantic rules
```

### SymbolKind Enum

Function, Method, Constructor, Type, TypeAlias, Class, Interface, Enum, EnumVariant, Trait, Module, Namespace, Variable, Parameter, Field, Property, Macro, Constant, Unknown

Kinds, containers, visibility and both `static` flags are decided once, at
extraction, from each symbol's declaration node (`file/extract/`:
`classify.rs`, `declaration.rs`, `rust_impl.rs`, per-language `visibility/`
and `static_flags/` readers behind one dispatcher each); there is no
post-conversion kind override. Bump `EXTRACTOR_REVISION` with any change to
extracted records, including repairs on an unreleased branch. See [Query System](./query-system.md#capture-to-symbolkind-mapping).

**Keyword and display header** (`file/extract/header/`): `identity.keyword` is read from one anonymous grammar token per `(language, declaration kind)` table entry in `header/keyword.rs`, never from text; add an entry only for a declaration kind the extractor actually captures (`symbols_header::less_common_declarations_report_their_keyword` pins the non-fixture ones). `source.signature_text` is cut from `declaration_text` at node boundaries only (body, `value`/`accessors`/… fields, first `=`/`:=` in declarator children, terminator), and is `None` when the cut range would not contain the captured name. `symbols_header` holds `KEYWORD_MATRIX` and `SIGNATURE_MATRIX`; the coverage guard requires a keyword row per language and a signature row (case, `NotApplicable` or `Unsupported`) for every `Shape`.

Access lives on `SymbolInfo::visibility` (`None` = Unknown), not on the signature; `is_static` (member without an instance) and `is_static_storage` (storage/linkage `static`) are separate flags. The v1↔v2 adapter round-trips all of them plus `container_kind`; see [API Reference](./api-reference.md#symbolinfo). It does not round-trip `TypeMetadata::type_parameters` (no `TypeData` slot) or a `TypeAlias`'s field metadata (C `typedef struct {…} Alias`; `TypeAliasData` holds only the aliased type); `symbols_adapter::every_fixture_symbol_round_trips_through_the_record` pins both.

- **Selective analysis** (`analysis/mod.rs`, `file/query.rs`, `file/source_file.rs`, `file/tree_file/definitions.rs`): one planner serves `symbol_index_with_passes`, `symbol_index_v2` (= `SymbolQuery::complete_index()`) and `query`; passes run once after prerequisites (parse → bind → semantic; parse → docs; parse → diagnostics) and `completed_passes` lists only what ran. `Capability::Containment` links parents/members without the reference query. `TreeFile::definitions(&MetadataSelection)` runs the locals query **once** per analysis; records, exports, references and semantic lint all take that result (`*_from` methods) — never call `symbols()`/`exported_symbols()` inside the pipeline. De-duplication happens before metadata: the winner supplies each field, later equal-priority captures only fill what it lacks (while no signature is known, a later capture's signature, visibility and `static` flags replace the current ones together). Unselected kinds stay light (name, kind, span, container) and are bound, then dropped; selecting a type kind also selects Field/Property/Constant. Reference edges come from the occurrences (`bind_references`: only `Scoped` occurrences with an owner; an in-file target ID → `references` + the target's `referenced_by`; a bound import (`ResolvedOccurrences::bound_imports`, aligned with the sorted occurrences) → `references` + `dependencies`; `NameOnly`/`Unresolved`/ownerless make no edge, so limited languages have no edges); `NameIndex` serves containment only: `resolve_containers` (`smallest_enclosing`, then `find_container_by_identity`) takes the smallest enclosing same-named record, else the record of `container_kind` whose in-file qualified name qualifies the member's (nearest preceding on ties, Lua repeated `local M`), else the only one whose qualified name agrees with the member's owner path (`agrees_with_owner_path`: a sole local `W` never owns `other::W::probe`; nearest-preceding among equal qualified names only where one owner repeats, `repeats_one_owner`: Lua tables, C++ forward declarations; two Go types of one name own nothing; Rust impl and Swift extension members never reach this rule under Containment: `link_relations` pre-links them from the impl's resolved self type / the extension's `extension_owners` decision, textual container with no ID when unproved; `resolve_container_kind` applies the same rule to `SameFileType`/`SameFileTable` kinds, except a Rust impl member, whose kind is its impl's resolved self type from `relations::impl_self_types` and absent when unresolved), else none — never the first of a repeated name (`symbols_owner_identity` is the row table, `ABSENT_OWNER_MATRIX` the absent-owner rows, `NESTED_SHADOW_MATRIX` the Swift closure-shadow rows, `UNPROVED_OWNER_MATRIX` the Swift unproved-owner rows (duplicate/alias/import/external owners: no conformance, textual container, no membership), both also fed into `declaration_fact_sources`); `RefSet` dedupes resolved refs by ID and unresolved ones by name + qualified name. `semantic_pass` (functions, methods, constructors) reads `is_recursive` from `index.occurrences`/`reference_coverage`/`imports` only, with each occurrence's `import_span` selecting exactly its bound import (never owner/file-wide name membership), so a cache widening from stored occurrences equals a fresh run (`direct_recursion`, `may_call_itself`). `Capability::Occurrences` (between References and Semantics; Semantics requires it) keeps the evidence; References alone resolves it and drops it in `run_query`; `coverage::record_passes_suffice` widens Semantics without a parse only from stored Occurrences. `work_counters()` (atomics, incl. `reference_captures`, `occurrence_resolutions`) proves skipped work in tests; `symbols_query` is the L1 file to extend, `symbols_reference_summaries` for edges, recursion (`RECURSION_MATRIX`) and whole-file evidence.
- **Reference occurrences** (`analysis/occurrences.rs`, `analysis/scope/{mod,rust,ecma}.rs`, user contract `tree-hugger/docs/references.md`): `run_query` fills `FileSymbolIndex::{occurrences, reference_coverage}` (types in `shared/schema_v2/occurrences.rs`, `skip_serializing_if` empty) under `Capability::Occurrences`; `TreeFile::reference_evidence()` is an `Occurrences` query selecting no kinds. With References it runs `definitions_with_scopes` (the one locals run, also returning `@local.scope` nodes), `imported_symbols`, `reference_captures` (the one references run, shared with diagnostics through `references_from_captures`), builds `OccurrenceSyntax` from the definitions' nodes **before** `records_from` consumes them (records align 1:1 with definitions, so index = record), then `resolve(&index.symbols)` before unselected records are dropped. The cache entry stores both lists (required keys; non-empty only under `occurrences`). `LanguageRules::for_language` resolves only Rust and TS/JS (`Ecma { typed }`); other languages get `NameOnly`/`Unresolved` over every same-named record and every region `Limited(unsupported_language)`; their declaration tokens are excluded before candidate selection by `analysis/declaration_names.rs::declaration_names` (called from `Walk::run` per node for a rule-less language, `Walk::declarations` joins `Resolver::excluded_names`): one grammar-shape inventory per language (fields and node kinds, Scala's own varid rule for pattern binders), never dependent on which declarations became records, never adding records, candidates or bindings (the wildcard `_` is dropped in every rule set where it names nothing, Rust/Go/Swift/Scala, `occurrences::is_wildcard`; rows `R5-F2.S20`); a declared name written as a path (`DECLARED_PATH_KINDS`: package/module/namespace paths, a Swift whole-module import path) contributes every segment, and a C++ `qualified_identifier` type name only its last, through `declared_name_tokens`, which both this inventory (in `Resolver::new`) and every record name (`tree_file::definition_ranges`, so TS/JS and Rust too: a TS `namespace A.B` prefix is never bound to a class `A`) go through (rows `R7-F2.nn`/`.Sn`, `typescript_namespace_prefixes_never_bind_to_a_same_named_class`, CLI `refs::unreported_and_compound_declaration_names_are_never_references`); it also owns the Python/Scala pattern readers (`python_targets`, `python_captures`, `scala_pattern_names`) the relation tree's `lexical.rs` shares (`symbols_occurrences::DECLARATION_EXCLUSION_MATRIX`, rows `R5-F2.nn`/`.Sn`; `symbols_cache::unreported_declaration_tokens_stay_excluded_through_the_cache`; CLI `refs::unreported_declaration_tokens_are_never_suggestions`). Contextual syntax markers are excluded the same way, in the same walk, by `analysis/syntax_markers.rs::syntax_markers` (`Walk::markers`, also joined into `excluded_names`; not declarations, so not in that inventory): by grammar role, narrowed to the one spelling the language reserves in a slot that also holds names — Java bare `var` in the inferred-type slots (local, enhanced `for`, resource, explicitly typed lambda parameter, record pattern component; Java 10+ reserves the type name; a file declaring or ordinary single-type importing a type `var` is legacy source, so `SyntaxMarkers::nodes` keeps none of its `var` markers (`java_declared_type_name`; a `static` import names fields/methods too and is never evidence, nor is an on-demand import or a `var` qualifier, rows `R7-F1.nn`); legacy `var` types elsewhere stay reads), the Lua `attribute` identifier (`<const>`/`<close>`), PHP `self`/`static`/`parent` (case-insensitive) as a `named_type`, `new` or `instanceof` operand, C# `global` as an `alias_qualified_name` alias (`global::X`; an extern alias reads), Swift compiler-configuration identifiers (`swift_markers`: a `precedence_group_attribute`'s directive and an `associativity` value, `higherThan`/`lowerThan` values and an operator's group staying reads; a `deprecated_operator_declaration_body`; `availability_condition` platforms; a one-segment attribute name spelled as a Swift 5.10 built-in (`SWIFT_BUILTIN_ATTRIBUTES`, or `_`-prefixed; `Sendable`/`MainActor` stay reads), every argument of `SWIFT_MARKER_ARGUMENTS` (`available`/`objc`/`convention`/`inline`/`exclusivity`) and any attribute argument label (rows `R7-F1.S6`); `directive` (`#if`) operands), named-argument and tuple labels (`argument_label`: Python `keyword_argument` name, C# `argument` name and `attribute_argument` `x:` label, PHP `argument` name, Swift `value_argument_label`, Scala `assignment_expression` directly in `arguments` (parenthesized stays an assignment), Perl bareword before `fat_comma`, Go key in a `struct_type` composite literal only; `swift_element_labels`: tuple expression/type `name` fields and `x: pattern` labels; rows `R7-F1.S5.*`), and the leading `-`/`+` options of a shell `declaration_command` through `--` (`symbols_occurrences::MARKER_EXCLUSION_MATRIX`, rows `R6-F3.nn`/`.Sn`; `symbols_cache::contextual_syntax_markers_stay_excluded_through_the_cache`; CLI `refs::contextual_syntax_markers_are_never_suggestions`). The shell inventory takes a `declaration_command`'s operands after those options (`syntax_markers::shell_option_count`: `local x`, `typeset +x y`, `declare -f g`, zsh `integer i`; only `local x=1` is a record, so a bare operand is excluded without one; rows `R6-F3.X2.nn`, Bash and Zsh as parity). The diagnostics references (`TreeFile::referenced_symbol`) use neither inventory; both they and the rule-less occurrences share the older `is_definition_like_reference` filter, whose `is_named_definition_node` reads name fields only (never `value`: a bare initializer `int k = xs;` is a read) and which excludes a TS/JS parameter's pattern but not its `value` default (`symbols_occurrences::INITIALIZER_READ_MATRIX`, rows `R6-F3.X1.nn`, one per language; `tree_file::initializer_and_default_values_are_referenced_symbols`; CLI `refs::bare_initializers_are_suggestions_and_shell_declaration_operands_are_not`). One cursor walk (`Walk::run`) collects anonymous callables, owner-absent initializer regions (Rust `const`/`static` in a fn, TS field initializers and static blocks), coverage reasons, parse errors, extra scopes (`extra_scope`: Rust inline `mod` body, trait, generic items, `const`/`static`; TS generators, classes, signatures, `switch_body`, a `with` body), binding sites (`binding_sites`: the truth for bindings (TS statement/specifier anonymous `type` modifiers put each affected import in TYPE only, noncallable; default/namespace/require aliases follow the statement modifier, ordinary exported `type` names stay ordinary imports; value-category `typeof F` and local function F remain independent), including names the locals query never reports — `for`/`catch`/destructured/generic params and a TS/JS named function/generator/class expression's own name, which `ScopeTree::names_itself` keeps inside the expression; bound `Scoped` with no ID; every site name is excluded from the occurrences) Rust globs and `Dynamic` name sources (`LanguageRules::dynamic`: a `with` body, the function around a direct `eval` (`ecma::is_direct_eval`, shared with coverage: an ordinary call with an argument list whose `invoked_operand` is `eval`; an optional `eval?.()` is indirect (coverage `indirect_dispatch` only) and a tagged ``eval`…` `` evaluates nothing, so neither binds; `EVAL_CALL_FORMS` is the row table), never the root; marked as globs, also in the relation tree, whose `scope_role` makes a `with` body a lexical scope). Records the walk did not find bind by kind (`record_rule`). A Rust pattern name is never decided by spelling: `mut`/`ref`/`x @` bind; a bare one (`BindingSite::bare_pattern` with its `Refutability`, in every pattern position, struct field shorthands included, captured as `@reference.pattern`) is placed after every other binding by `bare_pattern_meaning` (VALUE lookup where it is written: a `pattern_constant` binding (`const`, unit struct, `const` generic) → a read, a usage; a function, local or nothing → binds; an import or glob first → `BindingTarget::Unknown` in a refutable pattern (the token and every use uncertain), a binding in an irrefutable one; `None`/`Self` read), `place_sites` (established sites, then bare ones in walk order) is shared with extraction: `definitions.rs::drop_non_declarations` drops every capture that declares nothing before records exist — false captures (`is_false_capture`: Rust `Some` in `Some(x)`, a TS/JS parameter default; it runs only for Rust and TS/JS, so every other language's locals query must capture binding fields only: `symbols_occurrences::PARAMETER_CAPTURE_MATRIX`, see [Query System](./query-system.md#capture-naming-convention)) and Rust pattern names that read or are unknown in a refutable pattern (`rust_pattern_non_bindings`, run only when a Rust variable/parameter was captured) — so records, diagnostics and counts agree with the occurrences (`symbols_occurrences::PATTERN_IDENTITY_MATRIX`, `PATTERN_RECORD_MATRIX`; CLI `refs::symbols_list_no_declaration_for_pattern_names_that_bind_nothing`). The locals query records no nested moded (`Some(mut x)`, `ref`, `@`) or bare match-arm name; those bind `Scoped` with no ID. Swift `#if` and C# `#region` are flat `directive`/`preproc_region` siblings, not wrappers.
- **Member kinds are validated, not trusted.** `refine_symbol_kind` demotes any Method/Constructor (to Function) or Field/Property (to Variable), whether from a query capture or a classifier rule, when `is_function_local_member` finds a function before any type or object owner above the member slot (C# local functions are captured as methods by the vendored query). Lua `M:m`/`M.f` names its owner and is exempt. `symbol_scope` (which decides `DeclarationContext::is_local()`) also stops at the nearest owner, so members of a type declared inside a function keep their access; a JS/TS `constructor` is a Constructor only directly in a `class_body`. Other constructors: Java/C#/Swift by query capture (C# `static` excluded in the query); Python `__init__` and PHP `__construct` (`eq_ignore_ascii_case`) by name only after the declaration is a method; C++ by syntax alone (`declaration`/`function_definition` in a class body with no `type` field whose function declarator, reached through attributed/parenthesized wrappers only (`transparent_declarator`), is the `declared_function_named` one and declares the captured `identifier` itself: `C [[deprecated]] ()` and `(C)()` qualify, `~C`, `operator T`, `C::C` and pointer/reference wrappers do not; never a name comparison). Scala body `val`/`var` is reclassified to Field by a classifier arm, one per name of a grouped `val a, b: Int` (the query captures each `identifier` under `identifiers`; the field reader lists every name with the shared type). Recorded limits (Scala access-modified `enum`, tree-sitter-scala 0.24.0) live in `symbols_kind_coverage::GRAMMAR_LIMITS`; a demonstrated limit goes there, never in `unsupported` (which requires a clean parse).
- **Unnamed owners end the container search.** `find_symbol_container` returns no container at `is_unnamed_type_owner` (anonymous classes, Scala `given … with` instances, JS/TS class expressions and object literals, tagless C/C++ `struct`/`class`/`union` that is not an anonymous member) instead of climbing to the named type outside.
- **Implicitly static members are static.** A member the language makes static without the keyword sets `is_static` at extraction: Java interface constants, C# `const` fields, Rust associated `const`s (impl and trait), PHP member `const`s (`const_declaration` is captured as Constant; a top-level `const` is not a member). C++ `static constexpr` says `static`; Swift/TS/JS/Scala/Python have no keyword-less case beyond Scala `object` members and Python class attributes.
- **Static readers match nodes, not text, and stop at the nearest owner.** A member-`static` reader matches the declaration's own keyword/modifier token or decorator expression (Python: `staticmethod`/`classmethod`, bare or `builtins.`-qualified, and a `ClassVar` annotation head under any qualifier; never a substring or prefix) and asks only the type that directly owns the member (Scala: the member slot's `template_body` belongs to an `object_definition`). A new reader must not `.contains()` node text or climb past a class, trait, enum or anonymous class.
- **Field lists are completed from the standalone members.** `align_field_metadata` (`tree_file/definitions.rs`) pairs each type-metadata entry with the standalone `Field`/`Property`/`Constant` of the same name whose container node is that type (k-th entry with k-th symbol of a name), copies its `visibility`/`is_static`, **adds** any standalone member no reader listed (doc comment, no type) and orders the list by source position, so `hug classes` and `hug symbols` list the same members. Readers still matter: they supply type annotations and the entries with no standalone symbol (record components, Rust tuple positions, Scala class parameters). Enum owners get no field entries; their variant lists are completed from standalone `EnumVariant`s by `align_variant_metadata`/`reconcile_variants` (Enum owners only: a Swift enum is `Type` and has no list; `discriminant` from the member's `value` field; a standalone-only entry is unit, so a payload-bearing form needs a reader entry: Rust tuple/struct variants, Scala `full_enum_case` class parameters as `struct_fields`, every clause, defaults never a discriminant), and `MetadataSelection::for_kinds` keeps variant metadata when Enum is selected, and Rust `impl` members (by-name container) never join the struct's list. `symbols_field_lists` pins complete per-language lists on both paths; a new member form needs a query capture **and** a reader case.
- **Type metadata lists only fields and properties.** Interface, protocol and trait methods are standalone `Method`s, never `FieldInfo` entries (Java interface constants, C# interface properties, Swift protocol property requirements and Rust trait associated constants are listed). Go interface method elements are neither records nor entries: `extract_go_interface_methods` matches `method_spec`, which tree-sitter-go 0.25 no longer produces (`method_elem`); `symbols_field_lists` pins the empty list.
- **C/C++ names sit under any declarator chain.** The C/C++ `locals.scm` capture a name by its immediate parent (pointer, array, parenthesized, attributed declarator; C++ adds reference and, for member functions, `(function_declarator declarator: (field_identifier))` under any return declarators), never by a fixed outer shape. `classify_symbol_kind` makes a captured variable/field a Function (Method in a type body) when `declared_function_named` says its declarator declares one (`int f [[deprecated]] (int)`, `int (f)(int)`), so a function-pointer field stays a Field; `implied_c_function_context` (`declaration.rs`) supplies the context such a capture lacks. `c_field_name` (`type_metadata.rs`) is `declarator_name` minus function declarators. Typedef names behind a declarator are TypeAliases with the typedef's doc comment and no field list. `symbols_declarator_wrappers` is the row table to extend. Anonymous `struct`/`union` members (`anonymous_member_declaration`, `classify.rs`) belong to the enclosing type, with the C++ access of the section holding them.

## Key Architecture

- **Runtime**: Built on the tree-sitter Rust runtime (`tree-sitter = "0.26.3"`) plus one `tree-sitter-<lang>` grammar crate per language, all at independent versions — see [Tree-sitter Internals](./tree-sitter-internals.md)
- **Query vendoring**: Uses nvim-treesitter `locals.scm` in `lib/queries/vendor/<lang>/`
- **Custom queries**: `lint.scm`, `references.scm`, `comments.scm` per language
- **Capture naming**: `@local.definition.<kind>` for symbols, `@diagnostic.<rule-id>` for lint
- **Query caching**: Global `OnceLock<QueryCache>` for thread-safe caching
- **Builtin database**: Per-language builtin lists to avoid false positive undefined-symbol/undefined-module errors
- **Schema v2 module, schema version 5.1**: `shared/schema_v2` with facet-based `SymbolRecord` and staged `FileSymbolIndex`; records, file indexes, CLI envelopes and analyzer fingerprints emit `SchemaVersion::CURRENT` (the module keeps its historical `v2` name). Records carry no timestamps, so output and cache entries are byte-identical across runs; the container is `identity.container_name`
- **CLI declaration reports** (`cli/src/`: `declarations.rs` drives, `selection.rs`, `order.rs`, `report.rs`, `render.rs`, `classes.rs`, `scan.rs`, `prelude.rs`; `main.rs` only wires): `Declarations::query(format, &Selection)` is each command's fixed kind set ∩ `--kind`, the selectors as `SymbolQuery` predicates, and only the capabilities it shows (`classes` and `--tree` add containment; `--json`/`--jsonl` add `Flags` and `--stats` adds `Metrics`, all in `ReportFormat::capabilities`; no listing runs references, semantics, docs or diagnostics); `--json-full` asks `complete_index()` (every capability, flags and metrics included). `scan::in_file_order` runs rayon chunks of `4 × threads` and delivers results in file order, so `--json` is byte-identical across thread counts and cold/warm. The JSON envelope is written piece by piece with `errors` always last; records are projected (`report::trim_record`: scan-root-relative `file_path` and stable-key file segment, no `declaration_text`/source text/attached comments; IDs untouched). `tree_hugger::portable_relative` (`lib/src/file/naming.rs`, re-exported by `report.rs`) is the one path projection (entries, `errors[].file`, records, the qualified-name prefix; the CLI query passes `scan_root`): files outside the root get `../` routes via `biscuit_file::PathIdentity`, retried with directories canonicalized (macOS `/var` vs `/private/var`), and keep their absolute portable path only when no route exists (another Windows drive/share); the key's file segment is parsed from the key itself (`{lang}::{file}::{Kind:?}::`), never matched against `source.file_path`, because prelude aliases are keyed by the prelude file but located at the target. The one renderer (`render::Renderer`, built from `RenderOptions`) is `Prose` items in `UnorderedList`s (and a `Table` for `--format table`); it wraps only when `RenderOptions::width` is set (`main::wrap_width`: stdout is a TTY or `CLICOLOR_FORCE`, width from a positive `COLUMNS` else detection; `--plain`/`--format plain`/redirected output never wrap), and every source-derived string goes through `render::literal` (control chars → `\u{..}`, then `Prose::escape_text`, which on its own passes ANSI CSI/OSC through) or `render::neutralized` for table text cells; labels come from `identity.keyword` only for Type/Variable/Field/Constant, else the kind. Terminal output streams: `declarations::write_terminal` flushes after each `in_file_order` chunk (so a closed pipe stops scheduling within a chunk), `classes` writes per file, and `render::ListingStream` holds only the current unit (one file; one directory under `--group-by-module`; one package under flat `--sort name|kind` or `--prelude`) after `render::listing_order` reorders files by package, directory, path. Package sections are decided up front from `listing_order`'s package count (two or more packages in the scan, declarations or not), so nothing is held beyond the current unit; never reintroduce a layout decision that waits on later declarations, or a whole-scan accumulator ahead of the renderer. `write_json` flushes at the same chunk ends (`scan::flush_at_chunk_end`), so a closed pipe is noticed even when no entry fills the buffer. `--prelude` analyzes the prelude and its targets with an every-kind query first and the scan reuses them via `SymbolQueryResult::narrowed` (one parse per file; the reuse map, `collect_files` output, `SourceFile::path()` and the CLI roots are all `file_identity` spellings, so relative/`..`/symlinked inputs never split reuse or the cache); prelude exports are synthetic records (`visibility.is_synthetic`/`is_reexported`, own ID from the prelude file). Every output branch that writes declaration records (`--json` files, `--json-full` `index.symbols`, terminal listings, `classes` containers and member sections) orders through `order::compare`/`sort_file_records`: extraction order is not source order (C emits a typedef's inner `struct` specifier before the alias, Go a receiver parameter before its method). A failed file is stderr + `errors` + exit 1; a broken pipe exits 0 quietly. User-facing contract: `tree-hugger/docs/symbol-reports.md` (`order.rs` points at it); update it with any change to kind sets, envelope, order or `--verbose`.
- **`hug refs`** (`cli/src/refs.rs`, wired early in `main::run_refs`; user contract `tree-hugger/docs/references.md#hug-refs`): the first positional is the name (`NamePattern::exact`, matched with `SymbolQuery::matches`, so smart case and `file#`/qualified names behave as in the selectors), the rest are file filters; `--id` compares `record.id` exactly. It analyzes every file with `Capability::Occurrences` over every kind and scope (locals included), keeps only files with a match (resolution is file-local, so only the match's file can hold its evidence), and decides before writing: several matches → stderr list (location, label, qualified name, ID) and exit 1 with empty stdout; none → empty report. Incoming = `Scoped` rows with `target.id` == ID, plus a separate `name_only_suggestions` group (`NameOnly` whose candidates hold the ID); callees = `Call`s whose `owner.id` is the ID, every confidence, with `absent_id` (`import` iff the target name is in the record's `relations.dependencies`, which are exactly its bound imports by local name). Owner/candidate `qualified_name`s are re-prefixed from the result's records for presentation only. `DiscoveryArgs` (`--exclude-files`, `--language`, `--no-cache`) is shared with `ScanOptions`; `refs` takes no `SelectionArgs`/`ReportArgs`, so clap rejects `--kind`, `--format`, `--jsonl`, …; `--json-full` is rejected in `run_refs`. Text reuses `Renderer::{line, list, link, declaration}` and `render::label`. Tests: `cli/tests/symbols/refs.rs`, `level2_declarations::check_refs`.
- **Output modes** (`cli/src/output.rs`, `stats.rs`): `output::resolve(GivenOutput)` is the one place the "exactly one mode" rule lives (`--stats` composes with `--json` or a `--format`; `--sort`/`--signatures`/`--tree` reject `--stats`; `--tree` is terminal-only and not on `classes`); `main` maps the `OutputMode` to `declarations::ReportFormat`. `--sort` is `Option<SortOrder>` so "given" is detectable. `declarations::selected_records` is the one projection the JSON formats and the table share (classes: containers sorted, `displayed_members` trimmed); `write_json_lines`, `write_table`, `write_tree` stream per file in path order (not `listing_order`), `write_tally` holds only counters (`classes` counts containers). `selected_records` trims records (`trim_record`), so their `file_path` is scan-root-relative: anything that turns one into a file (the table's OSC 8 Location link) must join it onto `scan_root`, never resolve it against the working directory (`reports::table_location_links_resolve_against_the_scan_root`). `render::Outline` nests by `relations.container` ID, falling back to `identity.container_name` (a type declared in another file) for a marked `[in …]` heading that is never a record (an unlinked member is headed by its in-file owner path when that qualifies the name further, `[in other::W]`, so distinct external owners never share a heading); it reattaches anything a containment cycle would orphan. Type rows (`is_type()` kinds only, never a method or `[in …]` heading) end with `extends A; implements B; unclassified bases C` from `relations` as written (`Renderer::declared_bases`); under `--signatures full` a list the header already writes is dropped by `header_writes(record, list, base)`, an exact per-source rule (a Rust type's `implements` comes from impls, Go `extends` from interface bodies), never a text search (`struct W<T: Display>` + `impl Display for W` must still show it); a new language whose bases are not read from the header updates that match (`outline.rs` tests). `stats::Stats` keys are the records' serde spellings (`Function`, `Public`, `Rust`); synthetic exports count in the maps and apart from doc coverage. Tests: `cli/tests/symbols/reports.rs`, `outline.rs` (bases on type rows), goldens `symbols.{table,tree,stats,jsonl}`, `symbols-stats.json`, `symbols-signatures-full.plain` (`--format plain` shares `symbols.plain`); any test forcing color must pin `COLUMNS` (forced color wraps at the detected width).
- **CLI filters**: `hug <subcommand> <filter...>` with all-files default scan for symbol commands. A pathless scan honors `.gitignore` and skips test-data dirs by default (`**/fixtures/**`, `**/__fixtures__/**`, `**/snapshots/**`, `**/testdata/**`); an explicit path/glob re-includes a targeted file. `lint` scans hide clean files (single-file lint still shows `(no diagnostics)`).
- **Record selectors are one path** (`cli/src/selection.rs`): `SelectionArgs` (flattened into the declaration and `classes` args; `TargetArgs` = `--file`/`--name`/`--exact`, also on `imports`) resolves to a `Selection`, which becomes library predicates; the CLI keeps no name matcher of its own (positional names and `--exclude-symbols` are `NamePattern`s; `normalize_symbol_glob`/`matches_symbol_filters` are gone). Records are filtered by the library after the cache (`SymbolQueryResult::finish`); only `--prelude` is applied in `declarations::prepare` (its synthetic exports run `query.selects`/`query.matches` there). `symbols` defaults to `Item`+`Member` scopes (`SYMBOLS_DEFAULT_SCOPES`); other commands every scope. `classes` uses `classes::ClassSelection`: an analysis query with no predicates (container kinds ∪ member kinds, capabilities of both filters), identity predicates + `--kind` on containers, `--in` as the container's own name, shape predicates on members (fields hidden when one is given); `--static-only` conflicts with `--instance-only`. `imports` filters `index.imports` with `ImportSelection` (name, alias, original's last segment, or the whole original for a qualified pattern); positional tokens stay files. `--file` values: globs and unresolved values join the walker inputs, a `FileReference` that resolves to a file is an explicit target (`scanner::collect_selected_files`: bypasses `.gitignore`/fixture exclusions, not `--exclude-files`; never widens the scan). A bare `rs` is a name, not a file filter (`is_file_filter_token` needs a path, glob or `x.rs`). `--json-full` rejects every record selector (`SelectionArgs::given_flags`). Tests: `cli/tests/symbols/filters.rs`; tests that need locals from `symbols` pass `--all-scopes`.

## Diagnostic Metadata (Phase 1)

Every diagnostic now carries stable metadata for policy and display:
- **Category**: `correctness`, `suspicious`, `style`, `performance`, `pedantic`, `restriction`, `experimental`
- **Confidence**: `high`, `medium`, `low`, `experimental`
- **Source**: `tree-sitter-query`, `semantic-analysis`, `syntax-parser`, `external-tool`
- **Severity**: `default_severity` and `effective_severity` (after policy)

## Rule Registry

Built-in rules are registered in `RuleRegistry` with metadata:
- Rule id, version, title, category, default severity, confidence
- Language support, default enablement, examples, caveats
- `requires_experimental_semantics` gates low-confidence semantic rules

Default-off pattern rules are silent unless opted in with `--warn <rule>` or `--deny <rule>` (the registry's `enabled_by_default` flag is enforced by the CLI policy layer, `apply_lint_policy`):
- Debug artifacts: `console-log`, `print-call`, `fmt-println`.
- `restriction` category: `unwrap-call`, `expect-call` — valid, deliberate constructs, not anomalies. Enable per-rule or via `--deny category:restriction`. `--allow`/`--strict` never enable an off-by-default rule.

Experimental rules (`undefined-symbol`, `unused-symbol`, `undefined-module`) are disabled by default. Enable with `TreeFile::experimental_semantics = true` or `--experimental-semantics` in the CLI.

## Dead Code Detection

Dead code is detected only within the same block as a terminal statement (`return`, `panic!`, `break`, etc.). Terminal statements inside nested control-flow constructs (e.g., an `if` branch, a `match` arm, or a closure) do not propagate dead-code detection to the enclosing function or method body.

## CLI Policy

Policy selectors target rules by ID or category (`category:correctness`):
- `--deny <rule>`: promote to error
- `--warn <rule>`: promote to warning
- `--allow <rule>`: demote to info
- `--strict`: promote all warnings to errors (does not enable experimental rules)
- Syntax diagnostics are always errors and always fail the exit code

trailing spaces: WezTerm pads a wrapped line's last piece to the pane width). The helpers are
L1-tested on synthetic captures in the `symbols` binary (`terminal_scope`).

## Resolver and Adapter Architecture (Phase 3)

### Semantic Resolvers

The `resolver` module defines interfaces for project-level semantic analysis:
- `ProjectContext`: Root path, manifests, language configs, dependency hints, generated-file markers, target environment
- `SemanticResolver` trait: Reports confidence and supported-scope metadata, returns `ResolverOutput` with diagnostics and resolved imports
- `ResolverScope`: `FileLocal`, `Module`, `Project`, `Workspace`

Resolvers are gated until corpus precision is measured. Low-confidence resolver-backed diagnostics use `DiagnosticConfidence::Low` or `Experimental`.

### External Diagnostic Adapters

The `adapter` module defines interfaces for delegating to external tools:
- `ExternalDiagnosticAdapter` trait: `name()`, `version()`, `is_available()`, `supported_languages()`, `run()`
- `AdapterConfig`: Tool path, config path, extra args, environment, strict mode, timeout
- `AdapterResult`: Normalized diagnostics + `AdapterMetadata` (tool name, version, config files, exit status, elapsed time, cache status, fix availability)
- `AdapterError`: `ToolNotFound`, `IncompatibleVersion`, `ExecutionFailed`, `ParseFailed`, `UnsupportedLanguage`, `ConfigError`

Adapters preserve source tool rule IDs and report fix availability without applying fixes.

### Oxlint Adapter

`OxlintAdapter` is the first external adapter for JavaScript/TypeScript:
- Discovers `oxlint` via explicit config -> project-local `node_modules/.bin/oxlint` -> `PATH`
- Parses Oxlint JSON output into normalized `Diagnostic` values with `DiagnosticSource::ExternalTool`
- Maps Oxlint severity and categories to Tree Hugger equivalents
- Falls back to native diagnostics when Oxlint is unavailable
- In non-strict mode, missing tools produce empty results with metadata rather than errors

## Corpus and Default-On Gates (Phase 4)

The `corpus` module provides infrastructure for measuring rule precision against real-world code:

### Corpus Harness

- **`CorpusManifest`**: Defines repositories/fixtures with metadata (SHA, license, paths, rules, oracles)
- **`CorpusTier`**: `Smoke` (fast PR checks), `Expanded` (scheduled CI), `Benchmark` (performance timing)
- **`CorpusResult`**: Analysis output with per-rule threshold reports
- **`ThresholdReport`**: Tracks diagnostic counts against rule thresholds (`Zero`, `Budget(n)`, `Unlimited`)

### Snapshot Stabilization

- **`redact_snapshot_text()`**: Redacts absolute paths, temp dirs, tool locations
- **`normalize_diagnostics()`**: Sorts and deduplicates for stable comparison
- **`compact_diagnostic_text()`**: Produces compact stable representations
- **`strip_ansi_codes()`**: Removes terminal escape sequences

High-confidence syntax rules require `Threshold::Zero` corpus false positives. Experimental semantic rules use `Threshold::Unlimited` until resolver-backed precision is proven.

## Persistent Symbol Cache

`cache::SymbolCache` (`cache/symbol_cache.rs`) is the only cache `hug` uses
(`--no-cache` skips it); full design and the robustness table are in
[`docs/cache-design.md`](../../../tree-hugger/docs/cache-design.md).

- **One entry per file.** Key = `canonical_digest` (length-prefixed BLAKE3)
  of path (`/` separators), source xxHash, forced language or `detected`,
  and the records `PassFingerprint` (schema, `<crate>+rev.<EXTRACTOR_REVISION>`,
  grammar identity read from the `Language`, effective `locals`/`imports`/
  `references` text). Kinds and capabilities are **not** key inputs; the
  entry records `covered_kinds` (`"all"` or a non-empty ascending list) and
  `completed_capabilities`.
- **Diagnostics carry their own fingerprint inside the entry** (lint +
  comments text, rule metadata, `experimental_semantics`); a mismatch makes
  the diagnostics "not computed", never a key change.
- **Lookup**: `Hit` (no parse) / `WidenedCapabilities { parsed }` (docs,
  semantics-with-references and containment-over-all-kinds run on stored
  records; references and diagnostics re-parse) / `WidenedKinds` (one
  analysis for the union) / `Miss(CacheMiss)`. Every result goes through
  `analysis::coverage::project`, which narrows a wider entry to exactly the
  uncached result; a new pass that changes records must be reflected there
  (`symbols_cache::projected_results_*` fail otherwise).
- **Reader**: `deny_unknown_fields`, no defaults on entry fields, custom
  visitors for the coverage lists; failures are `CacheMiss::Malformed(serde
  message)` / `Mismatched` / `Inconsistent`, never an empty result. The entry
  and **every record** must carry exactly `SchemaVersion::CURRENT` (minor
  included), else `Mismatched("record schema version")`; a nested
  version-bearing value must be checked in `StoredEntry::validate`. Reference
  evidence has its own strict form (`cache/stored_evidence.rs`): the entry
  writes every key (`null` owners/IDs, `[]` candidates/reasons) and
  `deny_unknown_fields` types read them, never the public serde defaults;
  `validate_evidence` (one `StoredEvidence` argument) then checks spans
  against the source (bytes, char boundaries, one-based line/byte column),
  confidence/ID/candidate consistency, generated-ID form (`is_generated_id`,
  64 lowercase hex) for every evidence/summary/record ID, every target,
  candidate, owner and summary ID against a *retained* record of the written
  name (`StoredEvidence::covered_kinds`: an absent record is accepted only
  when the entry omits a kind it could have; owners and `referenced_by` are
  callables, so only an omitted Function/Method/Constructor exempts them;
  an every-kind entry exempts nothing), a `Scoped` no-ID target's name written
  elsewhere (`unbound_names_have_a_binding`: an import or unreported binding
  always is), canonical order, owners against coverage regions, the
  innermost region (`innermost_owners`) and records' names, unique regions
  and a retained callable's own region iff it has a `body_span`, containing
  that body (every language; never compared with `declaration_span`, which
  is only the declarator for C/C++; the region builder in
  `occurrences::resolve` reads the same fact, so an empty or comment-only
  Lua body owns its declaration's region), each non-null
  `target.qualified_name` (the written path, `written_path`) the source text
  ending at the occurrence's end and longer than the name, and agreeing with
  the occurrence's cache-only `path_start_byte` (a required key in
  `StoredOccurrence`, never in the public schema; `null` iff the path is
  `null`, else `end - path.len()`; `ReadOccurrences` carries the starts beside
  the occurrences into `StoredEvidence::path_starts`), in every language and
  whether or not any record is retained: a path or start deleted alone is
  `Inconsistent`, both deleted together is the documented coordinated-forgery
  limit (no source scan can tell a never-written `null` path from a deleted
  one: Rust macro token trees, leading `::`, JS spread), candidates in `name_only`'s
  order (name position, then ID) among retained records, summaries without
  repeats (`RefSet`'s key) in first-occurrence order
  (`summaries_in_first_occurrence_order`: exact for IDs; import edges must
  match the exact selected import span retained on each scoped occurrence), the
  no-rules languages' exact name lookup and `unsupported_language` reason,
  edges both ways (`references`/`referenced_by`/`dependencies` vs `Scoped`
  occurrences), and the whole `semantics` facet recomputed by
  `analysis::semantic_facets` (the semantic pass's own function; default
  without `semantics`). A test that renames a record or forges a qualified
  name in an entry must update the evidence refs and reference summaries
  too (`cache_upgrade::rename_record`/`set_qualified_name` do), and can only
  rename a record no occurrence writes (`rename_record` asserts it). Extend
  `cli/tests/symbols/cache_robustness.rs` (entry and record columns;
  `evidence_columns`/`INCONSISTENT_EVIDENCE` for evidence) for a
  new load-bearing field, and assert `CacheLookup::Hit` (not just equal
  output) in any warm-run test: a silently undecodable entry still produces
  equal output.
- **Writes** are temp file + rename (`PersistentCache::put`); last rename
  wins.
- **One directory for every scan root**: `hug` opens
  `default_cache("hug")` (`CACHE_PROJECT_ID` in `cli/src/main.rs`), never a
  package-root partition, so a file reached from two scan roots shares one
  entry (`cache_lookup::a_run_from_another_scan_root_hits_the_same_entry_with_the_same_ids`).
  Nothing scan-root-dependent may enter a stored record or the key.
- `StoredEntry::validate` refuses (`Inconsistent`) a `metrics` facet or a
  `true` `is_test`/`is_deprecated` whose capability (`metrics`/`flags`) the
  entry does not list, and a record without `metrics` under `metrics`. Flags
  and metrics need the tree, so widening by them parses. Query text is
  injectable for tests (`SymbolCache::with_query_text`).
- `InProcessCache`, `InMemorySymbolCache`, `SymbolSnapshot`,
  `AnalyzerFingerprint` remain as library types but no CLI path uses them.

## Neovim Query Reuse (Phase 6)

### Query Provenance

Every query carries provenance metadata (`QueryProvenance`) tracking:
- **Source project**: e.g., `nvim-treesitter` for vendored queries, `tree-hugger` for originals
- **Upstream revision**: Tag or commit SHA when vendored
- **Original path** and **local path** for audit trails
- **License**: SPDX identifier (e.g., `Apache-2.0`)
- **Translation status**: `Unchanged`, `PredicatesAdapted`, `CapturesRenamed`, `MultipleChanges`, `Original`

Access via `tree_hugger::query_provenance(language, kind)` or `all_query_provenance()`.

Vendored `locals.scm` provenance is per language (`vendored_locals_changes` in `queries/provenance.rs`, an exhaustive match): a language whose query gained or lost patterns is `MultipleChanges` with one note per change, else `CapturesRenamed`. **Perl's `queries/vendor/perl/locals.scm` is a Tree Hugger `Original`** (repository license `AGPL-3.0-only`), not nvim-treesitter's, so drift checks skip it. When you edit a vendored query, update its notes in the same change; `phase6_neovim_query_reuse::every_locals_definition_capture_is_inventoried` fails if a new `@local.definition.*` capture is missing from the inventory.

### Nvim-treesitter Inventory

`QueryInventory` records capture groups from all upstream query suites:
- **Locals** (`locals.scm`): Reused by Tree Hugger for symbol definitions and references
- **Highlights** (`highlights.scm`): Inventoried but not yet reused
- **Injections** (`injections.scm`): Inventoried for future language-injection support
- **Folds** (`folds.scm`): Inventoried for future folding support
- **Indents** (`indents.scm`): Inventoried for future indentation support

`CaptureEntry` tracks whether a capture is reused and includes translation notes.

### Predicate and Directive Compatibility

`CompatibilityRegistry` documents how Neovim predicates/directives behave in the tree-sitter Rust runtime:
- **Native**: `eq?`, `match?`, `lua-match?`, `any-of?`, `contains?`, `any-contains?`, `set!`, `offset!`
- **RequiresHook**: `has-parent?`, `is?`, `has-ancestor?`, `not-has-ancestor?` — the registry names a hook, but no hook is implemented: the runtime returns them as general predicates nobody applies, so a pattern carrying one matches as if it held (the Java import pattern did, importing every qualified annotation and module-directive operand). Never use them; write the context into the pattern's shape (`(import_declaration (scoped_identifier name: …))`). `queries::tests::no_query_carries_a_predicate_the_runtime_does_not_enforce` fails on any general predicate in any compiled query
- **Unsupported**: `make-range!`, `strip!` — must not be silently dropped

Use `find_unsupported_predicates(query_text)` and `find_hook_predicates(query_text)` to audit queries.

### Upstream Drift Detection

`check_query_drift(language, kind, current_revision)` and `check_all_drift()` report when vendored queries diverge from upstream:
- Detects newer upstream revisions
- Flags content mismatches and capture divergences
- Only applies to vendored queries (not original overlays)

`summarize_drift()` produces human-readable reports.

## Known Limitations

- **Swift**: structs, classes and enums all captured as `SymbolKind::Type` (an extractor limit; the grammar's `declaration_kind` field could distinguish them)
- **Constructors**: explicit instance constructors only; Java compact record, C# static/primary constructors and destructors are absent, C++ out-of-class `C::C() {}` is a container-less `Function`
- **Go**: Struct and interface both captured as `SymbolKind::Type`
- **Go**: embedded fields and fields of anonymous struct types are not reported; grouped `X, Y int` fields share one span, so `hug` orders them by record ID
- **Scala**: `private enum E { … }` does not parse (grammar limit G1 in `docs/symbol-kinds-and-visibility.md#grammar-limits`)
- **Python / JavaScript**: instance attributes assigned only through `self.x` / `this.x` are not reported (the catch-all assignment patterns were removed); class-body declarations are
- **C# / Swift / Scala**: mixed lists retain unknown categories in `relations.unclassified_bases`; Swift extensions of external, aliased or ambiguous owners cannot attach conformance to a local record (`docs/type-relations.md#c-swift-and-scala`)
- **Declaration-fact grammar limits** (pinned by `*_grammar_limits_*` tests, table in `docs/symbol-kinds-and-visibility.md#grammar-limits`): Python PEP 696 type-parameter defaults and TS `in`/`out` variance do not parse; a C++ concept-constrained parameter (`template <std::integral T>`) reads as `Const`; a TS/JS decorator is only a path or a call of one
- **Perl**: narrow coverage: named subs, `package` (Module) and `my`/`our`/`state` names only; variable names keep their sigil (`$name`); `local` is never a declaration; scope lives in the declaration text (`my`/`our`/`state`), not in the level

### Supported lexical name comparison

`analysis/name_identity.rs` owns comparison keys: Rust removes the raw prefix
and applies NFC; ECMA decodes identifier Unicode escapes without NFC. Imported
ECMA string originals decode string escapes as one name (dots are literal).
Scopes, candidates, Rust relation owners, recursion, diagnostics and cache
evidence consumers share these keys; public names and token geometry remain
written text. TypeScript's locals overlay captures bodyless function signatures
so ambient targets retain IDs and overload candidate lists stay complete.
`symbols_name_identity` partitions six-stage source regressions into bounded
registered groups with independent expected IDs and a corpus coverage guard.


### Cached import consistency

`StoredImport` and `StoredImportRef` are strict private readers in
`cache/stored_evidence.rs`. Import validation precedes every capability/kind
projection, including entries retaining no occurrences. External IDs and
symbol source spans are never produced. Exact written capture geometry,
name agreement, canonical capture order, and selected-import dependency
provenance are checked without another Tree-sitter parse. Required
`import_inventory` is a BLAKE3 witness of the complete grammar-produced import
list, including nullable metadata and exact name/statement geometry. The sole
entry writer computes it before projection; the reader checks it before every
capability, rejecting missing grouped members, invented roles, and changed
boundaries or metadata. There is no approximate source lexer. Retain independent
geometry/provenance checks alongside the witness; it is consistency evidence,
not authentication against coordinated edits of every witness.
The `symbols_cache_imports` L1 corpus restores a tool-written entry per edit,
asserts independent public facts and actual later hits, and has a registration
guard for all producer/geometry partitions. Preserve genuine no-alias/source/
original/statement controls and opaque/string/non-import syntax warm hits.
The shared `tests/fixtures/scoped_import_lexical.rs` corpus feeds library
`symbols_cache_lexical` and CLI `cache_lexical`; `just test lexical_inventory`
checks every supported language, all regex contexts and comment/raw delimiters,
six cache stages, deleted/invented imports and JSON/text reference directions.
Keep the live-target corpus and consumer registration guards complete.


Java import captures are scoped to `import_declaration` and accept both a qualified path's final identifier and a direct identifier (`import p.*`, `import static p.*`, comments around the dot). On-demand records retain source `p`, alias/name `p`, original `*`; exclude only that bound token, preserving qualifiers and body reads. `symbols_cache_imports::java_single_segment_on_demand_imports_keep_public_facts_and_six_cache_stages` pins public diagnostics, conservative evidence, summaries, filtering and cache projections; CLI `refs::java_single_segment_on_demand_imports_are_reported_without_token_suggestions` pins reports.
