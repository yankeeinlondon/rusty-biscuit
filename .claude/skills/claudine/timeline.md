# Claudine Change Timeline

For current behavior always trust [architecture.md](architecture.md), [cli-reference.md](cli-reference.md), and the repo `docs/topics/*` — this file is historical context, not a spec.

## 2026-06

- **2026-06-27 — `live-but-dead`**: Added the OpenCode **stalled-generation backstop**, a fourth `ProcessTermination::Aborted` content guard for the *live-but-dead* shape — a run that keeps retrying a dropped generation, re-emitting `service=llm ... stream` (`LlmCall` with `is_stream == true`) so the byte heartbeat stays alive and `step_timeout` never fires, while producing no assistant text, tool call, or step advance. State lives bridge-local in [`OpenCodeLogBridge`](../../../claudine/lib/src/stream/logs/opencode/bridge/mod.rs) (`last_progress_at`, `generation_count_since_progress`, `last_generation_context`). The guard trips only when **both** conditions hold on the same `llm_call_start`: retry churn (`generation_count_since_progress >= MAX_GENERATIONS_WITHOUT_PROGRESS`, a constant `4`) **and** progress silence (`now - last_progress_at >= stall_timeout`, default `10m`). Either alone never fires — the count condition exempts a single slow generation, and a long tool emitting no `LlmCall` never trips. Resets on genuine `StepLoop` advance / `StepExit` / subagent lifecycle; **not** on deduped `StepLoop`, another `LlmCall`, `http_response`, `permission_evaluated`, `service=bus`, or raw bytes. Independent of the `repeated_stream_error` counter (neither resets the other) and shares the bridge's single `fire_early_termination` idempotency. Routes to `error_kind = "stalled_generation"`, a terminal `AgentNative` "Stalled Generation" event, and fail-fast `AgentFailure` — **never** `handle_timeout:`. Config mirrors `step_timeout` precedence (CLI `--stall-timeout` > frontmatter `stall_timeout` > env `CLAUDINE_OPENCODE_STALL_TIMEOUT` > built-in `10m`; `0s` disables); it is **not** a third general timeout, and non-OpenCode runs accept the key as inert config. No `stall_timeout_warn` companion. See [Timeouts — Stalled-generation backstop](timeouts.md#opencode-stalled-generation-backstop), [OpenCode Event Sources](opencode-event-sources.md), and the [spec](../../../claudine/features/2026-06-22-live-but-dead/spec.md).
- **2026-06-26 — `positional-and-key-value`**: Reduced the lifecycle stack action grammar to **two** forms and unified its evaluation rule. **Positional** is a single-key `{verb: value}` object (scalar → 1 arg; array → N args zipped to the verb's canonical signature; null / `[]` / bare-verb-name string → 0 args), and **key/value** is the explicit `{action: verb, …}` object with named parameters for optional slots (`route`/`on_error`/`no_error`/`max_attempts`/…). The forms are distinguished structurally (an `action:` key means key/value; a lone known-verb key means positional). **One rule governs both: every value is literal text and `{{ … }}` injects a variable/expression**, with only `when`/`until`/`while` evaluated as boolean expressions — a whole-value `{{ expr }}` span still carries a typed value (`set_frontmatter: ["s.md", "ready", "{{ true }}"]` → boolean), and object args pass through a whole-value span (`merge_frontmatter: ["s.md", "{{ payload }}"]`), never a direct nested YAML map. Two **breaking** changes: the `verb(args)` **short form** was removed (`parse_short_form_action` / `parse_action_arg` / `has_unquoted_whitespace` deleted; a `verb(args)`-shaped value now fails with a typed did-you-mean rewrite — `success("x")` → `success: "x"`, `set_frontmatter('a','b','c')` → `set_frontmatter: ["a","b","c"]`), and key/value string params are now **literal by default** (`message: "ctx.area"` sends the text; use `"{{ ctx.area }}"` for the value — `value_to_expr` → `action_value_to_expr`). Verbs are validated at parse time against the union catalog via a new signature-parser helper over Darkmatter's `EFFECT_DESCRIPTORS` / `EXPRESSION_FUNCTION_DESCRIPTORS`; the `action: <verb>` + sibling-keys path was dropped. The loop `loop.action:` surface (`split_action_args` in `loop_config.rs`) is a separate grammar and unchanged. See [Lifecycle — Action Forms](lifecycle.md#action-forms) and the [spec](../../../claudine/features/2026-06-26-positional-and-key-value/spec.md).
- **2026-06-25 — `late-binding`**: Lifecycle event properties now interpolate **at event-time**, not during the initial compose — so `failure.message: "{{err.msg}}"` (top-level) and a `failure` stack `message(❌️ {{err.msg}})` finally render the real error (previously `err`/`timing`/`current` were unreachable in operational messages: top-level was rejected at prepare, stack rendered empty). Done **in Darkmatter, not a second claudine interpolator**: two opt-in Darkmatter primitives — **DM1** (`ComposeOptions::with_exclude_keys`) defers named top-level keys from all four compose-time resolution passes (claudine passes the seven lifecycle keys, so their `{{ … }}` spans survive raw in `effective_frontmatter`; `deferred_frontmatter_keys` reported back for dry-run labeling), and **DM2** (`SubtreeCompose`, an injectable layered lookup with eager/lazy globals + a strict mode) re-runs the same interpolation core over a frontmatter subtree. Claudine calls DM2 **just-in-time** before each property/action string is used (so a stack action #1 `set_frontmatter` is visible to action #2), with `err`/`timing`/`current` injected; the bespoke `lifecycle_executor::interpolate` + `LifecycleLookup` runtime path was **deleted**. Strict mode **fails closed** before dispatch on unknown roots (typos), malformed/unknown-function spans, and late-binding misuse, while a known-but-empty reference still renders empty. `shell(...)` (the `verb(args)` short form, **superseded 2026-06-26** by positional `shell: "…"` / key/value `command:`) is the early-binding exception (C3): resolved at pre-flight via DM2 with an early-binding-only lookup, stamped back byte-for-byte (approved == executed), late-binding refs rejected at prepare. The prepare-time leak/undefined-variable scans stopped running over lifecycle strings (they would flag authored spans); the leak guard moved **post-DM2** (`reject_surviving_spans`), and `validate_no_err_in_no_error_events` (the kept prepare scan) now walks `{{ … }}` spans of literal strings plus whole `when:` expressions. See [Lifecycle — Binding Time](lifecycle.md#binding-time-early-vs-late) and the [spec](../../../claudine/features/2026-06-22-late-binding/spec.md).
- **2026-06-24 — `literal-short-form-args`**: Short-form lifecycle actions became **arity-aware**. Single-parameter verbs — every communication channel plus `shell`/`error`/`proxy`/`resume`/`defer` — now take the **entire** parenthesized body as one **literal** argument: no comma splitting and no quoting required (`warn(phase 6 is too large, only 5 exist)`, `error(invalid phase: 6 > 5)`), with surrounding quotes still unwrapped for back-compat (`is_single_text_arg_verb` + `unwrap_wrapping_quotes` in `composition/lifecycle.rs`). Only multi-argument side-effect/expression-function verbs keep the comma-separated **expression** grammar. Consequence: a bare token in a single-param arg is literal text, not an expression — reference runtime values via `{{ … }}` (resolved in `render_message`), so `say({{err.msg}})` prints the error and the bare-`err` / undefined-variable parse-time guards now scope to expression surfaces (`when:` clauses, multi-arg args) only. Also fixed a misleading diagnostic where a non-unknown-field serde error (e.g. `stack:` authored as a YAML map instead of a list) rendered as a fabricated "Unknown property" with a bogus field catalog; it now shows the real type-mismatch message and a `stack:`-must-be-a-list hint. See [Lifecycle — Action Forms](lifecycle.md#action-forms).
- **2026-06-23 — `universal-flow-control`**: Generalized lifecycle flow control to be **universal** — `error`/`stop`/`retry`/`resume`/`proxy`/`defer` are valid in **every** event; `skip` is the one placement rule (`initialize`-only). The per-event "where valid" matrix collapsed to that single rule, and runtime dispatch was made event-agnostic (the per-signal gates in `decide_control` removed, `dispatch_terminal_control` de-signaled, `retry` re-entry derived from `provider_launched` rather than the event). `success`/`start` (and the off-loop `initialize`/`blocked`/`loop` events) now dispatch flow control, so `success` + `resume` (steer the agent when an expected artifact is missing) works end-to-end; off-loop `retry`/`proxy` surface a typed `LifecycleSetupPhaseRecoveryUnsupported` (no pre-flight re-entry loop yet). Renamed the `requeue` flow-control action to **`defer`** ("run again later"); `defer` is parse-valid everywhere but returns a typed `LifecycleDeferNotImplemented` until its rendezvous deferred-execution backend lands (the enqueue machinery is retained but unwired). See [Lifecycle](lifecycle.md) and the [spec](../../../claudine/features/2026-05-12-lifecycle/spec.md).
- **2026-06-23 — `finalize-recovery`**: The `finalize` event became a last-chance **recovery** surface. `Retry`/`Resume`/`Defer`/`Proxy` are now valid in `finalize` (parse-time `LifecycleControlAction::is_valid_for` and runtime `decide_control` both extended), in addition to the `Error`/`Stop` it already supported. A `finalize.stack` (typically guarded by `when: "err"`) re-enters the run or hands off under the same per-control `max_attempts` budget as `failure`. The harness loop runs finalize through a new `run_finalize_with_recovery` helper at the success/failure/inline-closure terminal sites; a `success`-stack `error()` downgrade now also surfaces its `err` (via `execute_terminal_event` → `TerminalEventOutcome { outcome, downgrade_err }`) so the downgrade routes through `failure` and then a recovering `finalize`. Enables the canonical "verify in `success`, recover in `finalize`" pattern. See [Lifecycle](lifecycle.md) and the [spec](../../../claudine/features/2026-05-12-lifecycle/spec.md).
- **2026-06-22 — `inline-hash`**: every successful `inline-compose` closure now stamps a Darkmatter `Simple` content hash into the `hash:` frontmatter property in the same atomic write that persists the body. The hash is forced to `Simple` (`<fm>-<body>`, 16 hex per segment) regardless of any pre-existing `structured`/`detailed` value, and `hash`/`last_updated` are excluded from the frontmatter segment so the stamp is a self-reference fixed point. Malformed existing `hash:` values fail with `CompositionError::InlineHashMalformed` before the file is written. The old bespoke `u64` body-unchanged check was folded onto the body segment of the same `ComputedHash::Simple`. See [Composition — `hash` property](composition.md#hash-property-auto-stamped) and the [implementation plan](../../../claudine/features/2026-06-21-inline-hash/plan.md).
- **2026-06-21 — `remove-validations`**: Retired the harness validation/handler DSL. `pre_checks`, `post_checks`, `handle`, `handle_<event>`, and `deviate` are no longer accepted — each fails preparation with a typed `CompositionError::RemovedValidationKey` (emitted by `scan_removed_validation_keys` before lifecycle parsing) that names the offending key and its lifecycle replacement. Gating, verification, and recovery move entirely onto lifecycle stacks (`when:` guards plus `Error`/`Skip`/`Proxy`/`Retry`/`Resume`/`Defer`). The harness keeps shell audit, timeouts, runaway guards, and attempt classification; the `validate/` module, `handlers.rs`, the validation-report code, `finalize_effective_plan`, and the inline writability pre-check (plus the snapshot/diff) were deleted. Inline-compose's prompt-preservation is the independent `composition/closure.rs` path and is untouched. See [Validations and Handlers → Lifecycle Stacks](validations-and-handlers.md) and the [spec](../../../claudine/features/2026-06-21-remove-validations/spec.md).
- **2026-06-16 — `always-harness`**: `compose` and `inline-compose` now route every non-dry-run execution through `run_harness_loop`, including bare documents (no harness frontmatter) and interactive sessions. The previously separate `execute_without_harness` path and its `CompositionExecutionMode::{Direct,Inline}` split were removed. Bare documents yield the empty harness plan; inline documents got a system-owned writability pre-check injected once by `finalize_effective_plan`. Phase 2 surfaced terminal-attempt `IterationSummarySignals` so `compose --loop` keeps rate-limit and exit-reason behavior. **Superseded 2026-06-21 by `remove-validations`** — `finalize_effective_plan` and the writability pre-check were removed; the plan now carries only timeout configuration. See the [Always-Harness Plan](../../../claudine/features/2026-06-03-always-harness/plan.md).
- **2026-06-06 — `inline-sequence`**: `claudine inline-compose <file>` now rejects a document that authors **both** a non-null `prompt` and a non-null `sequence` — an *inline sequence* that must be run with `claudine sequence` instead. Detection (`composition::is_inline_sequence_mismatch`) reads authored frontmatter only (overrides never participate), inspects non-null-ness rather than type validity, and runs fail-fast before prompt validation, schema, composition, provider selection, and execution (no shell runs, no provider launch, source unchanged). `FrontmatterParse` retains precedence on malformed frontmatter. The `CompositionError::InlineComposeSequenceMismatch` diagnostic names both properties, directs to `claudine sequence`, notes the upcoming `sections` feature, and — only when stderr is a TTY — echoes the authored frontmatter YAML verbatim (captured by `composition::capture_frontmatter_yaml`, delimiter lines and the final separator excluded, interior LF/CRLF preserved); non-TTY output withholds the YAML and says so, with no reveal flag. See [Composition — Inline-Compose / Sequence Mismatch](composition.md#inline-compose--sequence-mismatch).
- **2026-06-03 — `dry-run`**: The long-dormant `--dry-run` flag on `compose` / `inline-compose` / `sequence` became a real pre-launch gate. It runs the full composition pipeline up to (not including) provider launch — schema validation, real shell execution, harness pre-checks, and provider/model resolution all run — then emits the composed **body to stdout** and the highlighted YAML frontmatter + a metadata table (Document OSC8 link, Description, Agent, Model, YOLO, Area) **to stderr**. The old behavior (a provider-command dump via `output::log_dry_run`) was swapped out of the composition path but kept for the raw provider wrappers. `--quiet`/`--silent` are no-ops under `--dry-run`. Non-TTY unapproved shell commands fail fast with `Cannot dry-run: shell command 'X' requires interactive approval…` (bypass with `--yolo`); in a TTY the normal approval prompt fires. `inline-compose --dry-run` never mutates the source file; `sequence --dry-run` concatenates bodies to stdout with `=== Document N of M ===` dividers on stderr and fails fast. Render core lives in `cli/.../wrap/composition/dry_run.rs`. See [Composition — Dry Run](composition.md#dry-run).

## 2026-05

- **2026-05-12 — `lifecycle`**: Formalized the composition lifecycle into **seven** events — `initialize`/`start`/`blocked`/`success`/`failure`/`finalize`/`loop` (up from four) — each sharing one config shape: the legacy top-level communication properties plus an ordered `stack:` of `when:`-guarded actions. Actions span five categories (lifecycle, communication, side-effect, expression-function, shell); the lifecycle actions (`Stop`/`Skip`/`Error`/`Proxy`/`Retry`/`Resume`/`Defer`) are last-and-terminating with parse-time cardinality and "where valid" enforcement. Added the stack-only globals `err`/`timing`/`current` (bare `err` rejected at parse time in no-error events; `doc.err` is the escape hatch), the statusless `stdout` channel, and the universal `no_error` escape hatch. Looping wraps the whole document and re-enters later iterations at `start`. See [Lifecycle](lifecycle.md) and the [spec](../../../claudine/features/2026-05-12-lifecycle/spec.md).
- **2026-05-12 — `improved-error-handling`**: Compose-loop errors split out of the overloaded `LoopInvalid`. New `LoopIterationFailed { iteration, prompt_path, exit_code, reason, exit_reason }` and `LoopRateLimited { ... reset_at, message }`; `reason`/`exit_reason` come from the iteration's `session_end` JSONL row. Loop became rate-limit-aware via `loop.on_rate_limit: pause|abort|continue` (default `pause`), `--on-rate-limit`, and exit code `75` (`EX_TEMPFAIL`). `LoopInvalid` now means frontmatter parse failure only.
- **2026-05-12 — `opencode-stderr-returns`**: OpenCode **Dual-Source Contract**. Stdout NDJSON is "DONE-only" (no tool starts, no `task_started`), so the wrapper opts into structured stderr via `--print-logs --log-level INFO` and `OpenCodeLogBridge` promotes selected log records to first-class `SemanticEvent`s. Full mapping in [opencode-event-sources.md](opencode-event-sources.md).
- **2026-05-11 — `2026-05-10-prompt-reporting` (Phases 1-3)**: New `prompt_reporting` module — system/user prompt reporting, frontmatter verbosity parsing, precedence, token estimation, truncation, and markdown formatting with the system-prompt reporter.
- **2026-05-10 — `opencode-timeout-regression`**: Silence rule hardened after commit-style OpenCode flows were misread as hangs. Three layers: a provider-agnostic raw-byte heartbeat (`last_byte_at`), a per-step `provider_status` grace (silence suppressed `step_start`→`step_finish`), and synthesized `SubagentStart`/`SubagentStop` from completed `task` tools. Guard is OpenCode-only; zero-byte hangs still trip `step_timeout`.
- **2026-05-06 — `2026-05-06-looping`**: Per-prompt looping. `loop` frontmatter parsed in `composition/loop_config.rs`; action engine (`increment`/`decrement`/`set`/`append`/`prepend`/`merge` with all-or-nothing `ActionStaging`); Darkmatter condition evaluation against `env.*` and ambient vars (`iteration`, `is_first`, `is_last`, `last_output`, `last_exit_code`); `max_iterations` cap and `CLAUDINE_MAX_ITERATIONS`.
- **2026-05-06 — `2026-05-02-flattened-bridge` (Phases 4-5)**: Non-interactive terminal rendering hardened. Plain/`NO_COLOR` paths start from `Terminal::new_optimistic(width)` and clamp `is_tty=false` to avoid OSC 11 color probes; wrapper startup delays terminal construction until interactivity is known. Removed the legacy JSON-serialize-and-flatten expression path.
- **2026-05-03 — `2026-05-02-opencode-stability` (Phase 4)**: Unified timeout watchdog. Exactly two rules — `timeout` (wall-clock, opt-in, no default) and `step_timeout` (stream-silence, default `30m`) — with consistent vocabulary across CLI flags, frontmatter, and env vars (`CLAUDINE_TIMEOUT`, `CLAUDINE_STEP_TIMEOUT`, `CLAUDINE_KILL_GRACE`, `CLAUDINE_WATCHDOG_INTERVAL`). Replaced the old `CLAUDINE_SUBAGENT_*` / `CLAUDINE_STREAM_IDLE_*` knobs. Canonical reference: [Timeouts](timeouts.md).

## 2026-04

- **2026-04-29 — `2026-04-29-leverage-dm-parser`** (hardened 2026-05-06): Dispatch expression bridge unified. `EventMetaExpressionLookup` is the single source of truth for non-`ctx` path resolution across templates, matchers, and harness validation; hook `when` clauses add `ctx.*` via the composite `EventMetaConditionLookup`. Templates gained fallbacks (`||`), ternaries, comparisons, and helpers (`length(...)`); matchers became `RuntimeMatcher::{Regex, Expression}`.
- **2026-04-26 — `2026-04-26-just-flow` (Phase 1)**: Package-local compose prompts added under `claudine/prompts/` (design, plan, phase implementation, commit, review) for the planned `just flow` lifecycle — distinct from repo-level `prompts/`.
- **2026-04-25 — `2026-04-25-agent-selection` (Phases 3-6)**: Composition provider/model resolution redesign. Removed the `SingleInstalled` auto-selection shortcut; TTY shows an interactive picker, non-TTY follows a strict resolution chain. Added the model catalog service (`~/.claudine/cache/models/<provider>.json`), wired the executor and sequence orchestrator through `ResolvedExecutionTarget`, and replaced `inquire` UI with `biscuit-tui`.
- **2026-04-18 — research refresh**: Claude `RateLimitStatus` naming drifted to `allowed` / `allowed_warning` / `rejected`. The Claude stream formatter still special-cases older `approaching_limit` / `limited` names — treat both schemes as version-sensitive.
- **2026-04-17 — `2026-04-17-cli-pre-processing`**: `argv::normalize` pre-parses argv before clap with four fixed-order syntactic rules (provider booleans → `--provider`, provider canonicalization, `--help` hoisting, `--` separator insertion). Reference: [CLI Pre-Parsing](cli-pre-parsing.md).
- **2026-04-16 — `2026-04-16-more-is-more`**: Non-interactive stderr strengthened. Tool calls render as `Name(summary)` / `←Name(slot)`; shell tools prepend the shell name; `flush_if_idle` flushes dangling paragraphs; OpenCode gained a typed `Reasoning` variant; `SemanticEvent::Error` gained a typed `kind: SemanticErrorKind`.
- **2026-04-16 — `2026-04-16-consistent-rendering`**: `compose` and `inline-compose` unified onto one non-harness `execute_without_harness` function plus a shared structured-stream helper and summary emitter (`defer_section_separator` selects immediate vs. deferred emission). **Superseded 2026-06-16 by `always-harness`, which removed `execute_without_harness` entirely and routed all runs through `run_harness_loop`.**
- **2026-04-14 — `2026-04-14-response-refinement`**: Live stderr surface gained the 9-section non-interactive model with strict spacing, the canonical `ToolCallDisplay` contract (`🔧 →` / `🔧 ←`, no raw JSON), the Gemini markdown-list fix, and OpenCode `--yolo` → `--dangerously-skip-permissions`.
- **2026-04-14 — `2026-04-14-more-meta-response` (Plan 1)**: `claudine handle` enforces a 5-second execution deadline (`CLAUDINE_HANDLE_DEADLINE_SECONDS`, exit 124) plus 3-second bash/messenger timeouts inside hook handlers, with phase-level tracing spans.
- **2026-04-11 — stream refactor**: Stream parsing moved onto strongly typed serde protocol models in `stream/protocol/` (one module per provider). All fields optional via `#[serde(default)]`, no `deny_unknown_fields`, unknown event types skip silently, field aliases resolved by helper methods, and `feed_line` uses two-pass dispatch (Value first, then typed enum).
- **2026-04-06 — Protect refactor**: `ProtectService` became a standalone regex-backed deny catalog — strict `Allow`/`Block`, no posture or severity model, no `PolicyEngine` dependency, per-group toggles plus command-only `custom_patterns`. Promoted to a top-level `protect` module on 2026-05-04. Reference: [Protect Service](protect-service.md).
