# Claudine Change Timeline

Condensed history of significant Claudine features and refactors, newest first. Each entry names the feature/fix slug and the durable takeaway; deep references live in the linked docs. For current behavior always trust [architecture.md](architecture.md), [cli-reference.md](cli-reference.md), and the repo `docs/topics/*` — this file is historical context, not a spec.

## 2026-10

- **2026-10-02 — `cli-switches` (type-aware ownership)**: Arguments after a composition file are owned per token from the compiled switch catalog, not by "first unowned switch starts the tail". The pre-clap partition now holds them as `ArgumentsAfterFile`; `compose::ownership::own_caller_arguments` reads the authored `$schema` names and literal `agent` once the file resolves and calls `composition::own_arguments`. A second bare word is an `argv` positional, not a multiple-file error; `argv` cannot be set by name. `check_launch_tail` re-checks the recorded `SwitchAssignment`s before every spawn. **Trap:** a switch typed differently by the provider a proxy, retry, or resume actually launches fails before that spawn, so a test that forwards `-c x=y` and then hands off to Claude now fails by design; forward a switch both read the same way (`--add-dir x`). See [Type-aware ownership](topics/argv-normalization.md#type-aware-ownership).
- **2026-10-01 — `remove-strict-mode`**: Expression lookup has one contract across Darkmatter and Claudine. (1) Darkmatter: `SubtreeStrictness`/`.strict()`/`validate_strict_roots` and `EvaluationLookup::is_known_variable_root` are gone, and a bare name never falls back to `ctx`. A root resolves reserved namespace (`doc`, `ctx`, `env`, `current`, `current_env`) → host global → document property; an absent property is `null`. Hosts declare globals in a `BindingView`, associate runtime entries with `EvaluationSession::associate` (reserved names, omissions, contradictions refused before any provider runs), check authored text passively with `prepare_value` + `validate_prepared` (every branch), and evaluate with `evaluate_prepared` / `SubtreeCompose::with_binding_view`. The advisory is `dm.expression.undeclared_property` (no alias for `unknown_identifier`). (2) Claudine: `lifecycle/bindings.rs` is the one catalog for `err`/`timing`/`group` (plus `outputs` at sequence approval) per `LifecycleScope`; `first_undefined_stack_variable`, `validate_no_undefined_lifecycle_variables`, `LifecycleUndefinedVariable`, and `LATE_BINDING_ROOTS` are deleted. `err` is an explicit `null` in `finalize`/teardown without a failure; `group` outside a group raises `claudine.outside-group`; every approval scope refuses `group`. The typed Darkmatter cause rides on `LifecycleErrorInfo::cause` (`CompositionError::lifecycle_cause()`), and setup/teardown run the bytes sequence approval fixed (`ApprovedCommand`). (3) DMLS classifies roots through `BindingView::baseline()` and reports unknown functions as the error `dm.expression.unknown_function`. (4) Shipped prompts dropped their `(x || false)` legality guards; a fallback now only chooses a default. **Trap:** don't reintroduce a root list or a lookup override to decide what a bare name means — declare a global in a view. See [Lifecycle § Binding Time](topics/flow-control/lifecycle.md#binding-time-early-vs-late) and Darkmatter's [Host Bindings](../../../darkmatter/docs/topics/darkmatter-expressions.md#host-bindings).

## 2026-09

- **2026-09-29 — `sequence-review-screen`**: The `sequence` provider review screen shows a row only for a step whose outer executable can launch a provider (`prompt`, `task`, `group`, body step); `shell` and `side_effect` steps get none. Classification is `sequence/review.rs::is_review_eligible` on the normalized step, never composition. Every step still gets a draft and a baseline target (`baseline_targets`, the former bypass closure); reviewed targets merge back by `step_index`, never by name or row number, and a wrong row count is an `InvalidData` error carrying `ReviewRowCountMismatch`, never a cancel or a partial merge. With no eligible step the table does not open and the pre-prompt message is not printed; the no-TTY gate still runs first. `Esc`/Ctrl+C on the screen now exit `130` (the old match on `ErrorKind::Other` + `"cancelled"` never fired). `live_targets` takes the review as a closure so the whole decision is unit-testable without `run_standalone`. In `biscuit-tui`, `InputTable` static columns now size to their widest row value, shrink through three allocation tiers, clip grapheme-safely with `…` at draw time only, and focus no longer underlines blank cells. See [sequence guide](../../../claudine/docs/cli/sequence.md#the-review-screen) and `biscuit-tui/docs/components/input_table.md#column-sizing`.
- **2026-09-28 — `edit-integration`**: `claudine <provider> --edit -i` works. (1) The clap `conflicts_with = "interactive"` on `WrapperArgs::edit` and the runtime edit/interactive branch in `validate_timeout_constraints` are gone: an edited prompt is `PromptSource::Inline`, exactly like a typed one, so plain `--edit` runs non-interactively and `--edit -i` makes the edited text the first turn of an interactive session. (2) `wrapper_stages::reject_interactive_timeouts` rejects `-i` with `--timeout`/`--step-timeout` at the end of Stage 2, before the editor opens; `validate_timeout_constraints(args, non_interactive_requested)` keeps only the post-edit rules. (3) Interactive startup delivery repaired: Goose `run --text <p> --interactive` (`run` first; `--text=` for a `-` prefix), Kilo `--prompt` (the TUI positional is a project path), Antigravity `--prompt-interactive` (was headless `--print`), Pi `-- <p>` (stdin forces print mode; needs Pi ≥ 0.84.3; a leading `@` gets a leading space). `profile/tests/positional.rs::every_provider_delivers_an_interactive_startup_prompt` pins every provider's interactive shape and forbids stdin/wire-RPC; native first- and second-turn real tests back it — `real/real_native_interactive_startup.rs` for Claude, Codex, Gemini, OpenCode, Qwen, Kilo, and Antigravity (Goose written but unverified, no host has it installed) and `real/real_pi_interactive_startup.rs` for Pi. Kimi Code still delivers an interactive startup prompt through `--prompt`, which runs one turn and exits; by the author's decision the fix waits on updated Kimi research and does not hold back this fix. The spawn-site guard now exempts `real_` files that build an emulator session.
- **2026-09-28 — `edit-integration` (wrapper `--`)**: The user's first `--` on a direct wrapper is now consumed as Claudine's boundary and no longer forwarded (it was kept in `child_args` whenever a positional prompt or unknown flag preceded it, so providers read the options after it as message text). The boundary is located from the raw process arguments; the args after it reach the provider as options and stay opaque to Claudine (a provider `--edit` there does not open the editor), and a later `--` is the provider's own. A `-`-prefixed first message after the boundary therefore needs a second `--` (`claudine opencode -- -- "- fix the bug"`). Pinned by `every_provider_receives_options_after_the_user_separator_as_options`, `profile_separator_before_a_dash_prompt_is_the_only_separator`, and the spawned L1 `wrapper_dry_run_forwards_the_tail_after_the_user_separator_without_it` across all ten providers.
- **2026-09-28 — `lifecycle-handoff-gaps` (prompt guide and PR flow, R6/R10)**: (1) A shell span that fails without a handler inside a transcluded file now fails the composition as it would inline (Darkmatter `transclusion_failure_is_fatal` + `MarkdownError::shell_span_failure`); only non-shell child failures still become a `_Could not transclude_` notice. That let `prompts/_pr/push.md` read its facts from the shared `_pr/_facts.md`. (2) `prompts/_prompt.md` finds this fix by directory name with the new Darkmatter `find_files(glob)` and reads it with `try_frontmatter(file)` (`{ok, value, error}`); a missing, ambiguous, or malformed spec renders a notice plus every warning, `status: completed` hides the section, and every finding id has a warning. (3) `prompts/_pr/open.md` fell through from its success item into its unconditional `error` once F4 made that `error` fail the process; it now `stop`s, and `shipped_prompt_contract` rejects the pattern corpus-wide. The whole PR flow is rehearsed at L1 (`pr_flow_rehearsal`) with a portable re-exec stub provider and a local bare remote.
- **2026-09-28 — `lifecycle-handoff-gaps` (shell result values, R9)**: A lifecycle step can read a command's result. (1) Darkmatter frontmatter `$( … )` gained `::ok` (bool), `::exit-code` (number, `null` on an allowed timeout), and `::result` (`{ok, code, stdout, stderr}`), parsed by one grammar (`frontmatter_shell_expansion/suffix.rs::parse_frontmatter_shell_suffixes`: at most one result suffix, no suffix twice, no trailing text) that execution, the leak guard, and DMLS share. Only an exit status becomes a value; a signal (including Ctrl+C, and Windows `STATUS_CONTROL_C_EXIT`) never does. The executor now returns a whole `ShellOutcome` for every shape (single, `&&`/`||` chain: last-ran status and joined streams; ternary literal: code `0`), and the per-compose cache stores that outcome, keyed on command + working directory + color env + timeout + timeout policy, in a once-cell per key so concurrent identical requests share one run. A value a result suffix typed is validated against `$schema` after expansion (`schema_validation::validate_typed_shell_values`); unsuffixed stdout keeps its existing contract. (2) Claudine: a top-level `set` value that is a whole-value `$( … )` (`ProxyWithValue::Shell`) has its bytes fixed at preparation (`preflight::resolve_set_shell_value` → Darkmatter `ResolvedShellValue`), is approved bare with the lifecycle shell commands, and runs through `ShellRunner::run_values` when its action executes, after expression values, in a fresh result cache, writing every destination or none. `initialize` refuses it in any item (`parse.rs::runs_a_shell`); `DisabledShellRunner` refuses it on early routes; a sequence task's `set` refuses it. **Trap:** a set shell value that was never stamped refuses to run rather than falling back to event-time interpolation, so any new path that builds a `LifecycleConfig` must go through `resolve_lifecycle_shell_commands`. See [Lifecycle § Reading a Command's Result](topics/flow-control/lifecycle.md#reading-a-commands-result).
- **2026-09-28 — `lifecycle-handoff-gaps` (per-run `ctx`)**: `ctx` is evaluated once for each composition run, not once per invocation. Git working state (the `Git` group — `branch`, `worktree`, `merge_conflicts` — plus `FileChanges` and `GitHistory`) moved off `RepositoryEntry` into `invocation_context::RunEvidence`, which every `DocumentEpoch` carries; launch identity, topology, host facts, languages, documents, and the environment stay invocation-scoped. Run boundaries: a document invoked or adopted, each retry/resume (the harness now installs the re-entered attempt's context on the lifecycle guard through `set_run_prepared_context`, generalized from the proxy-only setter), each loop iteration (`compose::prep` opens an epoch per iteration; `LoopIterationOutput::context` hands it to the gate), each sequence step (the step document, its task, and the task's prompt document share one run via `StepComposeContext::run_evidence` / `PromptTaskRequest::run_evidence`), each serial group member (`PromptTaskRunner::open_member_run`), and a parallel group as a whole (`open_group_run` captures the union of the siblings' requirements before any starts). `current` is memoized once per lifecycle event (`CurrentAuthority::memoized`, re-scoped by `StackExecutionContext::with_signal`). Darkmatter's `ContextRequirements::for_document` now walks frontmatter strings (`for_frontmatter`) and skips body code blocks the way body interpolation does. Volatile observations are counted apart (`volatile_observations`, `--perf` note). **Trap:** an invocation-level `capture_launch_context`/`extend_launch_context` is a run of its own and retains nothing; stages that must agree go through one epoch. See [Composition — Launch-Anchored Prepared Context](topics/composition.md#launch-anchored-prepared-context).
- **2026-09-28 — `lifecycle-handoff-gaps` (pre-flight parity)**: A shell command is approved with the bytes it executes. (1) Darkmatter's discovery walk (`preflight/collect.rs`) derives each local child's options with `transclusion::markdown_child_options` and the parent state with `pipeline::document_state_builder`, the functions composition uses, so a partial's `{{ base }}` resolves from a parent default, derived value, `proxy.with:` overlay, caller value, or directive `set.*` exactly as at execution (a parent default used to be invisible to discovery; the `proxy.with:` row broke the same way before the overlay moved into a data layer). (2) A value discovery cannot observe — a shell probe, `as_markdown`, a lazy `current.*`/`current_env.*` read, directly or through a frontmatter key (own or inherited) — makes the command a pre-flight `UnevaluatedDependencyShape`; a pending parent `$(…)` in a child command is `DynamicCommandShape`. (3) `MarkdownError::pre_approval_violation` finds `NotPreApproved` anywhere in a cause chain; the transclusion stage and `as_markdown` never tolerate it. (4) Claudine's eager audit, the sequence step's JIT audit (`sequence::jit::step_prepare_options`, one option set for audit and preparation), and every re-audit go through `prepare::approve_document_shell` → `canonical_compose_options`; each loop iteration audits its own template and lifecycle `shell` bytes (deny-only after iteration 1) — before, iteration 2+ ran re-stamped lifecycle commands no audit had seen. See [Pre-Flight Shell Approval](topics/pre-flight-checks.md).
- **2026-09-28 — `lifecycle-handoff-gaps` (terminal handoffs)**: A `proxy` from any event now reaches the coordinator that owns the document. `SingleCompositionOutcome::handoff` (was `initialize_handoff`) carries every route; `build_loop_iteration_output` copies it onto the iteration, so a looping source's `start`/`success`/`failure`/`finalize` proxy ends the loop and the target is adopted. A `prompt:` task now owns a per-task `RunLedger` and drives `sequence::iterate::run_step_proxy_loop` like a body step; both pass a `compose::prep::StepScope` (caller `LayeredOverrides` with data keys, the step's `RuntimeState`, output suppression, task bar, the step-owned env from `sequence::jit::step_owned_env` plus a task's `OPERATION`, and the task's `operation`) through `prepare_and_run_active_document`, so the target keeps the step's inputs and publishes into the step's `outputs`. **Trap:** the ledger records a hop when it is committed, and a terminal-route commit happens in the harness before the owner adopts it, so every consumer of `handoff` must adopt it; ignoring the field leaves a phantom chain entry that turns the next legitimate request into a false cycle. Only the direct provider wrappers remain unowned (`LifecycleProxyWithoutOwningCoordinator`). See [Composition — Command-level ownership](topics/composition.md#command-level-ownership).
- **2026-09-28 — `union-partial-file-completion`**: `claudine compose prompts/clarify.md spec=fix` now reaches the file chooser. (1) Root-union arm selection for supplied eager `file(match)` partials (`schema::supplied`) ignores problems on values that still need composition (`doc: "{{spec || design}}"`), using the same predicate as the pre-validator. (2) Ruling D1: when no single arm applies, completion still runs if every contending arm declares the property as the same eager `file(match)`; the chooser searches the de-duplicated union of their globs, and the picked path settles the arm. (3) A decidable input failure (zero matches, declined dialog, `Ctrl-C` in `Use this file?`) is reported before the provider picker, and the late verdict names the caller's launch directory (`rebase_caller_file_problems`). (4) The one-shot provider picker renders inline with a bounded height (`chooser_height`), never on the alternate screen. (5) Frontmatter excerpts are focused: ±`EXCERPT_CONTEXT_LINES` (3) plus enclosing headers, real line numbers (`CodeBlock::with_start_line`), `⋮` between regions, `$schema` declarations in every union arm, and no excerpt when nothing is locatable (`BlockOnly` removed). `biscuit-terminal` gained `SourceContext::focused_line_regions`, and Darkmatter gained `ShellExpansionError::origin()`. See [Composition § Partial files](topics/composition.md#provided-partial-file-references) and [§ Frontmatter YAML blocks in errors](topics/composition.md#frontmatter-yaml-blocks-in-errors).
- **2026-09-28 — `agent-text-is-data` (Phase 5)**: The inline closure persists agent frontmatter as data. Order: repair → `restore_properties_text` → encode → hash → one `atomic_write` (`composition/closure/persist.rs`). Repair quotes an agent-added/changed single-line plain top-level value YAML would misread (`title: "Fix: colons"`, `note: "see issue #42"`); encode replaces each agent-owned string holding `{{`/`$(` with a Darkmatter literal token, located in place by `darkmatter::markdown::hash::locate_frontmatter_leaves`. Unrepairable YAML, duplicate keys, and unlocatable owned values fail as `InlineAgentFrontmatterRejected` (`document.invalid_frontmatter`, line + agent attribution) and roll back. Lifecycle `set_`/`merge_`/`append_`/`prepend_frontmatter` writes pass the same gate (`closure::persisted_data`). Readers judge tokens by their text (`closure::stored_text`), and data is never "pending composition" in Claudine or Darkmatter schema checks. Guardrails gain the plain-scalar `#` rule. **Trap:** runtime modules (`sequence/`, `looping/`, `runtime_state.rs`) must not name `literal_token`; go through the closure helpers (`override_boundary_guard.rs`). User-visible consequences: a `sequence:` value that is a token is refused (`SequenceInvalid`); list items are owned by index, so inserting at the front of an authored list encodes shifted `{{ … }}` items; lifecycle frontmatter effects can no longer write a template into a file (an authored `{{{ x }}}` stores `{{ x }}` as data). See [Frontmatter Properties § Values an Agent Writes](topics/frontmatter-properties.md#values-an-agent-writes) (on-disk contract, hand-editing a token), [Composition § Inline](topics/composition.md#inline-composition), and [Lifecycle § Template text in a value is data](topics/flow-control/lifecycle.md#template-text-in-a-value-is-data-not-an-error).
- **2026-09-28 — `agent-text-is-data` (Phase 4)**: Run-produced values keep **data** origin into Darkmatter. `layered_set_overrides` now returns `LayeredOverrides` (values + data keys); only user setters are authored. Loop frontmatter/ambient values, `outputs`, lifecycle `set:`, evaluated task `params`, group `variables`, the step overlay, and the `proxy.with:` overlay (`PrepareOptions::proxy_overlay`, re-applied by the harness on retry/resume/adoption) are data, so agent text with `{{ … }}` or `$( … )` arrives byte-for-byte and asks for no approval. Loop action mixed-text results are no longer re-parsed as JSON. The lifecycle executor scans authored text once (`evaluate_operand`); the event-time `reject_surviving_spans` guard and `LifecycleEvaluationReason::SurvivingSpan` were deleted. Pre-flight-stamped shell commands carry `ShellAction::pre_resolved` and run as approved. A `proxy.with:` value for a lifecycle key still refuses template text. **Trap:** `CallerInputLayers` must never hold the per-document overlay — the sequence step overlay rides there and must survive an in-place proxy.
- **2026-09-27 — `lifecycle-message-exit-race`**: A `success`/`finalize` lifecycle `message` or a hook `message` under `claudine handle` could be silently lost. The send ran as a detached Tokio task, and every command then called `std::process::exit`, which killed the send in flight. (1) The library registers every message and desktop-notification send with one process-wide delivery tracker (`messaging::delivery::track`). A guard test forbids a bare spawn in `messaging/`, and embedders opt in with `drain_deliveries(deadline)`. (2) The CLI has one ordinary-exit path, `shutdown::finish(code)`. It drains for at most 10 s, or less under `handle`'s deadline, warns `… was still sending at exit; delivery is unknown`, flushes, and exits with the unchanged code inside the runtime. `exit_site_guard.rs` pins every other direct exit to an exact allowlist. (3) Ctrl+C keeps working during the drain: the compose guard is held until exit, and other commands get a drain ladder, so a second press exits `130`. The documented "3-second messenger timeout" never existed, and the `handle` default is 15 s, not 5 s. See [Messaging](topics/messaging.md#the-cli-drains-before-every-ordinary-exit) and [Signal Handling](topics/signal-handling.md#ctrlc-during-the-exit-drain).

- **2026-09-16 — `better-static-analysis`**: A `{{ … }}` span inside a quoted string literal on a **single-pass** lifecycle surface is now refused before any provider starts. The single-pass surfaces are whole-value communication fields, `when`/`while`/`until` predicates, stack action operands, and `proxy … with` values. The motivating incident was a `success.say` ternary whose else branch returned `"… {{ctx.repo_name}} …"`. The review ran to completion, and then the event crashed because the whole-value path never rescans a literal. The body and mixed frontmatter strings rescan, so the rule does not apply there. (1) Darkmatter owns the rule: `lint_expression` walks authored string tokens with the same `ExpressionFinder::find_all_plain` recognizer the runtime guard uses, and emits a proven-equivalent `+` rewrite. `is_whole_value_span` is the shared syntactic classifier. (2) Claudine's `validate_no_nested_spans_in_literals` runs in `prepare_direct`/`prepare_inline` right after the lifecycle parses, so direct/inline compose, dry-run, proxy targets, retry/resume, and loop seeds all fail before spawn. `sequence` pre-scans every statically resolved `prompt:` document right after building its preflight graph. It replaces the uncalled `validate_no_interpolation_leaks` and `LifecycleInterpolationLeak`, both deleted. (3) The event-time `reject_surviving_spans` backstop stays for template text that only appears at run time. It now carries a typed `LifecycleEvaluationReason::SurvivingSpan` and the property, and the renderer picks the `+`/`{{{ … }}}` hint from that type, never from message text. (4) DMLS emits `dm.expression.nested_span_in_literal` (ERROR) with a typed, versioned quick fix, descends into frontmatter sequences, and adopts a written severity ladder: a warning means the construct *might* be wrong, an error means it *will never work*. (5) `\{{` (odd backslash run) opts a span out of scanning, and compose preserves the backslash. **Trap:** a document loop stamps its lifecycle when the seed is prepared, so lifecycle edits made mid-loop never execute. See [Lifecycle — `LifecycleNestedSpanInLiteral`](topics/flow-control/lifecycle.md#lifecyclenestedspaninliteral) and the fix spec.

- **2026-09-12 — `shadow-home`**: Provider isolation no longer replaces the user's home. The old "shadow home" set child `HOME=~/.claudine` for `--repo`, Codex repository prompts, and Codex/Gemini `--mcp`, and fell back to `HOME=/dev/null` when the tree could not be built. Every nested tool inherited it: in the motivating incident `gh` lost its keyring account and `git verify-commit` could not find public keys, which looked like broken credentials. Now: (1) `InvocationContext` captures an immutable `HomeBaseline` and raw-`OsString` `EnvBaseline`; home variables reach the child unchanged and a debug spawn assertion rejects `/dev/null`, `NUL`, or an overlay path in any of them. (2) A typed `OverlayPlan` (lib `provider_overlay/`) replaces the `force_shadow_home`/`needs_shadow_home` booleans, driven by two new generated facts keys, `overlay_selector` (`env_var`, `shape`, `relocates`, `additive`, `source_root`) and `overlay_capabilities` (`native_root`/`composable_injection`/`unsupported` per `repo_resources`/`repo_prompt`/`mcp`). (3) The provider is redirected only through its own selector (`CLAUDE_CONFIG_DIR`, `CODEX_HOME`, `GEMINI_CLI_HOME` as a parent, `KIMI_CODE_HOME`, `PI_CODING_AGENT_DIR`, `QWEN_HOME`); each launch now builds into its own root under `~/.claudine/overlays/<slug>/`, removed when the launch ends after a guarded write-back of changed top-level mirrored files whose source did not change (so a rotated OAuth token survives; a lock-guarded sweep reclaims crashed launches without write-back), and the legacy `~/.claudine/<agent-offset>` storage is left untouched (review-1 finding 2: a reused root kept excluded and deleted entries and raced concurrent launches). (4) **Intentional tightening:** `--repo` is refused before spawn (`provider.overlay_unsupported`) for Antigravity (only lever is `HOME`), Goose (no single source root), and OpenCode/Kilo (additive config dirs); any build failure is `provider.overlay_failed` with no fallback, except a missing *default* source root, which builds an empty overlay. (5) `repo_home.rs` became `wrap/provider_overlay.rs`: entries are classified, live state is never mirrored, and native Windows copies recursively instead of hard-linking. Claude needs `CLAUDE_SECURESTORAGE_CONFIG_DIR` pinned (undocumented upstream) and `.claude.json` placed in the overlay; Codex keeps `CODEX_SQLITE_HOME`, now resolved from the baseline. (6) Proxy/retry/resume rebuilds restore the baseline's selector values before applying the target plan, and the session-compatibility key includes the overlay view (the per-launch root name is spelled `<overlay>`). The audit also found that runtime MCP injection had written to a doubly nested path and was a no-op for Codex and Gemini; that is fixed, and Kilo's published inline MCP verdict is now wired through `KILO_CONFIG_CONTENT` (it previously refused `--mcp`). See `docs/topics/repo-isolation.md`, [MCP Mode](topics/mcp-mode.md), and the fix's `audit.md`.

- **2026-09-08 — `frontmatter-matters`**: A document's frontmatter `model:` now always reaches the provider launch. Since the provider-metadata Phase F "staged demotion" (2026-07-06) made the compiled `expected_offerings` the validation baseline, `resolve_model_with_env` silently dropped any frontmatter model the baseline did not carry — for OpenCode that is every user-configured provider (`minimax/…`, `zai-coding-plan/…`), because the baseline is the 50 `opencode/*` aggregator ids — and the run fell through to the OpenCode-only `apply_opencode_model_resolution`, which read the legacy `~/.config/opencode/config.json`, exported that stale value as `MODEL`, and pushed no flag, so OpenCode ran its own default while `--dry-run` (which bypassed the catalog) claimed the document's model. Three changes, one rule: **one model path for every provider**. (1) The library chain forwards a frontmatter model unconditionally; the catalog only orders list hints. (2) One CLI helper, `wrap/composition/target.rs::resolve_document_model`, replaces seven hand-rolled resolution sites (eager/live/execute-time compose, sequence review and dry-run, the retry/resume rebuild); it owns the refresh gate and emits one `[model]` warning for a frontmatter model outside the provider's expected offerings (`--silent` suppresses; the rebuild never repeats it), and dry-run resolves with the compiled baseline so its `Model` row is the launch model. (3) The shared prep stage `exec_prep::resolve_model_and_validate` is provider-neutral: an explicit model goes through `profile.apply_model` for everyone; a provider whose catalog sets `model_required_in_non_tty` and has none gets the catalog's `model_env_vars` then the new `WrapperProfile::configured_default_model` hook (OpenCode reads `opencode.jsonc` / `opencode.json` / legacy `config.json`, JSONC-tolerant); `OpenCodeModelSource`/`OpenCodeEnvSnapshot` became the provider-neutral `ModelSource`. Frontmatter `yolo:` was deliberately left out for the permissions spec. See [Composition — Frontmatter `agent` and `model`](topics/composition.md#frontmatter-agent-and-model) and the spec.

- **2026-09-05 — `inline-flow-and-validations`**: Reversed four uncommunicated steps of drift that had turned `inline-compose` from "the agent updates this document" into "the agent answers a question and Claudine transcribes it". The agent is **file-aware** again: it receives the document's native absolute path (never JSON-escaped), a `$schema` property table when one is declared, and guardrails naming the three closure-owned properties (`prompt`, `hash`, `last_updated`); it writes the body and any requested frontmatter itself, and its final response is a two-to-three-paragraph **summary for the caller** that never enters the document. The response-block frontmatter channel, its allowlist, and the closure-local YAML node editor are all deleted — the closure now reads the file back and restores the owned nodes textually through Darkmatter's `restore_properties_text`. A failed verdict is ordinary `failure` recovery (`retry`/`resume`/`proxy`), but a validly written artifact is **kept** on a completion-schema failure while a provider failure, exit 130, or refused body atomically restores the operation-level baseline. `wrap::write_grant` launches every provider in the narrowest posture that can write the document and refuses an explicit deny before spawn rather than widening to a bypass.
