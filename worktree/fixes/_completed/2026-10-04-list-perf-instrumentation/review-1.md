The fix is **not production ready**. Library ownership, stage paths, Git counting, receipt capture, and JSON framing are implemented and have passing functional tests. The remaining problems concern the human report, exact numeric validation, and the disabled instrumentation path. None requires a human design decision.

## Findings

### High: The human performance report lacks real-terminal verification

**Defect class:** Tests inspect report data or generated bytes without verifying the new report's hierarchy and columns through a real terminal.

In `worktree-cli`, [the human/JSON feature test](../../cli/tests/perf_flag.rs:317) searches captured output for stage labels. [The renderer tests](../../cli/src/perf/tests.rs:130) inspect `MetricNode` shares before the terminal component renders them. Both are Level 1. The latter passes despite the worker heading actually displaying `100%`, demonstrating why the distinction matters.

The following sweep covers all report-producing test paths and the existing real-terminal suites:

| Site | Shape tested or coverage inspected | Observed result | Expected result |
| --- | --- | --- | --- |
| `perf_flag` subprocess tests | Human output, JSON framing, stage agreement, errors, disabled flag | Level 1 checks execute and pass | Appropriate for framing and channels; insufficient for terminal layout |
| `perf_flag::a_pseudo_terminal_capture_ends_in_the_record` | `script` pseudo-terminal with JSON output | Level 1; verifies CRLF framing | Appropriate for JSON transport; does not verify human rendering |
| `perf::tests` | Synthetic sequential/concurrent trees, remainder thresholds, worker shares | Level 1; checks data and rendered strings | Keep these checks and add real-terminal assertions |
| `perf_graph_stages` | Graph timing paths in manufactured terminal captures | Performance evidence, rather than a real-terminal human-report assertion | Keep timing checks; add human-report coverage separately |
| `level2_list_verbose`, `level2_graph_in_kitty`, other area Level 2 tests | Existing listing, graph, and spinner rendering | All 39 pass; none invokes the new performance report | A report test must actually pass `--perf` and capture its rendered output |

Add a Level 2 test through the existing harness, without gaining focus, that captures `wt list --perf` for a local-origin fixture. Verify the diagnostic heading, hierarchy, Git-count suffixes, sequential versus concurrent shares, and readable alignment at representative widths. Use Level 1 synthetic trees for deterministic sub-millisecond and over-attribution cases. There is no new keyboard behavior, so Level 3 is unnecessary.

### Medium: Worker diagnostics lose share and reconciliation semantics when rendered

**Defect class:** The worker-report projection does not preserve the timing model's percentage and remainder rules.

In `worktree-cli`, [human_report](../../cli/src/perf.rs:46) renders the worker section as a separate `MetricsTree`. The `biscuit-terminal` package's [root-row rendering](../../../biscuit-terminal/lib/src/components/metrics_tree.rs:467) forces its root to `100%`, ignoring `MetricShare::Unknown`. Separately, [unshared](../../cli/src/perf.rs:138), which converts every nested worker span into a display row, never generates reconciliation rows. It therefore hides worker-half bookkeeping gaps and even synthetic over-attribution, despite the requirement to always show the latter.

Reproduction: initialize a repository with one commit, clone it to a local bare origin, fetch its tracking ref, and run the built `wt list --perf=human` and `wt list --perf=json`. No external network is involved. In the captured human run, the worker heading ends in `100%`; `default-branch refresh` is 57.6 ms and its only child, `head check`, is 26.3 ms, with no `unattributed` row for the approximately 31.3 ms difference. Exact values vary; the omitted row does not depend on speed.

| Site | Shape tested | Observed result | Expected result |
| --- | --- | --- | --- |
| Foreground root and sequential spans (`report_tree`, `span_node`) | Sequential remainder and synthetic excess | Remainder threshold and excess handled; existing tests pass | Clean |
| Foreground concurrent spans (`span_node`) | Overlapping children | No child shares or sum-based remainder | Clean |
| Worker diagnostic heading (`human_report`) | Complete local-origin report; synthetic renderings of all six statuses | Heading displays `100%` | No percentage on diagnostic headings |
| Owned launch rows (`worker_tree`) | Available, missing, invalid reports | No percentage; root remainder is generated for available reports | Clean |
| Nested worker sequential spans (`unshared`) | Both PR/head halves with 40 ms parents and 20 ms children, then 10 ms parents and 20 ms children | Remainder/excess rows omitted | Hide only remainders below 1 ms; always show excess, without shares |
| Nested worker concurrent spans (`unshared`) | Concurrent worker halves | No percentage and no sum-based remainder | Clean |

Make the root-share behavior configurable or choose a component layout that respects the unknown share. Reuse the foreground remainder logic for sequential worker parents, while preserving unknown shares on all worker rows. Add assertions against the final rendered report, including both worker halves and nested over-attribution. The implementation log already identifies the heading issue; the missing nested rows are an additional instance of the same projection defect.

### Medium: Saturated arithmetic accepts timing documents that do not reconcile

**Defect class:** Numeric validation compares against a clamped remainder instead of requiring the exact reconciliation equation.

In the `worktree` package, [reconcile](../../lib/src/timing.rs:737) sums in `u128` but clamps a remainder above `u64::MAX` back to `u64::MAX`. Both [root decoding](../../lib/src/timing.rs:882) and [nested-span decoding](../../lib/src/timing.rs:907) use that result to validate input. Two child durations of `u64::MAX`, a small parent duration, and `over_attributed_us: u64::MAX` are accepted even though their equation is false. These are extreme inputs, not realistic runtime durations, but rejecting inconsistent documents is an explicit public decoder contract.

A temporary nextest integration probe copied the JSON produced by the local-origin CLI fixture above, verified its unedited command and worker documents decoded, and modified durations and remainder fields. It exercised the public APIs, not private parsing helpers. The probe was removed after reproducing the defect.

| Site | Shape tested | Observed result | Expected result |
| --- | --- | --- | --- |
| [Timings::from_json](../../lib/src/timing.rs:490), command root | Multiple child durations set to `u64::MAX`; excess set to the saturated maximum | Accepted despite a false equation | Reject inconsistent document |
| [Timings::from_json](../../lib/src/timing.rs:490), sequential `refresh_worker` | Both child durations at the maximum; parent unchanged; saturated excess | Accepted | Reject |
| [WorkerTimings::from_json](../../lib/src/timing.rs:599), worker root | Both top-level durations at the maximum; saturated excess | Accepted | Reject |
| [WorkerTimings::from_json](../../lib/src/timing.rs:599), sequential head half | Distinct check/fetch children at the maximum; saturated excess | Accepted | Reject |
| [load_receipt](../../lib/src/remote_head.rs:785), optional `durations` | Worker document with saturated root excess | Outcome retained, timings accepted as partial | Retain outcome; mark timings invalid |
| Command-embedded worker report (`decode_report`) | Saturated worker root, launch and summary set to partial | Accepted | Reject command document |
| Concurrent-parent validation | Large overlapping children, zero remainder fields | Children excluded from reconciliation by design | Clean; do not reject merely because concurrent durations sum above the parent |
| Both document serializers | Public timing trees whose exact excess exceeds the wire integer range | Use the same saturating helper | Do not produce a document presented as exactly reconciled |

The applicable input-matrix rows were also inspected in [the command decoder matrix](../../lib/src/timing/tests.rs:408) and [the receipt matrix](../../lib/src/remote_head.rs:2009); both passed in this review. For `total_us`, `elapsed_us`, `unattributed_us`, and `over_attributed_us`, absent, null, wrong whole-field types, negative/fractional values, and duplicate keys are rejected. Element-shape cases do not apply to these scalar fields; empty collections are wrong types. Trailing content is rejected. Ordinary inconsistent numeric values are rejected. The missing boundary is valid unsigned values whose combined excess cannot fit in the wire field. The command decoder's synthetic matrix does not exercise that boundary through either worker decoder path.

Validate the equation using checked/wide arithmetic before converting the remainder to its wire type. Reject an unrepresentable exact remainder rather than comparing against its saturated substitute. Extend both format matrices with this boundary and ensure invalid optional worker timings continue to preserve receipt outcomes. Also define how public construction/serialization handles unrepresentable durations and remainders instead of silently clamping them.

### Low: Disabled worker instrumentation still reads a stage clock

**Defect class:** A timing-only clock read happens before the disabled-instrumentation guard.

In `worktree-cli`, [run_and_record](../../cli/src/commands/refresh_worker.rs:207), which runs the worker halves and writes their receipt, calls `Instant::now()` for `halves_started` even when `clock` is `None`. Its value is used only inside the enabled timing branch. Ordinary listings launch this worker with timings disabled, so they still pay for this instrumentation clock read. The cost is small, but the spec explicitly requires no per-stage clock reads when instrumentation is disabled.

The sweep distinguished instrumentation reads from clocks needed to enforce existing deadlines:

| Site | Disabled shape checked | Observed result | Expected result |
| --- | --- | --- | --- |
| Library pipeline and graph (`record`, `record_parent`, `gather`) | `ListOptions.timings: false` | Timing clocks/scopes bypassed; enabled/disabled functional-equivalence tests pass | Clean |
| Foreground launch timing (`LaunchClock::launch`) | `timed: false` | Returns before reading clock | Clean |
| CLI rendering (`perf::time`) | No timing list | Executes rendering without a stage clock | Clean |
| Worker entry and individual halves (`run`, `timed_half`, operation wrappers) | No timing request | Clock and span allocation guarded | Clean |
| Worker concurrent-halves envelope (`run_and_record`) | `clock: None` | Unconditional `Instant::now()` | Guard this read too |
| Worker head deadline and foreground wait clocks | Timings disabled | Still run to enforce functional budgets | Clean; these are required behavior, not instrumentation |

Plain CLI output and the existing untimed-worker tests confirm that disabled runs emit no timing report; the clock-read defect itself is established by the unconditional call, because the production clock has no injectable observation seam. Use `timed.then(Instant::now)` or an equivalent guard; no new clock abstraction is necessary.
