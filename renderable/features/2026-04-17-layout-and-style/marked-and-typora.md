# Theme systems in Marked and Typora

## Marked

**How themes are defined** – Marked is a preview and export tool for Markdown. Each theme in Marked is a CSS file that styles the HTML representation of the Markdown document. Themes are either **built‑in** or **custom**. When a custom stylesheet (a `.css` file) is imported through the *Style* pane of Marked’s settings or dragged into the Style Manager, Marked adds it to the styles menu and associates it with a keyboard shortcut [oai_citation:0‡markedapp.com](https://markedapp.com/help/Custom_Styles.html#:~:text=). Custom styles are stored on disk (so you can edit them in any text editor) and can be enabled/disabled or renamed via the **Style Manager** [oai_citation:1‡markedapp.com](https://markedapp.com/help/Style_Manager.html#:~:text=Opening%20the%20Style%C2%A0Manager). Marked never modifies built‑in themes; the recommended approach is to duplicate a built‑in theme and edit the copy [oai_citation:2‡markedapp.com](https://markedapp.com/help/Style_Manager.html#:~:text=Edit%3A%20Opens%20the%20CSS%20file,to%20create%20an%20editable%20copy).

**Metadata in CSS files** – Marked expects each custom theme to start with a metadata comment. A skeleton theme provided by the developer includes a header containing *Title*, *Author*, *Description*, and optional fields such as non‑standard fonts and notes [oai_citation:3‡github.com](https://github.com/ttscoff/MarkedCustomStyles/blob/master/Custom.css#:~:text=). When a theme is created using Marked’s web‑based **Custom Style Generator**, the generator prompts for the author, author URL and description; this metadata is inserted into the CSS header [oai_citation:4‡markedapp.com](https://markedapp.com/help/Custom_Style_Generator.html#:~:text=Metadata). The metadata is used by Marked’s theme gallery and helps identify the style within the app.

**Custom style rules** – Marked uses a WebKit WebView to render previews. The body of the document is wrapped in a `div` with the id `#wrapper` [oai_citation:5‡markedapp.com](https://markedapp.com/help/Custom_Styles.html#:~:text=window%20where%20you%20can%20add,g). Custom CSS should generally target elements inside `#wrapper` to override Marked’s defaults. Marked defines a few **body classes** that themes should handle:

* **`inverted`** – When the user enables dark preview, the body gets the class `inverted`. Themes should provide dark‑mode overrides inside `@media screen` to avoid affecting print styles [oai_citation:6‡markedapp.com](https://markedapp.com/help/Writing_Custom_CSS.html#:~:text=Inverted). A typical dark‑mode snippet sets the background and text colours for `.inverted` and `.inverted #wrapper` [oai_citation:7‡markedapp.com](https://markedapp.com/help/Writing_Custom_CSS.html#:~:text=Inverted).

* **`poetry`** – If the user chooses *poetry mode*, tab‑indented text is treated like poetry. When the body has class `poetry`, code blocks inside `pre` should be styled more poetically; the documentation suggests customizing the `pre code` font family, weight and margins [oai_citation:8‡markedapp.com](https://markedapp.com/help/Writing_Custom_CSS.html#:~:text=Poetry).

Marked’s documentation also advises theme authors to pay attention to **tables**, **figures/figcaption** and **footnotes** because these elements appear differently in the default themes; it provides example CSS for superscript footnote markers and footnotes container [oai_citation:9‡markedapp.com](https://markedapp.com/help/Writing_Custom_CSS.html#:~:text=Tables%2C%20Figure%2FFigcaption%2C%20and%20the%20special,what%20CSS%20rules%20Marked%20needs). To prevent images from overflowing the page, authors should set `max-width: 100%` on `#wrapper img` [oai_citation:10‡markedapp.com](https://markedapp.com/help/Writing_Custom_CSS.html#:~:text=It%E2%80%99s%20also%20a%20good%20idea,Something%20like).

**Print and PDF export** – Marked injects its own `@media print` rules (`mkprintstyles`) that set a base font size and normalize paragraph text. Theme authors can override these print defaults by defining rules inside `@media print` and using `!important` when necessary [oai_citation:11‡markedapp.com](https://markedapp.com/help/Custom_Styles.html#:~:text=Marked%20injects%20a%20built,in%20PDFs%20and%20printed%20output). Print styles ensure that background colours and screen‑only effects (such as fixed scrolling) are removed when exporting to PDF [oai_citation:12‡markedapp.com](https://markedapp.com/help/Custom_Styles.html#:~:text=Print%20and%C2%A0PDF%C2%A0export).

**Applying additional CSS globally** – Users can append universal CSS rules via the **Additional CSS** field in Marked’s Style pane [oai_citation:13‡markedapp.com](https://markedapp.com/help/Custom_Styles.html#:~:text=Additional%C2%A0CSS). These rules are applied after the selected style and apply to every document. For example, the documentation shows how to set all images inside `#wrapper` to full width [oai_citation:14‡markedapp.com](https://markedapp.com/help/Custom_Styles.html#:~:text=window%20where%20you%20can%20add,g). The Additional CSS field is helpful for overriding specific rules without editing individual themes.

**Style Manager and live preview** – Marked’s Style Manager displays all installed styles (built‑in and custom) in a sortable table. Authors can enable/disable a style, rename it, duplicate it, reveal it in Finder or delete it [oai_citation:15‡markedapp.com](https://markedapp.com/help/Style_Manager.html#:~:text=The%20Style%20Manager%20displays%20all,the%20table%20contains%20several%20columns). Rows can be reordered; the order controls the style menu and the keyboard shortcuts (`⌘1`–`⌘0`) [oai_citation:16‡markedapp.com](https://markedapp.com/help/Style_Manager.html#:~:text=Reordering%C2%A0Styles). The right side of the Style Manager shows a **live preview** of the selected style applied to a sample document. This preview updates instantly as the author edits the CSS file, and includes a checkbox to toggle dark‑mode preview [oai_citation:17‡markedapp.com](https://markedapp.com/help/Style_Manager.html#:~:text=Live%C2%A0Preview).

**Style Generator and Style Stealer** – Marked includes a **Custom Style Generator** that provides a visual interface for adjusting typography, colours and spacing. It generates CSS and can insert metadata automatically [oai_citation:18‡markedapp.com](https://markedapp.com/help/Custom_Style_Generator.html#:~:text=Metadata). A **Style Stealer** tool lets users extract CSS from any website; it captures typography, layout, interactive elements and pseudo‑selectors. The extracted styles can be saved as a new custom style [oai_citation:19‡markedapp.com](https://markedapp.com/help/Style_Stealer.html#:~:text=The%20Style%20Stealer%20is%20a,It%E2%80%99s%20perfect%20for). The tool filters out default browser styles and extraneous rules and supports dark‑theme extraction [oai_citation:20‡markedapp.com](https://markedapp.com/help/Style_Stealer.html#:~:text=,bold%2C%20italic%2C%20etc).

**Watching CSS changes** – In the Custom Styles section of Marked’s Style pane, a checkbox allows Marked to watch the active CSS file. When changes are detected, the preview automatically refreshes [oai_citation:21‡markedapp.com](https://markedapp.com/help/Custom_Styles.html#:~:text=Watching%20CSS%C2%A0changes). This feature lets authors edit CSS in an external editor and see updates immediately.

## Typora

**How themes are defined** – Typora is a hybrid Markdown editor and previewer. Its entire interface (the writing area, file list, sidebars, dialogs and menus) is rendered using WebKit on macOS and Chromium on Windows/Linux. Every theme is a single `.css` file stored in Typora’s **theme folder**; the file name must be lowercase and use hyphens instead of spaces [oai_citation:22‡support.typora.io](https://support.typora.io/About-Themes/#:~:text=Naming%20Rule). Typora exposes six built‑in themes and allows users to download or create custom themes [oai_citation:23‡support.typora.io](https://support.typora.io/About-Themes/#:~:text=Change%20Themes). Separate themes can be selected for light mode and dark mode, or a single responsive theme can be created with a `prefers‑color‑scheme` media query [oai_citation:24‡support.typora.io](https://support.typora.io/About-Themes/#:~:text=Use%20Themes%20Under%20Light%20Mode,and%20Dark%20Mode).

**Installing and overriding themes** – The theme folder can be opened from the *Appearance* section of Typora’s preferences. To install a custom theme, you copy the `.css` file and any resources (fonts, images) into this folder and restart Typora [oai_citation:25‡support.typora.io](https://support.typora.io/About-Themes/#:~:text=1,menu). Typora loads CSS in a specific order: its own base styles, the current theme’s CSS, then `base.user.css` (global overrides) and finally `{theme}.user.css` (per‑theme overrides) [oai_citation:26‡support.typora.io](https://support.typora.io/Add-Custom-CSS/#:~:text=Append%20Custom%20CSS%20to%20all,themes%20or%20other%20themes). Authors are advised to **avoid editing the built‑in theme file directly** because updates may overwrite customizations; instead, modifications should go into `base.user.css` or a per‑theme `.user.css` file [oai_citation:27‡support.typora.io](https://support.typora.io/Add-Custom-CSS/#:~:text=style%20will%20still%20be%20loaded,and%20applied).

**Writing a custom theme** – To create a theme, authors create a CSS file with a valid name and place it in the theme folder [oai_citation:28‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=If%20you%20want%20to%20write,you%20need%20to%20do%20is). Typora encourages the use of **CSS variables** to define fonts, colours and other properties; for example, the documentation lists variables like `--bg‑color`, `--text‑color`, `--meta‑content‑color` and `--primary‑color` in the `:root` selector [oai_citation:29‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=%3Aroot%20%7B%20,link%20address%20in%20markdown). Overriding these variables simplifies theme maintenance and makes it easier to support dark mode [oai_citation:30‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=Overwriting%20existing%20CSS%20Variables%20is,Common%20used%20ones%20are). Typora provides a **toolkit** containing templates and a LESS file for starting a theme from scratch [oai_citation:31‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=We%20prepared%20a%20toolkit%20for,or%20to%20do%20simple%20testing). Authors can also convert existing website CSS and then add styles for elements not covered by the original design (e.g., table of contents or dialogs) [oai_citation:32‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=If%20you%20want%20to%20convert,%E2%80%9Ctoc%E2%80%9D%20or%20for%20UI%20components).

**Selecting the right CSS selectors** – The HTML generated by Typora uses semantic tags wherever possible. The writing area is a `div` with id `#write`; authors should target `html` or `#write` to set general properties like font, background, margins and padding [oai_citation:33‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=General). Since headings, paragraphs, lists, tables and blockquotes are rendered with standard tags (`<h1>`–`<h6>`, `<p>`, `<ul>`, `<table>`, etc.), theme designers can style these tags directly [oai_citation:34‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=Typora%20will%20try%20to%20render,part%20or%20do%20some%20adjustment). For more precise control, Typora annotates block elements with an `mdtype` attribute. For example, `[mdtype="heading"]`, `[mdtype="blockquote"]`, `[mdtype="fences"]`, `[mdtype="toc"]`, etc., can be used as selectors [oai_citation:35‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=Aslo%2C%20all%20block%20elements%20has,cases%2C%20tag%20selector%20is%20enough). Inline elements (bold, italic, code, footnote markers, etc.) are wrapped in a `span` with an `md-inline` attribute indicating the type (e.g., `md-inline="strong"` or `md-inline="footnote"`) [oai_citation:36‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=An%20inline%20elements%20usually%20includes,will%20be%20rendered%20as); authors can style these wrappers or the inner tags to control meta characters and inline formatting.

**Using media queries and print styles** – Typora themes can be responsive. On macOS and Windows, users can assign separate themes for light and dark modes [oai_citation:37‡support.typora.io](https://support.typora.io/About-Themes/#:~:text=Use%20Themes%20Under%20Light%20Mode,and%20Dark%20Mode) or write responsive themes using `@media (prefers-color-scheme: dark)`. CSS variables simplify colour switching [oai_citation:38‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=Overwriting%20existing%20CSS%20Variables%20is,Common%20used%20ones%20are). For printed output and PDF export, Typora applies print styles if CSS is enclosed in `@media print` and targets `.typora-export` or global selectors. The documentation shows an example where `-webkit-print-color-adjust: exact` is set for printed output [oai_citation:39‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=Print).

**Custom fonts and resources** – Fonts in Typora are specified using CSS. A base rule such as `body { font-family: Courier; }` placed in `base.user.css` overrides the theme’s font family [oai_citation:40‡support.typora.io](https://support.typora.io/Custom-Font/#:~:text=Custom%20fonts%20in%20Typora%20are,under%20theme%20folder). Web fonts can be imported with `@import` or embedded via `@font-face` definitions inside the theme file [oai_citation:41‡support.typora.io](https://support.typora.io/Custom-Font/#:~:text=%40import%20url%28https%3A%2F%2Ffonts). Typora recommends using `rem` units for font sizes so that the *Font Size* preference in the application still works [oai_citation:42‡support.typora.io](https://support.typora.io/Custom-Font/#:~:text=A%20quicker%20way%20to%20change,for%20it%20in%20preferences%20panel).

**Additional UI and behaviour** – Because Typora’s themes style the entire webview, they can affect not only the Markdown content but also the **UI elements** such as the sidebar, file tree, dialogs and focus mode. The documentation lists CSS variables for UI backgrounds, active file backgrounds, hover colours and primary button colours [oai_citation:43‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=%3Aroot%20%7B%20,link%20address%20in%20markdown). Authors can use these variables to change the appearance of sidebars and the active file row, or apply custom widths and colours to the writing area [oai_citation:44‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=General). However, Typora warns that certain CSS properties may break the editor (e.g., setting `white-space: pre-wrap` on `#write` prevents the Tab key from working) and recommends minimal changes to avoid interfering with functionality [oai_citation:45‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=You%20could%20limit%20,as%20possible%2C%20test%20it%20out).

**Debugging and testing** – Typora includes a debug mode that enables Chrome/Safari DevTools. On macOS, authors choose *Help → Enable Debug*, then right‑click and choose *Inspect*; on Windows/Linux, DevTools is available under *View → Toggle DevTools* [oai_citation:46‡support.typora.io](https://support.typora.io/Add-Custom-CSS/#:~:text=Debug%20CSS). The official toolkit also provides HTML files for previewing themes in a browser [oai_citation:47‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=Debug%20and%20Test).

## Summary of differences

| Aspect | **Marked** | **Typora** |
|---|---|---|
| **Theme format & naming** | One CSS file per theme; metadata comment with *Title*, *Author* and *Description* at top of file [oai_citation:48‡github.com](https://github.com/ttscoff/MarkedCustomStyles/blob/master/Custom.css#:~:text=). Names shown in menus come from the metadata or file name and can be edited in the Style Manager [oai_citation:49‡markedapp.com](https://markedapp.com/help/Style_Manager.html#:~:text=Name%C2%A0Column). | One CSS file per theme stored in the theme folder; file name must be lowercase and use hyphens (e.g., `my-first-theme.css`) [oai_citation:50‡support.typora.io](https://support.typora.io/About-Themes/#:~:text=Naming%20Rule). Typora derives the label from the file name. There is no metadata header. |
| **Scope of styling** | Styles only affect the rendered Markdown preview inside the `#wrapper` div. The application UI (window frame, menus, buttons) remains native. Styles must handle body classes such as `inverted` (dark mode) and `poetry` [oai_citation:51‡markedapp.com](https://markedapp.com/help/Writing_Custom_CSS.html#:~:text=Inverted). | Styles affect the entire Typora webview, including the writing area and UI components (sidebar, file list, dialogs). Authors can use CSS variables and selectors like `#write`, `[mdtype]` and `[md-inline]` to style content and UI [oai_citation:52‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=General) [oai_citation:53‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=An%20inline%20elements%20usually%20includes,will%20be%20rendered%20as). |
| **Dark‑mode support** | Dark preview is indicated by the `inverted` class on `<body>`. Theme authors need to add `@media screen` rules for `.inverted` to ensure dark styles do not affect print [oai_citation:54‡markedapp.com](https://markedapp.com/help/Writing_Custom_CSS.html#:~:text=Inverted). | Users can select different themes for light and dark modes [oai_citation:55‡support.typora.io](https://support.typora.io/About-Themes/#:~:text=Use%20Themes%20Under%20Light%20Mode,and%20Dark%20Mode) or write responsive themes using `@media (prefers-color-scheme: dark)`. CSS variables simplify colour switching [oai_citation:56‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=Overwriting%20existing%20CSS%20Variables%20is,Common%20used%20ones%20are). |
| **Global overrides & user customisation** | Marked provides an **Additional CSS** field in the Style pane that appends CSS to every document [oai_citation:57‡markedapp.com](https://markedapp.com/help/Custom_Styles.html#:~:text=Additional%C2%A0CSS). Style watching automatically updates the preview when the CSS file changes [oai_citation:58‡markedapp.com](https://markedapp.com/help/Custom_Styles.html#:~:text=Watching%20CSS%C2%A0changes). | Typora loads styles in the order: base styles, current theme, `base.user.css` (global overrides) and `{theme}.user.css` (per‑theme overrides) [oai_citation:59‡support.typora.io](https://support.typora.io/Add-Custom-CSS/#:~:text=Append%20Custom%20CSS%20to%20all,themes%20or%20other%20themes). Users can customise fonts, spacing, colours or width by editing these `.user.css` files. |
| **Theme management** | The **Style Manager** offers a UI to enable/disable styles, rename them, reorder them (affecting keyboard shortcuts), duplicate built‑in styles and view a live preview with dark‑mode toggle [oai_citation:60‡markedapp.com](https://markedapp.com/help/Style_Manager.html#:~:text=The%20Style%20Manager%20displays%20all,the%20table%20contains%20several%20columns). | Typora has no built‑in theme manager. Themes are selected via the Themes menu. Installing, removing or renaming themes is done by manipulating files in the theme folder. Global and per‑theme customisations use `.user.css` files [oai_citation:61‡support.typora.io](https://support.typora.io/About-Themes/#:~:text=1,menu) [oai_citation:62‡support.typora.io](https://support.typora.io/Add-Custom-CSS/#:~:text=Append%20Custom%20CSS%20to%20all,themes%20or%20other%20themes). |
| **Tools for creating themes** | Marked offers a **Custom Style Generator**, a visual design tool that adjusts typography, colours and spacing and inserts metadata [oai_citation:63‡markedapp.com](https://markedapp.com/help/Custom_Style_Generator.html#:~:text=Metadata). It also has a **Style Stealer** that extracts CSS from any website into a theme [oai_citation:64‡markedapp.com](https://markedapp.com/help/Style_Stealer.html#:~:text=The%20Style%20Stealer%20is%20a,It%E2%80%99s%20perfect%20for). | Typora provides a **toolkit** with templates and example HTML files for testing themes in a browser [oai_citation:65‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=We%20prepared%20a%20toolkit%20for,or%20to%20do%20simple%20testing) [oai_citation:66‡theme.typora.io](https://theme.typora.io/doc/Write-Custom-Theme/#:~:text=Debug%20and%20Test). ## Conclusion

Both Marked and Typora allow users to customise the look and feel of Markdown documents through themes, but their theme systems serve different purposes and offer different capabilities. **Marked** is a preview tool whose themes focus on styling the rendered Markdown; it uses a metadata‑rich CSS format, provides tools like a visual style generator and a style stealer, and includes a live preview with dark‑mode switching. **Typora** is a full‑fledged editor whose themes style the entire editing environment; themes are pure CSS files placed in a special folder, use CSS variables extensively and rely on semantic selectors (`#write`, `[mdtype]`) rather than metadata. Typora’s system gives theme authors more control over UI elements but requires caution to avoid breaking editor functionality. Understanding these differences helps developers choose the right approach when designing or customising themes for each application.
