# Unified Events Refactor Plan (Claudine Library)

## Design Authority Rule

This refactor is **design-led**. When code and design disagree:

1. `claudine/docs/unified-events.md` wins.
2. Existing behavior is treated as migration debt.
3. Compatibility shims are temporary and must not redefine canonical runtime types.

## Scope

Implement the unified-events target architecture in `claudine/lib`, including:

- Canonical unified types (`AgenticEvent`, `Provider`, `ResolvedHook`, `HookAction`, `Mapper`, `HookResponse`, `HookDecision`)
- Full `ProviderAdapter` contract (`parse_event`, `can_block`, `format_response`, `exit_code`)
- Dispatch/action pipeline with response propagation for blocking events
- Handlebars-style templating semantics and migration behavior
- Canonical config loading/validation for unified actions
- Provider coverage expanded to 8 providers (including Roo Code)

Out of primary scope but required for repository health:

- Downstream `claudine-cli` compile updates for renamed/changed public library types
- External config migration command (library must remain canonical-only)

## Baseline (Before Refactor)

- Baseline test status: `cargo test -p claudine` passes (293 unit tests + doctests) on current code.
- Current implementation gaps versus design are structural, not just behavioral.

## Critical Gap Matrix (Implementation vs Design)

| Area | Current Implementation | Design Target | Required Refactor Outcome |
|---|---|---|---|
| Provider set | 7 providers in `claudine/lib/src/events/provider.rs` | 8 providers including `RooCode` | Add `Provider::RooCode` end-to-end (types, adapters, support tables, detection) |
| Unified hook representation | No `ResolvedHook` type | `ResolvedHook` is canonical unified hook output | Introduce `ResolvedHook` and drive dispatch on it |
| Adapter trait | `parse_event` only, returns `Option`, adapter factory returns `Box`, several `unimplemented!` | Rich trait with parse + block + response conversion + exit code, static adapters | Redesign trait and eliminate runtime panics/unimplemented adapters |
| Action model | `EventAction` + `Run { blocking }` | Canonical `HookAction` with `FireAndForget` and `Call` split | Replace runtime action model; move legacy migration out of runtime |
| Response flow | No unified `HookResponse` path from actions to adapters | Blocking-aware response round-trip | Implement response conversion pipeline and exit-code routing |
| Mapper support | No `Mapper`/`CompiledMapper` | `ExitCode`, `JsonField`, `JsonObject`, `Regex` mappers | Implement mapper engine + compile-time validation for regex |
| Template syntax | Single-brace interpolation (`{tool_name}`) in `dispatch/template.rs` | Handlebars-style (`{{tool_name}}`) + env fallback syntax | Replace templating engine semantics; keep transitional rewrite warnings |
| Matcher compilation | Regex compiled per event in `dispatch/matcher.rs` | Compile during config load | Precompile and store matcher/mapper runtime forms |
| Non-hook provider adapters | Goose/Kimi/Qwen adapter lookup panics | Adapters for all providers | Implement parser coverage and graceful non-blocking behavior |
| Duplicate mapping sources | Mapping logic split across `events/provider.rs`, `config/*`, adapters | Single coherent canonical mapping behavior | Centralize mapping constants/helpers and generate support behavior from one source |
| Empty duplicate modules | `claudine/lib/src/events/providers/*.rs` empty stubs | No duplicate dead surfaces | Remove or replace with real provider modules |
| Extensibility posture | Core enums not marked for forward compatibility | `#[non_exhaustive]` on canonical enums | Add non-exhaustive markers and update matching code/tests |

## Refactor Strategy

Execute in staged, compile-safe phases with narrow checkpoints. Prefer short-lived internal compatibility shims only where needed to keep branch buildable between phases.

### Phase 2: Provider Adapter Contract Redesign

**Goal:** Move from parse-only adapters to full unified adapter interface.

**Primary Files**

- `claudine/lib/src/adapters/mod.rs`
- `claudine/lib/src/error.rs`
- New adapter files for missing providers (Goose, Kimi, Qwen, Roo)

**Tasks**

- Redefine trait to:
  - `parse_event(&self, raw: &Value) -> Result<(AgenticEvent, EventMeta), AdapterError>`
  - `can_block(&self, event: &AgenticEvent) -> bool`
  - `format_response(...) -> Result<Value, AdapterError>`
  - `exit_code(...) -> Option<i32>`
- Replace `Box<dyn ProviderAdapter>` factory with static adapter singletons returning `&'static dyn ProviderAdapter`.
- Add `AdapterError` variant(s) and conversion strategy in `error.rs`.
- Remove all `unimplemented!` adapter paths.

**Exit Criteria**

- `adapter_for()` never panics for any canonical provider.
- All adapters implement full contract even if some methods return no-op/default behavior for non-blocking providers.

## Parallelization Plan

Safe parallel streams after Phase 2:

1. Adapter implementation stream (Phase 3)
2. Action runtime + mapper stream (Phase 5)
3. Template migration stream (Phase 6)

Merge point:

- Phase 4 dispatch integration must consume outputs from streams 1 and 2.
- Phase 10 runs only after all streams merged.

## Risk Register

1. **Breaking public API for CLI consumers**
   - Mitigation: explicit downstream compile pass and same-branch CLI updates.
2. **Provider behavior drift due duplicated mapping logic**
   - Mitigation: centralize mappings and add table-driven conformance tests.
3. **Template migration breaks existing configs**
   - Mitigation: transitional single-brace rewrite + warnings, external migration command.
4. **Non-hook provider ambiguity (Kimi/Qwen/Roo)**
   - Mitigation: adapter-level parse support plus explicit non-blocking/no-hook semantics.
5. **Long-running `Call` hooks block pipeline**
   - Mitigation: default timeout and per-action timeout override.

## Definition of Done

This plan is complete when:

- `claudine/lib` runtime model matches sections 3.1-3.12 and rationale constraints in section 4.
- `EventAction` is no longer a runtime library type.
- All 8 providers are represented in canonical types and adapter factory without panic paths.
- Blocking response flow works end-to-end where supported and degrades gracefully where unsupported.
- Library and CLI packages compile/test cleanly with no unresolved migration debt hidden in runtime parsing.
