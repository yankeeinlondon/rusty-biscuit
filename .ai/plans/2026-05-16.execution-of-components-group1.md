## Lessons Learned

- [PLAN]: Phase 3.2 — the `CodeRenderer` trait API sketch shows `render_terminal_code`
  taking `&TerminalRenderContext`, but that type lives in `biscuit-terminal` and
  `renderable` cannot depend on it. Resolved by having `render_terminal_code` take a
  primitive `width: u32`; the terminal renderer extracts it from the context.
- [PLAN]: Phase 5.1 — `ColumnsHints` required two keys beyond the plan's listed set:
  `left_count` (to split the flat child list back into two columns) and a
  `left_width_kind` discriminator (a single JSON value cannot disambiguate
  `Fixed(u32)` from `Percent(f32)`).
- [PLAN]: Phase 5.2 — there is no generic block-grouping `NodeKind`; `BlockQuote`
  was used as the columns carrier (all 3 renderers special-case the columns hint).
- [PLAN]: Phase 4.4 — Markdown/Browser progress fallback turned out to be no-ops:
  the projected `Paragraph` already carries `"{label} {percentage}%"` text.
- [PLAN]: Phase 6.3 — `prefer_cursor_alignment` is carried as a terminal hint and
  the native renderer uses space-padding; cursor-positioned emit was not duplicated
  (Rule 2). The hint round-trips but the cursor-positioning rendering path is not
  reimplemented natively. Follow-up if cursor alignment fidelity is required.
- [INFO]: A pre-existing flaky darkmatter test
  (`allow_once_persists_across_sibling_transclusions`) was observed by a subagent;
  it passed in the final full run. Unrelated to this work.
