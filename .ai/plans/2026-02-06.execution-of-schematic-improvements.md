## Lessons Learned

- [SKILL: rust]: The standard library's blanket impl `impl<T: FromStr> TryFrom<&str> for T` means types deriving `EnumString` from strum already have `TryFrom<&str>` - only `TryFrom<String>` needs explicit impl
- [CODE: module_docs.rs]: The `quote!` macro renders `#![doc = "string"]` with spaces around punctuation. When `prettyplease` formats single-line doc attributes, they become `//!` style; multi-line strings become `/*! */` blocks
- [CODE: non_exhaustive]: When adding `#[non_exhaustive]` to enums, must also update (1) doc examples, (2) code generators emitting match statements, (3) regenerate auto-generated code
- [CODE: quote + syn]: When generating type expressions with generics (e.g., `Vec<ModelInfo>`), use `syn::parse_str::<syn::Type>()` instead of `format_ident!()` which only handles simple identifiers
- [CODE: trait consts]: To access trait associated constants without importing the trait, use fully qualified syntax `<Type as Trait>::CONST`
- [DATA: huggingface]: HuggingFace definitions referenced undefined types (StatusResponse, Commit, etc.) - added stub types to unblock codegen
