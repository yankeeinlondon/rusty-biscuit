## Analysis

### Current State

The `Table` component has two rendering paths:

1. **Standard path** (`render`/`fallback_render` → `render_content` → `apply_layout`):
   - Uses space-based padding via `pad_cell()`
   - Full `Layout` support: margins, alignment, word wrap, row fill
   - Works everywhere but can misalign when glyphs render narrower than computed

2. **Cursor alignment path** (`render_with_cursor_alignment` → `render_content_with_cursor_alignment`):
   - Uses ANSI `\x1b[{n}G` cursor positioning
   - Only applies `left_margin`
   - Missing: cell alignment, right margin, word wrap, row fill
   - Public method bypasses trait

### Problems with Current Implementation

1. **Public method bypasses `Renderable` trait** - callers must know to use special method
2. **Incomplete Layout support** - only left margin works
3. **No cell alignment** - content always left-aligns within cells
4. **No automatic detection** - caller must decide when to use it

### Proposed Architecture

```
Table struct:
  + prefer_cursor_alignment: bool  // new field, default false
  + prefer_cursor_alignment() -> Self  // new builder method
  - render_with_cursor_alignment()  // REMOVE public method

render() / fallback_render():
  if prefer_cursor_alignment && terminal_supports_cursor_positioning:
    return render_with_cursor_positioning(term_width)  // private, full Layout support
  else:
    return render_content() via apply_layout()  // existing path
```

### Layout Features to Support in Cursor Mode

| Feature | Current | Required |
|---------|---------|----------|
| `left_margin` | ✅ | ✅ |
| `right_margin` | ❌ | ✅ (clamp table width) |
| `alignment` (block) | ❌ | ✅ (offset table start) |
| `row_fill_strategy` | ❌ | ✅ (fill to available width) |
| `word_wrap` | ❌ | ⚠️ Tables don't typically wrap |
| `page_bg_color` | ❌ | ✅ (emit bg color codes) |
| Cell alignment | ❌ | ✅ (cursor offset within cell) |

### Key Implementation Details

1. **Cursor positioning qualifies when**: Always qualifies for `render()` (assumes TTY), qualifies for `fallback_render()` when terminal is detected as interactive (not piped)

2. **Cell alignment with cursor positioning**:
   ```rust
   // Calculate cursor position for right-aligned cell content
   let content_width = visible_width(content) as u32;
   let cursor_offset = match alignment {
       Alignment::Left => 0,
       Alignment::Right => cell_width - content_width,
       Alignment::Center => (cell_width - content_width) / 2,
   };
   format!("\x1b[{}G{}", cell_start + cursor_offset, content)
   ```

3. **Block alignment**: Offset `table_start` based on `Layout.alignment` and table width vs available width

4. **Row fill**: After final cell, position cursor at `table_start + table_width` and fill to `available_width`
