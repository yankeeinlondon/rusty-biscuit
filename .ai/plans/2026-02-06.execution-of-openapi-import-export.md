## Lessons Learned

- **Phase 1:** thiserror `source` field name conflicts with user field names; box large enum variants
- **Phase 2:** schemars 1.x API differs from 0.8.x; ArrayType has no Default
- **Phase 3:** openapiv3 v2 types lack Default; Serialize/Deserialize needed on extension types
- **Phase 4:** Only OpenAI has JsonSchema derives; ValueEnum works well for CLI enums
- **Phase 5:** Named QueryParamType to avoid conflict; updated 128+ Endpoint sites for params field
- **Phase 6:** openapiv3 boxing varies by schema type; Type::Boolean is tuple variant
- **Phase 7:** Name collision between imported schemas and generated request structs requires:
  - Computing reserved names (endpoint IDs + "Request" suffix) before schema processing
  - Deconfliction via `deconflict_name` function with suffix appending
  - Post-processing to remap TypeRef::Named values using name mapping
  - Standalone mode for generated clients (no schematic_definitions imports)
  - Default derive on generated model structs for proper initialization
