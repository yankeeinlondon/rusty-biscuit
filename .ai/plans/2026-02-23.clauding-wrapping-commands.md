# Claudine Wrapped Agent Commands Implementation Plan

## Goal

Implement seven new `claudine` wrapper subcommands that:

1. verify provider CLI installation;
2. sanitize/inject environment variables;
3. translate `--yolo` and `--non-interactive` into provider-specific execution;
4. forward remaining args faithfully;
5. return the wrapped process exit status.

## Invariants From Design

- Wrapper commands: `claude`, `codex`, `gemini`, `kimi`, `qwen`, `opencode`, `goose`
- Wrapper flags on every command:
  - `--yolo`, `-y`
  - `--include <ENV_NAME>` (repeatable)
  - `--non-interactive`, `-n`, `--ni`
- Sensitive env names (contains `API_KEY` or `TOKEN`, case-insensitive) are removed unless included.
- Injected env vars:
  - `AGENT`
  - `YOLO`
  - `AGENT_PARAMS`
  - optional `PACKAGE_AREA`, `PACKAGE` when resolvable in monorepo context.

## Phase 0: Baseline and Safety Net

### Tasks

1. Capture current CLI behavior snapshots before changes:
   - `claudine --help`
   - `claudine providers`
2. Run baseline checks in `claudine/`:
   - `just test`
   - `just lint`
   - `just build`
3. Note failing tests/lints, if any, before wrapper changes.

### Exit Criteria

- Current state is known and recoverable.

## Phase 1: CLI Surface and Command Wiring

### Files

- `claudine/cli/src/main.rs`
- `claudine/cli/src/commands/mod.rs`
- new: `claudine/cli/src/commands/wrap/mod.rs`

### Tasks

1. Add seven new `Commands` enum variants in `main.rs`.
2. Add shared wrapper args struct:
   - `yolo: bool`
   - `include: Vec<String>`
   - `non_interactive: bool`
   - passthrough args (`Vec<String>`, trailing var arg behavior)
3. Route all seven commands through one shared runner API:
   - `run_provider_wrapper(provider_slug, args)`.
4. Ensure `--help` output includes aliases and options for each wrapper subcommand.

### Exit Criteria

- New commands parse correctly and dispatch to shared wrapper runner.

## Phase 2: Provider Profile Layer

### Files

- new: `claudine/cli/src/commands/wrap/profile.rs`

### Tasks

1. Define `ProviderProfile` struct with:
   - wrapper command name
   - binary name
   - yolo mapping strategy
   - non-interactive mapping strategy
2. Implement profile registry for all seven providers.
3. Add deterministic transformation functions:
   - `apply_yolo_mapping(...)`
   - `apply_non_interactive_mapping(...)`
4. Make mappings idempotent so duplicates are not added.

### Exit Criteria

- Provider-specific arg translation is centralized and unit-tested.

## Phase 3: Install Detection and Preflight Diagnostics

### Files

- `claudine/cli/src/commands/wrap/mod.rs`
- optional helper in `claudine/lib` only if needed for reuse

### Tasks

1. Implement binary/install preflight using existing provider/sniff metadata where possible.
2. Emit actionable error on missing binary.
3. Emit warning (not error) for unsupported yolo mappings.

### Exit Criteria

- Wrapper does not spawn child when provider runtime is unavailable.

## Phase 4: Environment Sanitization and Context Injection

### Files

- new: `claudine/cli/src/commands/wrap/env.rs`

### Tasks

1. Implement env sanitizer:
   - case-insensitive match on env names containing `API_KEY` or `TOKEN`;
   - allowlist override by `--include`.
2. Validate include names and warn on includes not found in current env.
3. Report removed env names (sorted, unique) to stderr.
4. Inject required env vars:
   - `AGENT`
   - `YOLO`
   - `AGENT_PARAMS` (JSON string array)
5. Add monorepo resolution using Sniff:
   - detect repo at current `cwd`;
   - when monorepo, pick package whose path is longest prefix of `cwd`;
   - set `PACKAGE_AREA` and `PACKAGE` when found.

### Exit Criteria

- Sanitized env map and injected context envs are generated deterministically.

## Phase 5: Child Process Execution and Exit Propagation

### Files

- new: `claudine/cli/src/commands/wrap/exec.rs`
- `claudine/cli/src/commands/wrap/mod.rs`

### Tasks

1. Spawn provider process with:
   - inherited stdin/stdout/stderr
   - sanitized + injected env
   - current `cwd`
2. Wait for child completion and propagate exit code.
3. Handle signal termination on Unix with non-zero wrapper exit.

### Exit Criteria

- Wrapper process behavior is transparent except for intended pre-processing.

## Phase 6: Testing

### Files

- new: `claudine/cli/tests/wrap_commands.rs`
- optionally add targeted tests under `claudine/cli/src/commands/wrap/*`

### Test Matrix

1. Unit tests:
   - env filtering and include exemptions;
   - include validation;
   - AGENT/PACKAGE env injection logic;
   - yolo/non-interactive mapping idempotency.
2. Integration tests:
   - missing binary returns clear error;
   - passthrough args preserved after wrapper stripping;
   - removed env names are reported (names only);
   - child exit code is propagated.
3. CLI help tests:
   - each new wrapper subcommand appears with expected flags.

### Exit Criteria

- Tests cover behavioral contract, not just parsing.

### Exit Criteria

## Risks and Mitigations

1. Provider mapping drift:
   - Mitigation: keep all mapping logic in one profile table and add tests per provider.
2. Non-interactive mode differences between providers:
   - Mitigation: codify explicit per-provider strategy and warn when behavior is best-effort.
3. Over-removal of env vars:
   - Mitigation: strict include allowlist and explicit reporting of removed names.

## Done Definition

- New wrapper commands are implemented and tested.
- `just test`, `just lint`, and `just build` pass for `claudine`.
- README/docs reflect new runtime behavior.
- No regressions to existing `claudine` commands.
