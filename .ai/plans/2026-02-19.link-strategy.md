## Phase 1: Rule Enforcement Baseline

### Status
Completed for current skill/command linking implementation

### Goal
Implement the hard safety and scope rules before advanced behavior.

### Tasks
1. Enforce scope isolation:
   - never cross-link User to Repo
   - never cross-link Repo to User
2. Enforce symlink target style:
   - User scope => absolute targets
   - Repo scope => relative targets
3. Enforce non-destructive symlink behavior:
   - do not remove unknown/user-created symlinks
4. Support category-level symlink detection and reporting:
   - detect root-to-root category links
   - emit guidance to move to granular links
   - do not auto-remove
5. Keep linker dry-run default.

### Exit Criteria
1. Safety rules are enforced in both detect and apply paths.
2. Category-level links are surfaced as guidance, not destructive actions.

## Phase 3: Canonical Provider Selection Engine

### Status
Completed

### Goal
Implement preference-aware canonical selection per `(scope, resource type)`.

### Tasks
1. Implement preference assignment behavior for `claudine init`:
   - 1 installed provider: auto-assign
   - 2 installed providers: ask favorite
   - 3 installed providers: ask favorite + second
   - 4+ installed providers: ask first/second/third, append rest alphabetically
2. Implement canonical candidate filtering:
   - sort providers by configured preference
   - exclude non-Markdown providers from canonical selection
   - exclude providers where resource entry point is symlink
3. Canonical selection logic:
   - choose first candidate with valid assets for `(scope, resource type)`
   - fallback to first candidate if none have valid assets
   - if no candidates after filtering, return "no meaningful linking service" state
4. Persist canonical provider decisions per `(scope, resource type)`.

### Exit Criteria
1. Canonical selection is deterministic and persisted.
2. Non-Markdown providers remain eligible only for derived sync paths.

## Phase 8: Frontmatter Compatibility and Canonical Upgrade

### Status
Not started

### Goal
Support compatibility-aware linking with deterministic canonical upgrades.

### Tasks
1. Parse canonical frontmatter and body for all canonical candidates.
2. Classify canonical source as:
   - `Source` when requirements are satisfiable
   - `PartialSource` when required properties cannot be confidently filled
3. Implement deterministic upgrade operations in place on canonical sources:
   - key alias duplication where mapping is certain
   - derive `name` from filename where valid
4. Enforce `IncompleteLink` when target provider requirements cannot be met from canonical source.

### Exit Criteria
1. Canonical upgrades occur only for deterministic mappings.
2. Incomplete requirements block link creation and are surfaced as `IncompleteLink`.
