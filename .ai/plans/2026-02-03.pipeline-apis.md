# Pipeline API Transition Plan (Updated For Schematic Headers/Hooks)

## Context

- `unchained-ai/lib/src/api/openai_api.rs` handles OpenAI-compatible model discovery across providers (auth, retries, size limits) and is used by `unchained-ai/gen/src/main.rs`.
- `unchained-ai/lib/src/api/hugging_face_api.rs` is empty.
- Target clients live in `schematic/schema` (`schematic_schema::openai::OpenAI`, `schematic_schema::huggingface::HuggingFaceHub`) and are generated.

## What Changed In Schematic (Addresses Prior Concerns)

- Programmatic credential injection + default header injection via `schematic_define::Headers`.
- Generated clients support:
    - `variant()` builder with `.headers_builder(Headers)`
    - `variant_with_headers(Headers)` convenience
    - `pre_response_json(...)` hook (reshape JSON before deserialization)
    - `mutate_response::<Request>(...)` hook (post-deserialize mutation)

## Goals

- Remove `unchained-ai/lib/src/api` and route model discovery through `schematic-schema`.
- Keep `gen-models` working.
- Avoid relying on ENV alignment in schema clients: unchained-ai should be able to read env vars and inject credentials programmatically.

## Plan

1. Scope + mapping
   - Enumerate call sites: `unchained-ai/gen/src/main.rs` and docs.
   - Decide provider coverage for model enumeration:
     - Minimum: OpenAI + HuggingFace Hub.
     - Optional: OpenAI-compatible providers (Deepseek, Groq, Mistral, etc.).
     - Optional: Gemini if it supports Bearer auth (see step 3 for JSON shape hook).
   - Create a table: Provider -> base_url -> auth method -> where model list comes from.

2. Add schematic-schema dependency + new discovery wrapper
   - Add `schematic-schema = { path = "../schematic/schema" }` (or workspace path) to `unchained-ai/lib/Cargo.toml`.
   - Implement `unchained-ai/lib/src/rigging/providers/model_discovery.rs` which:
     - Reads provider credentials from unchained-ai env rules.
     - Builds a `schematic_define::Headers` instance with explicit credentials:
       - `Headers::default().use_bearer_token(token)`
       - Add any required extra headers here (e.g., `anthropic-version`).
     - Creates a client variant that does NOT require env-based auth:
       - Use `.variant().auth_update(UpdateStrategy::ChangeTo(AuthStrategy::None)).headers_builder(headers).build()`
       - This is important because base clients still try `std::env` for `auth_strategy` before applying headers.
     - Calls the generated request APIs and normalizes to `Vec<String>` model ids.
     - Maps `schematic_schema::shared::SchematicError` -> `unchained_ai::rigging::providers::provider_errors::ProviderError`.
   - Re-introduce retry/backoff and response-size guard here (schematic clients are intentionally thin).

3. Gemini / non-OpenAI response shapes (if needed)
   - If Gemini returns `{ models: [{ name: "models/gemini-..." }] }`, use `pre_response_json` in the OpenAI client variant to reshape into OpenAI `ListModelsResponse`:
     - Emit `{ object: "list", data: [{ id, object: "model", created: 0, owned_by: "google" }, ...] }`.
   - This avoids forking schema definitions, but note: it synthesizes required `Model` fields.

4. Update `gen-models` to use the wrapper
   - Replace `unchained_ai::api::openai_api::{get_api_keys, get_provider_models_from_api}` with the new wrapper.
   - Update provider iteration / skipping logic based on what the wrapper supports.

5. Remove legacy API module
   - Delete `unchained-ai/lib/src/api/*` and remove `pub mod api;` from `unchained-ai/lib/src/lib.rs`.
   - Remove `ApiAuthMethod` and simplify `ProviderConfig` if it is no longer needed by runtime code.

6. Docs + verification
   - Update `unchained-ai/lib/README.md` and `unchained-ai/lib/src/rigging/providers/models/README.md` to reference `schematic-schema` + the wrapper.
   - Validate: `cargo check -p unchained-ai`, `cargo check -p unchained-ai-gen`.

## Remaining Concerns / Notes

- Programmatic injection works, but do not rely on `variant_with_headers()` alone if the client still has `auth_strategy` set to Bearer/API-key (it will error on missing env before headers are applied). Use the variant builder to set `AuthStrategy::None`.
- `AuthStrategy::ApiKeyParam` exists in `schematic-define`, but generated clients currently do not implement it (fallthrough `_ => {}`); only relevant if a provider requires query/cookie key auth.
- Using `pre_response_json` to normalize Gemini means `created/owned_by/object` are synthetic; safe if you only consume model ids.
