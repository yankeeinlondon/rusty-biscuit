# Pipeline API Transition Plan

## Context
- `unchained-ai/lib/src/api/openai_api.rs` handles OpenAI-compatible model discovery across providers (auth, retries, size limits) and is used by `unchained-ai/gen/src/main.rs`.
- `unchained-ai/lib/src/api/hugging_face_api.rs` is empty.
- Target clients live in `schematic/schema` (`schematic_schema::openai::OpenAI`, `schematic_schema::huggingface::HuggingFaceHub`) and are generated.

## Goals
- Remove `unchained-ai/lib/src/api` and route model discovery through `schematic-schema`.
- Keep `gen-models` working for supported providers.
- Update docs to reflect the new discovery path and environment variables.

## Plan
1. Scope + provider mapping
   - Enumerate all call sites: `unchained-ai/gen/src/main.rs`, docs (`unchained-ai/lib/README.md`, `unchained-ai/lib/src/rigging/providers/models/README.md`).
   - Decide provider coverage: default to OpenAI + HuggingFace; optionally allow OpenAI-compatible providers that return OpenAI-shaped `/models` responses with Bearer/API-key auth.
   - Build a mapping table of provider -> base URL -> env var list -> auth strategy -> client to use.
   - Record which providers must be skipped or need schema updates (Gemini query param auth, non-OpenAI response shapes).

2. Add schematic-schema dependency + wrapper module
   - Add `schematic-schema` to `unchained-ai/lib/Cargo.toml`.
   - Create a new module (e.g., `unchained-ai/lib/src/rigging/providers/model_discovery.rs`) that wraps `schematic_schema::openai::OpenAI` and `schematic_schema::huggingface::HuggingFaceHub`.
   - Provide functions like:
     - `list_openai_models(base_url, env_vars, auth_strategy) -> Result<Vec<String>, ProviderError>`
     - `list_huggingface_models(env_vars) -> Result<Vec<String>, ProviderError>`
   - Map `SchematicError` to `ProviderError` (401/403 -> AuthenticationFailed, 429 -> RateLimitExceeded, MissingCredential -> MissingApiKey, etc.).
   - Re-introduce retry/backoff and response-size guard in the wrapper (no new deps; reuse tokio sleep).
   - For HuggingFace, use `HuggingFaceHub::variant` to include existing env var names (`HUGGINGFACE_TOKEN`, `HUGGING_FACE_TOKEN`) so current setups keep working.

3. Update `gen-models` flow
   - Replace `openai_api::{get_api_keys, get_provider_models_from_api}` usage with the new wrapper module.
   - Update provider iteration to only include supported providers (OpenAI + HuggingFace by default).
   - If keeping OpenAI-compatible providers, build base URLs with `/v1` where required and skip providers that require query-param auth or non-OpenAI responses.
   - Update errors and logs to reflect the new error types and skipped providers.

4. Remove legacy API module + tighten registry
   - Delete `unchained-ai/lib/src/api/*` and drop `pub mod api;` from `unchained-ai/lib/src/lib.rs`.
   - Remove `ApiAuthMethod` and `ProviderConfig.auth_method/models_endpoint` if unused after migration.
   - Update `ProviderConfig` to retain only fields needed by the new discovery wrapper (env vars, base URL, is_local).

5. Documentation + validation
   - Update `unchained-ai/lib/README.md` and `unchained-ai/lib/src/rigging/providers/models/README.md` to reference `schematic-schema` clients.
   - Note new environment variables and any changes in provider coverage.
   - Validate: `cargo check -p unchained-ai`, `cargo check -p unchained-ai-gen`, and (if needed) `cargo check -p schematic-schema`.

## Concerns / Open Questions
- OpenAI client expects the OpenAI `/models` response shape; providers like Gemini (uses `models[]`) will fail without a schema update or custom handling.
- `schematic_define::AuthStrategy` does not support query-param auth, so Gemini and similar providers cannot be supported without extending schema/definitions.
- Generated clients do not expose a public API to add default headers (e.g., `anthropic-version`); any provider needing extra headers may require schema updates or manual HTTP calls.
- HuggingFace env vars differ (`HF_TOKEN`, `HUGGING_FACE_API_KEY`, `HF_API_KEY` vs existing `HUGGINGFACE_TOKEN`, `HUGGING_FACE_TOKEN`); wrapper must normalize to avoid breaking existing configs.
- Legacy openai_api had retry/backoff and response-size limits; the schema clients do not, so behavior will change unless reintroduced in the wrapper.
