# Darkmatter CLI Output/Command Refactor Plan

Date: 2026-02-13
Scope: `darkmatter/cli` plus targeted `darkmatter/lib` image-output behavior needed by CLI output modes.

## Confirmed Decisions (Locked)

1. Replace only render-format flags with `--output <output>`.
2. Remove `--show-html`; add output-neutral `--show` that opens the produced output artifact.
3. Convert `--toc` and `--delta` to subcommands:
   - `md toc <input> [--json]`
   - `md delta <base> <updated> [--json]`
4. `--output auto`:
   - TTY: render terminal ANSI output to terminal.
   - non-TTY: emit markdown text.
5. No backward-compat aliases for removed flags.
6. Boolean env parsing should support broad truthy/falsy values.
7. `TERMINAL_IMAGES=true` must force protocol output behavior even when terminal capability detection says no.
8. Markdown image serialization should preserve all defined `ImageRef` properties; undefined properties are omitted.
9. Width hint delimiter is only `|` (e.g. `![alt|15%](...)`).
10. Keep or evolve metadata marker behavior by engineering judgment, with tests.

## Target CLI UX

Render outputs:
- `--output auto` (default)
- `--output markdown` (alias: `text`)
- `--output html`
- `--output json` (AST JSON for primary render path; subcommand JSON remains scoped to subcommands)
- `--output ast` (alias of `json`)

Show behavior:
- `--show` writes the selected output into a temp file and opens via `open` crate:
  - HTML -> `.html`
  - Markdown/Text -> `.md`
  - JSON/AST -> `.json`
  - Auto on TTY -> still opens markdown temp file while also rendering ANSI to terminal
  - Auto on non-TTY -> opens markdown temp file based on markdown output

Subcommands:
- `toc` subcommand owns `--json`.
- `delta` subcommand owns `--json` and comparison target args.

Removed flags:
- `--html`, `--show-html`, `--ast`, `--json` (top-level), `--no-images`, and `--toc`/`--delta` top-level switches.

## Implementation Phases

### Phase 1: CLI Surface Redesign (Clap model)

Goals:
- Replace output-mode booleans with typed `OutputFormat` enum.
- Add `--show`.
- Introduce `toc` and `delta` subcommands and move JSON options under them.

Planned changes:
- `darkmatter/cli/src/lib.rs`
  - Add `OutputFormat` value enum and aliases.
  - Remove legacy render flags.
  - Add `show: bool`.
  - Add subcommand enum (`Toc`, `Delta`) with scoped flags.
  - Keep existing non-output features (`clean`, `clean-save`, `fm-*`, themes, mermaid, line numbers, completions).
- Update help text and examples in module docs.

Acceptance:
- `md --help` reflects new switches/subcommands.
- Clap rejects removed flags.

### Phase 2: Main Execution Routing

Goals:
- Route top-level render path by `--output`.
- Route `toc`/`delta` via subcommands.
- Implement explicit auto-mode behavior by TTY state.

Planned changes:
- `darkmatter/cli/src/main.rs`
  - Replace old `if cli.html/ast/show_html/...` chain with:
    - subcommand dispatch first (`toc`, `delta`)
    - render dispatch by `OutputFormat`
  - Auto mode behavior:
    - if `stdout.is_terminal()` -> terminal render
    - else -> markdown string render (`md.as_string()`)
  - Add output artifact generation helper returning `{content, extension, label}` for `--show`.

Acceptance:
- Terminal vs non-terminal auto behavior matches decision #4.
- `toc` and `delta` behavior preserved but now under subcommands.

### Phase 3: `--show` Output-Neutral Open Flow

Goals:
- Open any selected output type through temp files.
- Preserve current graceful failure behavior when host open fails.

Planned changes:
- `darkmatter/cli/src/main.rs`
  - Add helper to create temp file path in `std::env::temp_dir()` with stable naming.
  - Write selected output content to file and call `open::that(...)`.
  - For `--output auto` on TTY:
    - render ANSI to stdout
    - separately materialize markdown text for opening.

Acceptance:
- `--show` works for markdown/html/json in a single mechanism.
- CLI prints fallback path on open failure.

### Phase 4: Terminal Image Env Overrides

Goals:
- Remove `--no-images`.
- Implement `TERMINAL_IMAGES` broad bool parsing.
- Enforce forced protocol path when env is truthy.

Planned changes:
- `darkmatter/cli/src/main.rs`
  - Remove `no_images` wiring.
  - Read and parse `TERMINAL_IMAGES` with broad values (`true/false`, `1/0`, `yes/no`, `on/off`, case-insensitive).
  - Map env result to terminal options.
- `darkmatter/lib/src/markdown/output/terminal.rs`
  - Extend `TerminalOptions` with image render mode (auto/never/force).
  - Update `ImageRenderer` decision points:
    - bypass `graphics_supported()` gate in force mode.
    - keep standard fallback behavior in auto mode.
    - disable in never mode.
  - Ensure force mode still handles invalid/missing files safely.

Acceptance:
- `TERMINAL_IMAGES=true` attempts protocol output regardless of detection.
- unset env behaves as today (capability-based).

### Phase 5: Markdown Image Serialization Semantics

Goals:
- Keep `|` width-hint contract.
- Ensure markdown serialization for rich `ImageRef` stays lossless for defined metadata.
- Omit undefined properties from serialized payload.

Planned changes:
- `darkmatter/lib/src/render/image_ref.rs`
  - Keep `parse_alt_width_hint` pipe-based parsing only.
  - Review metadata package generation to ensure all defined fields are included.
  - Preserve marker-based round-trip strategy (or evolve marker version if needed) with backward parse support.
  - Confirm no undefined keys are emitted (`skip_serializing_if` behavior).
- Update docs/examples if needed to remove ambiguity and typos around delimiters.

Acceptance:
- Round-trip tests retain class/style/title/decoding/fetchpriority/height/width/loading/referrerpolicy/sizes/srcset/data when defined.
- Undefined fields are absent from markdown metadata payload.

### Phase 6: Docs and Test Migration

Goals:
- Bring tests/docs in sync with new CLI contract.
- Keep regression coverage for legacy bug fixes where still applicable.

Planned changes:
- `darkmatter/cli/tests/cli.rs`
  - Replace tests for removed flags.
  - Add tests for:
    - `--output` enum parsing and aliases.
    - `--output auto` behavior split by tty/non-tty contexts (as feasible in test harness).
    - `toc` and `delta` subcommands with `--json`.
    - `--show` artifact write + open path behavior (mock/failure-path friendly assertions).
    - removed-flag errors.
- Docs:
  - `darkmatter/cli/README.md`
  - `darkmatter/cli/src/lib.rs` top-level usage docs
  - `darkmatter/docs/cli-pipeline.md` (align spec wording with final implementation).

Acceptance:
- `cargo test -p darkmatter-cli` green.
- Any updated lib tests for `ImageRef` and terminal output behavior green.

## Risk Register and Mitigations

1. CLI breakage from removed flags
- Mitigation: explicit tests for error messaging and updated README/help examples.

2. Force-image mode causing noisy fallback behavior on unsupported terminals
- Mitigation: isolate forced mode behind env only; preserve safe failure for path/file errors.

3. `--show` with auto mode creating ambiguous behavior
- Mitigation: codify dual behavior (render ANSI + open markdown artifact) and test it.

4. Metadata marker compatibility regressions
- Mitigation: keep decode support for existing marker payloads and add backward-compat tests.

## Execution Order

1. Phase 1 (CLI model)  
2. Phase 2 (dispatch/routing)  
3. Phase 3 (`--show`)  
4. Phase 4 (env-driven image behavior)  
5. Phase 5 (`ImageRef` serialization)  
6. Phase 6 (tests/docs hardening)

## Done Criteria

- New CLI UX is live and documented.
- `toc` and `delta` operate as subcommands with scoped JSON flags.
- `--output auto` honors tty split exactly as specified.
- `--show` works for html/markdown/json and for auto-mode dual behavior.
- `TERMINAL_IMAGES` supports broad boolean values and forced protocol mode.
- Image metadata round-trips losslessly for defined values and omits undefined keys.
