# Plan for Tree-Hugger Symbol Schema Refactor

## Objective
Refactor `tree-hugger` library and `hug` CLI to:
1. Adopt Symbol Schema v2 (`SymbolRecord` + facets + kind payloads).
2. Implement staged analysis passes (parse -> bind -> semantic -> docs).
3. Add deterministic incremental caching (L0-L4) with correct invalidation.
4. Redesign CLI behavior around `hug <subcommand> <filter...>` with all-files default scanning.
5. Preserve compatibility during migration, then retire v1 after one release cycle.

## Inputs Used
- `tree-hugger/docs/refactor.md`
- `tree-hugger/docs/symbol-schema-design.md`
- `tree-hugger/docs/cache-design.md`
- Current implementation in:
  - `tree-hugger/lib/src/shared/symbol.rs`
  - `tree-hugger/lib/src/file/tree_file.rs`
  - `tree-hugger/lib/src/queries/mod.rs`
  - `tree-hugger/cli/src/main.rs`
  - `tree-hugger/lib/tests/*`, `tree-hugger/cli/tests/cli.rs`

## Current State Snapshot
1. Schema is v1-centric (`SymbolInfo`, `TypeMetadata`, `FileSummary`, `PackageSummary`).
2. Extraction logic is largely monolithic in `lib/src/file/tree_file.rs`.
3. Query cache exists (in-memory `OnceLock<Mutex<HashMap<...>>>`), but no persistent incremental cache.
4. CLI behavior still depends on `--all`, has an `exports` subcommand, and is file-centric in output flow.
5. Existing tests are strong for current CLI and parsing behavior, but there is no v2 schema/caching test matrix yet.

## Definition of Done
1. Library emits v2 symbol records with `schema_version` and required v2.0 facets/kind payloads.
2. Analysis passes are explicitly modeled and independently cacheable.
3. Cache correctness proven via fingerprint-based invalidation tests.
4. CLI defaults to all-source scanning, supports mixed file/symbol filters, removes `exports` subcommand.
5. JSON output is lossless for available analysis data.
6. Performance target met: >=3x warm-run speedup on unchanged repository.
7. Migration path complete: dual-write/adapters -> v2 default -> v1 removal after one cycle.

## Non-Goals for This Refactor
1. Full type-checker parity across all languages.
2. Perfect side-effect/purity inference in first cut.
3. Full inter-file semantic resolution parity on day 1.

## Workstreams and Sequence

## Phase 0: Architecture Baseline and Guardrails
Goal: establish stable scaffolding before behavior changes.

Tasks:
1. Create a `schema_v2` module namespace in library:
   - `lib/src/shared/schema_v2/mod.rs`
   - split facets/kinds/types into focused files.
2. Add `AnalysisPass` and pipeline contract types:
   - `parse`, `bind`, `semantic`, `docs`.
3. Add compatibility adapters:
   - `From<SymbolInfo> for SymbolRecord`
   - `TryFrom<SymbolRecord> for SymbolInfo` (best-effort).
4. Keep existing public APIs intact while introducing parallel v2 API entry points.

Deliverables:
1. Compiling v2 type system with serde support and schema version fields.
2. Initial adapter tests and serde round-trip tests.

Exit criteria:
1. `just test` passes with no behavioral change to existing CLI commands.

## Phase 1: Symbol Schema v2 Parse Pass (Core Extraction)
Goal: emit high-fidelity parse-layer `SymbolRecord` values.

Tasks:
1. Introduce parse-pass output type (`FileSymbolIndex` based on v2 records).
2. Populate required v2.0 facets in parse pass:
   - `identity`, `source`, `visibility`, `docs.raw_doc/comments`, `modifiers`, `type_info.declared/canonical`, `provenance`.
3. Populate v2.0 kind payloads:
   - `FunctionData`, `TypeData`, `EnumData`, `FieldData`.
4. Keep unresolved relation IDs as `None` in parse pass where needed.
5. Preserve existing symbol extraction parity for all currently supported languages.

Code focus:
1. Incrementally split `lib/src/file/tree_file.rs` into pipeline components under a new analysis namespace.
2. Keep `TreeFile` as façade while delegating to pass modules.

Deliverables:
1. New v2 parse output API in library.
2. Golden fixtures for v2 JSON parse output across languages.

Exit criteria:
1. v2 parse output contains required fields for all fixtures.
2. Existing v1 paths still pass tests.

## Phase 2: Bind Pass and Relations
Goal: link symbols and produce cross-symbol relationships.

Tasks:
1. Implement bind pass to fill relation fields:
   - parent/container/members/references/dependencies.
2. Normalize import/export modeling to align with `SymbolRef` usage.
3. Add stable ID generation:
   - stable key format from design.
   - hash with BLAKE3 for `SymbolId`.
4. Add package-level binding context for multi-file resolution where possible.

Deliverables:
1. Deterministic IDs and relation edges in v2 records.
2. Tests for ID stability across repeated runs.

Exit criteria:
1. Relation fields are populated for fixture scenarios.
2. ID determinism tests pass.

## Phase 3: Docs Pass and Structured Documentation
Goal: upgrade doc handling from raw strings to structured docs facet.

Tasks:
1. Implement doc attachment model (`Leading`, `Trailing`, `Inline`, `Detached`).
2. Build parser for structured doc tags into `ParsedDocs`.
3. Keep raw and parsed doc views simultaneously to avoid loss.
4. Add pass provenance update rules (`created_at`, `updated_at`, `parse_pass`).

Deliverables:
1. `docs` facet populated with comments + parsed summaries/params/returns.
2. Language-specific doc attachment precision tests.

Exit criteria:
1. Doc attachment and parsed-doc tests pass on fixture matrix.

## Phase 4: Semantic Pass (Initial Cut)
Goal: fill first semantic inference fields with explicit unknown states.

Tasks:
1. Add initial semantic inference engine for low-risk fields:
   - recursion detection,
   - may_throw/may_panic heuristics,
   - mutates_self/mutates_arguments where obvious.
2. Encode with `Option<TriState>` to distinguish not-run vs unknown.
3. Keep semantic pass optional/configurable for rollout safety.

Deliverables:
1. Semantic facet population for selected languages/rules.
2. Deterministic semantic unit tests.

Exit criteria:
1. No regressions in existing lint/syntax diagnostics behavior.

## Phase 5: Cache Foundation (L1/L2 + Fingerprints)
Goal: implement high-impact incremental caching first.

Tasks:
1. Add `AnalyzerFingerprint` with:
   - schema version,
   - tree-hugger version,
   - grammar fingerprint,
   - query fingerprint,
   - config fingerprint.
2. Implement `FileCacheKey` and L1/L2 snapshot structs.
3. Add in-memory cache tier with bounded entries.
4. Add disk cache backend (SQLite + WAL + compressed payloads).
5. Cache parse/docs first, then bind/semantic pass completeness.

Dependencies expected:
1. `serde_json` (v2 AST/value fields).
2. `rusqlite` (or equivalent SQLite binding).
3. `zstd` for payload compression.
4. `dashmap` (or sharded map) for low-contention in-memory cache.

Deliverables:
1. Cache manager module and persistence schema.
2. Deterministic key tests + mutation invalidation tests.

Exit criteria:
1. Unchanged warm run demonstrates significant speedup.
2. Invalidation tests prove no stale data on schema/query/config/file changes.

## Phase 6: Advanced Cache Layers (L3/L4) and Observability
Goal: complete incremental and UX-visible cache behavior.

Tasks:
1. Add package graph cache (L3) for dependency-aware invalidation.
2. Add render cache (L4) for exact command signature reuse.
3. Implement single-flight duplicate-work suppression in parallel runs.
4. Add CLI cache controls:
   - `--cache` / `--no-cache`
   - `--cache-dir`
   - `--cache-reset`
   - `--cache-stats`
5. Add env support:
   - `TREE_HUGGER_CACHE_DIR`
   - `TREE_HUGGER_CACHE_DISABLE=1`

Deliverables:
1. Hit/miss metrics per cache layer.
2. Cache stats report in CLI.

Exit criteria:
1. Cache stats and debug logs reflect per-layer behavior and invalidation reasons.

## Phase 7: CLI Command Surface Refactor
Goal: align CLI semantics with `refactor.md`.

Tasks:
1. Replace current input semantics with `hug <subcommand> <filter...>`.
2. Remove `--all` behavior from primary symbol commands.
3. Remove redundant `exports` subcommand.
4. Keep `lint` and `imports` behavior independent as noted in design.
5. Introduce unified filter classifier:
   - file references (extension/path-like tokens),
   - symbol glob filters.
6. Apply wildcard normalization:
   - auto-wrap with `*` when user provides no wildcard,
   - preserve explicit wildcard patterns.
7. Apply `--exported` and `--prelude` filtering on top of base result set.

Important open ambiguity from `refactor.md`:
1. Document says symbol filters are combined with logical AND.
2. Example says `foo bar` means name contains `foo` OR `bar`.
3. Decision needed before implementation; proposed default: OR semantics for user intent consistency.

Deliverables:
1. Updated clap command definitions and help text.
2. Backward-incompatibility notes in CLI docs/changelog.

Exit criteria:
1. CLI integration tests cover new syntax and no `--all` dependency.

## Phase 8: Sorting, Grouping, and Output Model
Goal: deliver required report behavior and JSON fidelity.

Tasks:
1. Default output ordering:
   - alphabetical symbols across scope, not grouped by file.
2. Add grouping switches:
   - `--group-by-file`
   - `--group-by-module` (first grouping layer if both used).
3. Add sorting switches:
   - `--sort-by-kind`
   - `--sort-by-module`.
4. Keep JSON output lossless with full available symbol metadata.
5. Reshape terminal renderer around information-dense but clear output.

Stretch integration:
1. Adopt `biscuit-terminal` renderable components for richer terminal reports.

Deliverables:
1. Deterministic ordering/grouping implementation.
2. Golden output tests for plain and JSON modes.

Exit criteria:
1. Sorting/grouping combinations validated by integration tests.

## Phase 9: Migration Cutover and v1 Retirement
Goal: safe transition to v2 as default.

Tasks:
1. Dual-write period:
   - keep v1 outputs available internally for compatibility.
2. Make v2 default in `--json` output.
3. Preserve adapters for one release cycle.
4. Remove v1 schema fields/types and deprecated command behavior after cycle.
5. Clean up stale tests and fixtures tied to v1-only behavior.

Deliverables:
1. Migration notes and upgrade guide.
2. Final schema/version policy documentation.

Exit criteria:
1. No remaining production path depends on `SymbolInfo`/`TypeMetadata` structures.

## Testing Strategy (Execution-Ordered)
1. Unit tests:
   - v2 struct serde round-trips.
   - ID generation determinism.
   - doc parsing/tag extraction.
   - filter classification and glob semantics.
2. Fixture-based library tests:
   - cross-language symbol-kind coverage.
   - type views (`declared`, `canonical` in v2.0).
   - relation edges where available.
3. Cache tests:
   - cache hit/miss on unchanged files.
   - invalidation on file/query/schema/grammar/config mutations.
   - corruption recovery and partial write handling.
   - concurrent duplicate-work suppression.
4. CLI integration tests:
   - new command shape, removed `exports`, no `--all` dependency.
   - grouping/sorting matrix.
   - `--cache-*` flags and stats output.
5. Golden tests:
   - deterministic JSON snapshots for v2 output.

Run gates per phase:
1. `cd tree-hugger && just test`
2. `cd tree-hugger && just lint`
3. `cd tree-hugger && just build`

## Performance and Reliability Gates
1. Warm-run target: >=3x speedup on unchanged repo.
2. Cold-run overhead from cache bookkeeping remains acceptable (<15% regression target).
3. Memory bounded by configurable LRU/sharded map limits.
4. Zero stale-result regressions under fingerprint-triggered invalidation tests.

## Documentation and Drift Updates Required
1. Update `tree-hugger/lib/README.md` and `tree-hugger/cli/README.md` for v2 schema and CLI behavior.
2. Update `tree-hugger/docs/dependencies.md` for cache/storage/compression dependencies.
3. Update `.claude/skills/tree-hugger/*` docs for new architecture and command semantics.
4. Update `tree-hugger/docs/refactor.md` status markers as phases complete.

## Risk Register
1. Risk: schema overreach stalls delivery.
   - Mitigation: enforce v2.0 initial cut and defer v2.1 fields.
2. Risk: stale cache due to incomplete fingerprinting.
   - Mitigation: centralize fingerprint builder, test each dimension explicitly.
3. Risk: CLI breaking changes create user confusion.
   - Mitigation: clear error hints, migration docs, transitional compatibility window if needed.
4. Risk: monolithic file refactor causes regressions.
   - Mitigation: keep `TreeFile` façade stable while extracting pass modules incrementally.

## Decision Log Needed Before Implementation Starts
1. Resolve symbol filter combination semantics (AND vs OR contradiction in `refactor.md`).
2. Confirm SQLite backend choice vs alternatives (`redb`) for disk cache.
3. Decide whether v2 JSON becomes immediate default or opt-in by flag for one cycle.
4. Decide initial scope for `biscuit-terminal` integration vs plain renderer-first.

## Suggested Milestone Breakdown
1. Milestone A (Phases 0-2): v2 schema + parse/bind + IDs.
2. Milestone B (Phases 3-5): docs/semantic initial + L1/L2 cache.
3. Milestone C (Phases 6-8): advanced cache + CLI refactor + ordering/grouping.
4. Milestone D (Phase 9): migration cutover and cleanup.
