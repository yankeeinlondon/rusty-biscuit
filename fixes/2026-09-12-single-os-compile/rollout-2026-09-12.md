# Acceptance ledger

> **Review 1 correction, 2026-09-15:** The earlier rows below are historical
> implementation evidence, not acceptance of the current architecture. The
> review found production-boundary gaps in AC2–AC5 and AC8–AC9. Corrections and
> current validation are tracked in [review-1-response.md](review-1-response.md).
> Hosted measurements, actual artifact-service execution, and current native

One row per acceptance criterion in `spec.md`, mapped to the test, artifact,
or measurement that answers it. Where the evidence is **compile** rather than
**behavioral**, or where an environment could not be reached, the row says so
rather than narrowing the criterion.

Every test named here was run on this host (macOS 26, `aarch64-apple-darwin`,
Rust 1.97.1) at the head of `feat/single-os` on 2026-09-14. Suite totals are in
[Final validation](#final-validation).

## Vocabulary used below

- **Behavioral** — the contract was executed on that environment and observed.
- **Compile** — the code was built for that target but not run there.
- **Contract** — the shipped artifact (workflow, recipe, script) was asserted
  against, without executing it on a live runner. A contract test is real
  evidence about the shipped text and no evidence about a runner.

## AC8 — Cold and warm measurements, three consecutive green runs

> Report total runner compute and end-to-end critical path separately, three
> consecutive green runs per environment, 15% noise band, and an explicit design
> ruling for a regression above it.

**Status: NOT MET.** This is the one criterion this work does not evidence, and
it is unmet in both directions:

- The **pre-cutover** rows of `baseline-2026-09-12.md` are empty (plan Task
  1.6). The document carries the revision, configuration, measured identities,
  schema, WSL2 two-row split, noise band, and the exact dispatch procedure —
  and no observations. Since the Review 2 correction it also names the
  constructed instrumentation-only revision those rows are collected on, which
  it previously could not.
- The **post-cutover** rows (Task 7.4) do not exist for the same reason.

Both require pushing this branch and dispatching `ci.yml` with
`measure-compiler-work: true` six times per environment (three cold, three
warm). The implementing sessions were instructed not to commit or push, and
three consecutive *green hosted* runs per environment cannot be produced any
other way. Local `cross-check` runs measure a rig, not a hosted critical path,
and are not a substitute.

What *is* measured, and what it does and does not tell you:

- **Compiler work is counted, not inferred.** `ci-build`'s rustc wrapper writes
  one event file per invocation, and AC3's fixture uses it to prove the
  dependency compiles once. A warm `Swatinem/rust-cache` restore therefore
  cannot be mistaken for one compilation — which was the specification's
  stated reason for the counter.
- **Every stage is reported apart** (AC9 below), so when the runs are
  collected, transfer and setup cannot hide inside test time.

Consequently **Task 7.5's measured architecture gate has not been applied.** The
single-owner design is *not* recorded as accepted; it is untested against the
15% band. Compatibility cohorts stay out — the specification's recommendation is
to adopt them only if the measurements reject single-owner, and no measurement
exists to reject it with.

Neither a first hosted run nor merging this branch closes either task; the plan
says so at Task 7.5 and this ledger now says the same thing. Task 7.4 closes on
three consecutive green runs per environment in each of the controlled cold and
warm conditions, matched to Task 1.6's, and Task 7.5 closes only on an explicit
recorded ruling against the 15% band once both halves exist.

Review 2 additionally found that the pre-cutover half had no revision to run on:
the instrumentation and the ownership cutover arrived as one change, so
dispatching this branch measures only the post-cutover schedule.
`scripts/ci/build_baseline_revision.py` now constructs that missing revision
deterministically, and
[deferred-performance-measurements.md](deferred-performance-measurements.md)
records the full deferred procedure, the acceptance rule, and why this session
could not perform it.

### One host note, not a repository defect

`.githooks/tests/test-pre-push.sh` resolves its repository root with
`cd … && pwd`, which prints an extra line when the invoking shell has `CDPATH`
set — this session's did, and the harness then looked for the hook in a
different worktree. `CDPATH= bash .githooks/tests/test-pre-push.sh` is correct
and is what the 66/0 above was run with. CI sets no `CDPATH`. Left unchanged:
it is a shell-configuration interaction in a file outside this plan's scope.

## What a reader should take from this

The producer/consumer contract is complete, refuses every fault it was asked
to refuse, and is behaviorally proven on macOS and native Windows. Two things
are genuinely outstanding and neither is hidden:

1. **Behavioral proof on Linux and in the WSL2 guest** — blocked by rig
   availability this session, closed by one CI run or two reachable hosts.
2. **The measured architecture gate (AC8, Tasks 1.6, 7.4, 7.5)** — blocked by
   the no-push constraint. Closed by six dispatches per environment with
   `measure-compiler-work: true` on **each** of the two revisions — the
   constructed pre-cutover one and this branch — followed by an explicit ruling
   against the 15% band. A first run does not close it and merging does not
   close it. See
   [deferred-performance-measurements.md](deferred-performance-measurements.md).

Until (2) is done, nobody should claim this change made CI faster. What is
claimed and evidenced is narrower and still worth having: each compatible
configuration is compiled exactly once per run, every consumer provably
executes those exact bytes, and no consumer can silently rebuild.
