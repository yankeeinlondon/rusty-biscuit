### Host trap: `CDPATH` breaks the hook suite

`.githooks/tests/test-pre-push.sh:21` computes its repo root with

```sh
REPO_ROOT="$(cd "$(dirname "$0")/../.." && pwd)"
```

When `CDPATH` is exported — it is, in Ken's shell, and it includes this
worktree — `cd` echoes the resolved directory to stdout. The command
substitution captures that echo *plus* `pwd`, so `REPO_ROOT` becomes a
two-line string and the suite dies immediately on
`FAIL: hook not executable at …`. The hook is executable; the path is
garbage.

Hosted CI never sets `CDPATH`, so `pre-push-hook-tests.yml` is green and this
is invisible there. It will bite every Phase 4 and Phase 8 run of this suite
on this host. The one-line fix is `cd -- "$(dirname "$0")/../.." >/dev/null`;
it is deferred to Phase 4, which owns this file. Until then, run the suite as
`env -u CDPATH bash .githooks/tests/test-pre-push.sh`.

### Where `just ci-local --plan` may render (Phase 4)

`scripts/Cargo.toml` already depends on `biscuit-terminal`, but only behind
the default `local-tools` feature, and its comment states the reason
verbatim: `ci-rollup` links none of the monorepo crates because Cargo
compiles the union of a package's dependencies regardless of the selected
bin, and `ci-rollup` is the fast always-runs required check. CI builds it as
`--no-default-features --bin ci-rollup`.

So the Phase 4 task "render the human-facing plan through a
`TerminalRenderable` `Table`/`Prose` surface in the existing Rust repository
tooling" has a home that costs nothing: a **new `local-tools`-gated bin**
alongside `repo-deps` and `drift`. It must **not** go inside `ci-rollup`, and
Phase 5's per-area rollup work must not reach for `biscuit-terminal` either
— doing so would silently add the terminal renderer, `gix`, and `duckdb` to
the required check's build. A workflow contract test should pin the
`--no-default-features --bin ci-rollup` invocation so this cannot regress.
